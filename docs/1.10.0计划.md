## 1. B9 的现场证据（1.9.0，已复现）

- `settings.json`：`WindowMode=auto`、`AudioWindow=599×815 @1120,241`。
- 截图：窗口宽约 583 物理像素，**封面与三行文字却按约 1150 逻辑像素居中**——封面挤到右侧、右边缘被裁掉，左边一大片空白；进度条 / 音量条本身是满宽且正确的。
- 代码原因：卡片 `Ui/NowPlayingView.cs` 用 `Dock = Fill` 摆内部 `CoverView`，而 `CoverView` 全部按自己的 `ClientSize` 算（`Ui/CoverView.cs` 的 `OnPaint`）。卡片是在**窗体还没恢复几何**（构造函数里就打开了启动媒体）或**卡片隐藏着**的时候完成排版的，内部的 `CoverView` 就保留旧宽度（≈设计尺寸 1152），此后窗口变窄也不重排。
- 为什么 1.9.0 的冒烟没抓到：断言只验了**卡片自己**的 `Bounds`，没验卡片**内部**是否跟着重排。
- **第一次修没修好**（所有者第二次截图）：卡片内部改算术排版之后仍然是偏的。运行期量到真根因——
  `Panel2Collapsed = true` 的 `SplitContainer` 不会随容器变窄重算 `Panel1` 的宽度：窗口 581 宽时
  `splitMain.Panel1` 还是 1171，卡片按 1171 排、被窗口右边缘裁掉。
- 最终改法：卡片内部算术排版 + `LayoutAudioCard()` 显式给尺寸 + **折叠切换一次逼 SplitContainer 重排**
  + `splitVideo.Panel1.SizeChanged` 触发 + 界面计时器每 200 ms 兜底；冒烟留不变式断言（`Panel1` 宽 == 容器宽）。
  这条的变异**只能在真机上复现**（冒烟环境会自己重算），修前修后各截了一张图做对比。

## 2. 改法（按子系统）

### 2.1 Core

| 文件 | 改动 |
| --- | --- |
| `Core/WindowModes.cs` | `Resolve` 加第三个参数 `bool? hasVideoTrack`（`null` = 轨道还没解析出来）。顺序：手动偏好 → 真实轨道 → 扩展名 → 都没有按视频。保留两参重载 |

## 3. 测试与变异（都挂在冒烟第 11 项，日志编号不变）

新断言放在 `tools/SmokeTest/Program.AudioWindow.Card.cs`（`Program.AudioWindow.cs` 已 472 行）：

1. `CheckWindowModeTruthTable`：手动偏好 > 真实轨道 > 扩展名。
2. `CheckCardLayout`：`new MainForm(new[]{ 音乐 })` + `Show()`（所有者撞上的那条路径）→ 卡片贴住面板、**封面控件宽 == 卡片宽**、封面方框水平居中、位图中列有内容、占位提示不盖上来。
3. `CheckPlaybackControls`：四个按钮齐全，暂停 / 继续 / 下一首 / 停止都作用在引擎上；图标随状态换（`CurrentGlyph` + 位图引用变化）；停止后"停止"变灰、"播放"仍可用；停止后占位提示不盖卡片。

## 5. 如实说明

- 125% / 150% 缩放、拖到副屏再切形态，冒烟仍覆盖不到，需要真机看一眼。

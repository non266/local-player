## 2. 先量（改之前的现状）

1. **B 的基线**：`CheckOnlineCache` 的第一次跑（当时还没接磁盘缓存）——同一首歌第二次起窗体，`FakeLrcApiServer.RequestCount` 从 4 又涨到 8；现在的版本第二次是 **0**（见 §5 的变异表第一行）。
2. **C1 的基线**：`settings.json` 里 `"LrcApiToken": "…"` 是明文（`Core/AppSettings.cs` 原来就是一个普通字符串属性）；变异 C1a（不加密）把这条钉住。
3. **C2 的基线**：`reg query HKCU\…\LocalDumps` 没有 `播放器.exe`；`%LOCALAPPDATA%\CrashDumps` 里没有本程序的转储。
4. **D 的基线**：1.19.0 装机目录那次全量的日志（`没能把主窗口推到前台（前台给的是别的程序）` → 紧接着 `桌面歌词检查：右键菜单弹不出来` 判红；重跑 31/31）。

### 2.1 WER 本地转储在这台机器上的两个实测发现（影响了实现）

- **HKCU 下的 `DumpFolder` 不生效**：给 `dumpprobe.exe` 配了自定目录（REG_SZ / REG_EXPAND_SZ 都试过），崩了三次，转储仍然只出现在 `%LOCALAPPDATA%\CrashDumps`；把 `DumpFolder` 删掉（只留 `DumpType` / `DumpCount`）就正常出转储。所以本版**只配类型与份数**，路径交给 Windows 默认位置（那本来就在用户自己目录下）。
- **注册之后不是立刻生效**：第一次跑探针（注册完马上崩）等了 20 秒也没转储；同一台机器上等一会儿再跑就出（2,200,889 字节、约 2 秒）。所以探针的输出写的是"通没通"，不拿它当判据；真机上键是启动时写、运行时长期存在的，不依赖这个时序。
- 顺带确认：`Environment.FailFast` 和 `RaiseException(0xC0000005)` 都会留下转储；探针用的是后者（M8 那一族的真实形状）。

## 3. 实现

### 3.1 B：`Core/OnlineCache.cs`（新）+ 服务接缝 + 菜单

- 目录：`数据目录\online-cache\{lyrics,covers}`（跟着 `播放器_DATA_DIR` 走，冒烟天然隔离）。
- **键 = 规范化绝对路径的大写 SHA-256 前 32 位**（和「按文件路径记录」的其他东西同一口径；文件挪走 / 改名后旧条目命中不到，靠上限回收）。
- 一条一个 JSON：歌词存 LRC 原文 + 来源，封面存 base64 + mime；写入走 `SafeFile`（临时文件 + 改名）；JSON 坏 / base64 坏 / 不是图片 / 空歌词 → **删掉这条并按没有处理**。
- 上限 `128 MB`，每次写完量一次，超了按 `LastWriteTimeUtc` 从最旧删到 **75%**；单张封面 > 4 MB 不落盘。
- `Core/Lyrics.cs` 新增 `ToLrcText()`：把解析结果写回 `[mm:ss.fff]`（时间已应用过 offset，往返毫秒级一致；跨 1 小时带小时位）。
- `Core/OnlineLyricsService.cs`：构造多一个可空 `OnlineCache`；`TryGet*` 先内存再磁盘（磁盘命中顺手填回内存，所以 `Decide` 问完"缺不缺"之后界面再取不会重复读盘）；`Store*` 顺手写盘；`Clear*` 连磁盘一起清；`ClearEntry(path)` 只清一首；`IsLyricsFromDisk / IsCoverFromDisk` 给界面选文案。
- `MainForm.OnlineLyrics.cs`：菜单加「重新获取当前曲目（忽略缓存）」与「清空在线缓存（N 条 · X MB）…」；文案区分「本地缓存」/「本次运行已取过」；清空要确认框（测试用 `confirm:false` 跳过）。

### 3.2 C1：`Core/SecretProtector.cs`（新）+ 设置接线

- `ProtectedData`（`CurrentUser`，固定 entropy），密文带 `dpapi:` 前缀；没有前缀的按明文读（老文件），带前缀解不开 → 空串 + 一次日志（「可能是别的 Windows 用户 / 别的机器存下的」）。
- `AppSettings.LrcApiToken` 变 `[JsonIgnore]`，新增 `LrcApiTokenStored` 用**同一个 JSON 键名 `LrcApiToken`**：读出解密、写入加密。所以方案分组 / 抢救清单 / `KeysOf` / `Merge` 全不用改。
- `Protect` 失败（DPAPI 不可用）→ 退回明文 + 一次日志，**不丢用户填的密钥**。
- `SettingsLibrary.ExportTo` 导出时把那一项换成明文（明确的可携带语义）；导出后的状态栏写明「文件里含明文鉴权密钥，注意保管」；导入两种都认，落盘自动变密文。
- 日志规矩不变：只记「有 / 无」（变异 C1d 钉住）。

### 3.3 C2：`Core/CrashDump.cs`（新）+ 启动提示 + 卸载清理

- `Enable / Disable / Sync / IsEnabled / TryReadSettings`：只操作 `HKCU\Software\Microsoft\Windows\Windows Error Reporting\LocalDumps\播放器.exe`（`DumpType=1`、`DumpCount=3`，并删掉旧的 `DumpFolder` 值——见 §2.1）。跟现有的 `DiagnosticLog` 开关走：开就注册、关就撤键；启动时对齐一次、菜单开关里对齐一次。
- 正常退出写 `last-exit.txt`；托管致命异常由 `AppLog` 写 `fatal.txt`；启动时比"转储 / fatal 的时间 > last-exit 且 > 已报告时间"，有就状态栏说一句，并记下已报告（同一份崩溃只报一次）。
- 帮助菜单加「打开数据目录」（转储 / 缓存 / 日志 / 方案都在那儿）。
- `tools/installer/播放器.iss` 加 `[Code]`：卸载后删掉那支 HKCU 键（`%AppData%\播放器` 与 `%LOCALAPPDATA%\CrashDumps` 都不碰）。
- gated 探针 `播放器_TEST_CRASHDUMP=秒数`：给 `SmokeTest.exe` 注册转储、跑 `SmokeTest.exe --crash`（`RaiseException(0xC0000005)`），打印"转储出来没有、多大、在哪"，然后撤键、只删这次产生的文件。**只量不判**。

### 3.4 D：桌面歌词右键菜单的三态判定

- 把 312～334 那段抽成 `ShowAndDecideDesktopLyricsMenu(context, owner, foregroundOwned)` + 纯判定 `DecideDesktopLyricsMenuOutcome(visible, foregroundOwned)`（Ok / Skip / Fail）；前台不是本窗口时先再抢一次，仍不是就跳过并打印原因；前置成立时仍是硬失败。
- `CheckDesktopLyricsMenuDecision()` 在检查开头直接调纯判定四次（任何机器都能验），不依赖真的抢到前台。

## 4. 边界（都写进 README 的已知限制）

1. **缓存按路径做键**：文件挪走 / 改名后旧条目命中不到；`清空` 是唯一的手动回收入口（上限之外）。
2. **失败结果不缓存**：这次没找到，下次切回来还会再试（「没找到」缓存住就再也不会重试）。
3. **不缓存超大封面**（> 4 MB）；写盘失败只记一次日志，界面照常用内存里的。
4. **密钥只在这台机器 / 这个 Windows 用户下解得开**；换机器导入老方案仍可用（导出是明文），但 `settings.json` 直接拷过去会读不出来。
5. **只抓不分析**：本机没有 cdb / windbg、没有管理员；这一版保证"有证据、能定位到哪次崩溃"，不假装能现场分析。
6. **转储最多 3 份**（Windows 按 `DumpCount` 轮转），路径是 `%LOCALAPPDATA%\CrashDumps\播放器.exe.<pid>.dmp`；卸载不删它们（那是可能还要发给别人看的现场）。
7. **WER 注册的生效有延迟**（§2.1 实测），所以探针只打印"通没通"，不当判据。
8. 缓存不加密（内容就是歌词与封面图，和音乐文件同级）；不做在线结果的多源聚合。

## 5. 测试与变异

新增**第 32 项检查「在线缓存」**（`tools/SmokeTest/Program.OnlineCache.cs`，第 27 个运行步骤；`StepCount` 31 → 32；口径 27 个运行步骤 / 32 项检查）：

1. 第一次：假服务器 **4** 个请求、落盘 **2** 条（495 字节）、菜单里两条新入口在、清空那条写着「2 条」；
2. 第二次启动：**0** 个请求、歌词与封面都从磁盘来、状态栏说「本地缓存」、时间轴逐行相同；
3. 把两个缓存文件写成垃圾：回退联网并重写（两条都变回合法 JSON）；
4. 清空：内存与磁盘都空、状态栏说清删了几条、菜单变「现在是空的」；重新获取把两条写回来；
5. 重新获取碰上连不上：旧条目当场忘掉、失败结果不落盘、再切回这一首也不会"假装拿得到"；
6. 上限：给 400 字节的小上限写 5 条 → 只剩 3 条，最旧的没了、最新的还在。

**C1 的断言**并入第 4 项「设置持久化」（`CheckTokenEncryption`）：密文保存 / 读回 / 老明文迁移 / 解不开降级 / DPAPI 不可用退回明文 / 导出明文 / 日志无密钥。
**C2 的断言**并入第 15 项「日志与错误处理」（`CheckCrashCapture`）：注册表三值、`Sync(false)` 撤键、`Sync(true)` 再开、伪造转储只报一次、干净退出不报、`fatal` 标记也报；「帮助」里新增「打开数据目录」。
**D 的断言**：三态判定四次直调 + 原有的真菜单一次（环境不成立时打印跳过原因）。

## 8. 本轮不做

| 事项 | 理由 |
| --- | --- |
| 不可达网络流的超时提示 | 1.19.0 只量到"60 秒还停在 Opening"；要另定超时值与"别杀了慢流"的边界 |

## 10. 做完之后（2026-11-13）

- 全量冒烟 **32/32**，连跑三次全绿：**248.0 秒 / 245.2 秒 / 244.9 秒**（1.19.0 的基线是 222.6 秒 / 238.5 秒；
  多的约 22 秒里，第 32 项检查自己 6.2 秒，其余是 1.20.0 起每个主窗体多了一次 `MarkCleanExit` 与几次 `AnnouncePendingCrash` 的开销）。
  新检查每段的实测：第一段 4 个请求、落盘 2 条 495 字节；第二段 0 请求、时间轴相同；坏文件回退 4 → 8；上限 400 字节写 5 条剩 3 条。
- 探针 `播放器_TEST_CRASHDUMP=20`：子进程崩掉后 Windows 写了转储 **2,200,889 字节**（`SmokeTest.exe.<pid>.dmp`）——
  WER 这条路是通的；但**注册之后不是立刻生效**（第一次跑等 20 秒也没有，过一会儿再跑就有，见 §2.1）。
- 三连期间第 15 步有一次"假红"（在另一台机器上跑着别的命令、前台被占）：日志是
  `光标（…）底下不是歌词窗口…所以按下去没人收到`——这是 M1 记过的**拖动**那一条，不是这次改的右键菜单那条；
  连续跑（不并发干活）三次都绿。M1 的状态照旧：等它再假红一次再按三态收口。
- `tools/release-check.ps1` 第一次跑在**第 13 项**红了一次：`全屏进度条：鼠标再动一下之后它没有回来`
  （合成鼠标那一族，环境敏感；同一条在紧接着的重跑里绿，整套 **249 秒**全绿）。这一条**没有**加跳过判据——
  照 M1 的规矩，它再假红一次再照三态收口，这一轮不顺手放宽。
- 干净树验收与发版：**未做**（等所有者说"发布"）；本机的 `HKCU\…\LocalDumps\播放器.exe` 是冒烟里主窗体
  按默认设置（记录诊断日志）注册出来的，属于程序自己的配置，不是残留。

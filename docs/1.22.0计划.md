# 1.22.0 计划：Ogg / Opus / APE 标签 + 媒体信息更详细 + 偶发红与挂死收口

## 0. 目标与成功判据

1. `.ogg` / `.oga` / `.opus` / `.ape` 文件的标题、艺术家、专辑、年份、音轨号、流派、备注、
   内嵌歌词、内嵌封面能读出来；`.mp3` / `.flac` / `.mp4` 既有断言一条不改仍然全绿。
2. 媒体信息页的轨道行能显示分辨率、显示比例、帧率、语言中文名等——**只显示 libvlc 实测给得出
   的字段**，读不到的字段不出现、不编造；顺带把"编码"那一列一直显示四字符码的问题修掉。
3. 冒烟有看门狗：任何一步连续 180 秒（可配）没有心跳就写迷你转储、以退出码 3 结束；

   修 / 收紧 / 显式跳过 / 留证据记成已知偶发——**判据一条都不许放宽**。
5. 10 条变异全部按预期变红；全量冒烟 32/32 三连绿；`docs-check` 与干净树 `release-check` 绿。
6. 版本 `1.22.0`；本轮不发布。

## 2. A · Ogg / Opus / APE 标签

### 2.1 用户看见的行为

`.ogg` / `.oga` / `.opus`（Vorbis / Opus / Speex）与 `.ape`（APEv1 / APEv2）文件的标题、艺术家、
专辑、专辑艺术家、年份、音轨号、流派、备注、内嵌歌词（`LYRICS` / `UNSYNCEDLYRICS`）、
内嵌封面（`METADATA_BLOCK_PICTURE` 的 base64 / `Cover Art (Front)` 二进制条目）都读出来；
侧栏、音频卡片、媒体信息、桌面歌词照旧显示。读不到时行为不变（退回文件名）。

### 2.2 改动

- **`Core/OggTagReader.cs`（新）**：逐页读 Ogg（27 字节页头 + 段表 + 数据），按页头继续位拼包；
  第一个包认 `\x01vorbis` / `OpusHead` / `Speex   `，第二个包去前缀后交给 FLAC 那份 Vorbis comment 解析；
  读到评论包就停。上限：32 页 / 2 MB / 单包 8 MB，超了就地停、已读字段保留。
- **`Core/ApeTagReader.cs`（新）**：文件尾 32 字节 `APETAGEX` footer（含"带 header"的 v1 形状）；
  条目 = `值长 / 标志 / 键（ASCII+0）/ 值`；文本键走同一套键名归一，`TRACK` → 音轨号；
  `Cover Art (Front)` 去掉「文件名 + 0」前缀后当封面；条数 4096、封面沿用 `TagReader.MaxCoverBytes` 上限。
- **`Core/FlacTagReader.cs`**：`ReadVorbisComment` / `ApplyVorbisField` / `ReadFlacPicture` 改 internal
  （Ogg 与 FLAC 共用同一段）；`ApplyVorbisField` 增加 `TRACK` 与 `METADATA_BLOCK_PICTURE`
  （base64 → PICTURE 结构；坏 base64 / 超上限只丢封面）。
- **`Core/TagReader.cs`**：分发加两支——`OggS` → Ogg；扩展名 `.ape` / `.wv` / `.tta` / `.mpc`
  或文件尾是 `APETAGEX` → APE。ID3 在前的 FLAC、MP3、MP4 走原路。
- 不改设置、不改 schema、不改播放路径（`MediaTags` 字段够用）。

### 2.3 失败模式与边界

- 截断页 / 坏 segment 表 / 坏 base64 / 非 UTF-8 值：吞掉并停在原地，返回已读到的部分，绝不抛。
- 链式 Ogg（多段拼接）只读第一段；`Ogg-FLAC`、`Theora(.ogv)`、`WMA(ASF)` 不做（README 写明）。
- APE 标签也常挂在 MP3 上：本轮只按 `.ape` 族扩展名认，MP3 不动（避免改变现有行为）。
- 解析跑在 `MetadataLoadQueue` 的专用线程（最多 2 条在飞）：新解析必须有界，否则坏文件会卡死队列线程。

### 2.4 断言（第 9 项「标签与歌词」新增一段）

- **Opus 跨页**：评论包 70 KB 撑到跨页（一页最多 255 × 255 字节），字段 / 中文 UTF-8 / 封面 /
  歌词全部正确。
- **Vorbis**：framing bit 之后的评论包；`LYRICS` 取第一个非空。
- **Speex**：无前缀的评论包。
- **APE**：APEv2（无 header）全字段 + `Cover Art (Front)`；APEv1（带 header）字段正确
  ——"标签总长含 footer、不含 header"的起点不能算错。
- **坏样本**：坏 base64 只丢封面；截断的 APE footer / 截断的 Ogg 页安静返回、不抛。
- **真实文件（gated `播放器_TEST_OGGPROBE=1`）**：ffmpeg 现造 `.opus` / `.ogg`（带标题与歌手），
  解析结果与写入一致；没有 ffmpeg / 编码器时打印原因跳过。
- **回归**：`.mp3` / `.flac` / `.mp4` 现有断言一条不改仍全绿。

### 2.5 变异（6 条，期望红）

1. 不认 Ogg 继续位（只读一页）→ 跨页样本字段缺。
2. Opus 前缀少去一个字节 → 标题 / 艺术家全空。
3. 键名归一不删下划线（METADATA_BLOCK_PICTURE 认不出）→ 封面丢了。
4. 坏 base64 不吞异常 → 整份标签读空（连标题都没了）。
5. APE footer 起点算错 32 字节 → 值全乱。
6. APE 封面不去掉「文件名 + 0」→ 多出 10 字节、MIME 猜错。

## 3. B · 媒体信息更详细

### 3.1 先量后写（探针实测，2026-11-15）

640×480 / 25 fps / `setsar=4/3` / H.264 + AAC + 字幕的 3 秒样本上，libvlc 3.0.24 报的是：

| 字段 | 实测值 |
| --- | --- |
| `VideoTrack.Width/Height` | 640 × 480 |
| `SarNum/SarDen` | 4 : 3（显示 16:9） |
| `FrameRate` | 25 / 1 |
| `Orientation` / `Projection` | `TopLeft` / `Rectangular` |
| `MediaTrack.Profile` / `Level` | **−1 / −1**（读不到） |
| `MediaTrack.Bitrate` | **0**（读不到） |
| `MediaTrack.Description` | 空 |
| `CodecDescription(type, codec)` | `H264 - MPEG-4 AVC (part 10)` / `MPEG AAC Audio` / `tx3g` |

所以：Profile/Level、轨道码率、`Description` **不显示**（读不到就不编）；显示比例、帧率、
语言中文名、编码名照写。轨道码率补一个"文件总码率 = 大小 × 8 ÷ 时长"（容器平均，标成「总码率」）。

### 3.2 行为

- 视频轨行：`H264 - MPEG-4 AVC (part 10) · 640×480 · 显示 16:9 · 25 fps`（只写有值的；
  H.264 且 libvlc 真给了 Profile/Level 时插一段 `High@4.1`；方位 / 投影非默认才追加）。
- 音轨行：`MPEG AAC Audio · 44100 Hz · 1 声道 · 英语`；字幕轨行：`tx3g · 中文`。
- 新增文件级「总码率」一行（`114 kbps` 这类）；轨道自己的码率为 0 时不写。
- 语言码映射中文（eng → 英语、chi/zho → 中文、jpn → 日语、kor → 韩语、fra/deu/spa/ita/rus…）；
  `und`（未标注）不显示；认不出的原样写。

### 3.3 改动

- **`Core/MediaDescriptions.cs`（新）**：语言名、H.264 的 `Profile@Level`、显示比例（SAR → DAR，
  能约成 16:9 就写好写法）、码率单位、方位与投影。全是纯函数，边界直接断言。
- **`MainForm.Metadata.cs`**：`DescribeEngineTrack` 用它们拼串；新增「总码率」行；
  `FourCc` 改成 `DescribeFourCc`（VLC 的 fourcc 第一个字符在最低字节，旧代码反着取）。
- **`Core/PlayerEngine.Tracks.cs`**：`DescribeCodec` 的第二个参数改传 `track.Codec`
  （签名要的是编解码器 fourcc，不是轨道 id）——这是 1.22.0 之前一直存在的显示错误。

### 3.4 断言与变异

- 第 13 项新一段（`Program.Video.Info.cs`）：纯逻辑断言（语言 / 码率 / 比例 / Profile@Level /
  方位投影 / 四字符码）+ 真播放样本断言（含 `640×480`、`显示 16:9`、`25 fps`、`H264`、`英语`、
  `中文`、`总码率`，且不出现 `462h`、`@`、`0 kbps`、`und`）。
- 变异（4 条）：显示比例忽略 SAR；语言不映射；码率 0 照写（`Bitrate(0)` 返回 `0 kbps`）；编码仍传轨道 id。

## 4. C · 偶发红与挂死收口

### 4.1 看门狗（`tools/SmokeTest/Program.Watchdog.cs`）

- 心跳：`PumpMessages` 每圈、`Journal` 每行刷新单调时钟；阈值 `播放器_TEST_WATCHDOG` 秒
  （默认 **180**，`0` 关掉）。合法但很久不泵消息的操作（ffmpeg 等待 ≤60 秒、`Media.Parse` ≤15 秒）
  不会误触。
- 触发时：先把「疑似挂死：第 X 步 / 已 N 秒没有心跳」写进 journal（写日志很快），再用
  `MiniDumpWriteDump`（`dbghelp.dll`，`MiniDumpNormal | MiniDumpWithThreadInfo`）写一份迷你转储到
  `%TEMP%\smoke-hang-<pid>-<时间>.dmp`，最后 `Environment.Exit(3)`。
  用 Exit 而不是 FailFast：FailFast 会让 WER 再记一次崩溃、在 CrashDumps 里多一份与挂死无关的转储。
- 自我验证（gated `播放器_TEST_WATCHDOG_SELFTEST=1`）：起 `SmokeTest.exe --watchdog-selftest`
  子进程（阈值 2 秒、故意睡 60 秒），断言退出码 3、有转储、子进程自己的日志里有「疑似挂死」；
  子进程用自己的临时日志文件，不碰父进程的 `smoke-journal.txt`。
- 如实说明：本机仍**不能**分析转储（没有 cdb / dotnet-dump）；它保证"不再白等、现场留下、
  能拿到别处分析"，与 1.20.0 的崩溃取证同一条口径。

### 4.2 第 6 步现场补强

按住那 600 ms 里每 100 ms 记一行 `(标签, 滑块值, 位置, 时长, 状态, 拖动中)`，失败时整段打进 journal（**判据一个字不改**）。
连跑第 3 次抓到的现场：

```
「00:01:00」/ 值 1000 / 位置 550 / 时长 60000 / 状态 Playing / 拖动 True
```

引擎位置只有 0.5～1.3 秒、在播、拖动状态还在，滑块值却已经 1000——根因是**合成拖动打开了鼠标捕获**，
真实鼠标在这 600 ms 里一动，`WM_MOUSEMOVE` 就落到滑块上，把它带到真实光标的位置（拖动本来的行为，不是产品 bug）。
收口办法三件一起：

1. 按住期间记录"真实鼠标是否把滑块带走"（拖动状态还在 + 值变了）；
2. 检查开始前把真实光标停到屏幕左上角、结束还原——挪开它，别在捕获期间被碰；
3. 真实鼠标带跑 → 打印原因后**跳过**这一次；**拖动状态被清掉**（计时器把标签 / 滑块写回播放时间）
   仍然硬失败（B5 那个老 bug 的形状）。

### 4.3 复现活动与判定规则

- `dotnet SmokeTest.dll 主窗体` 连跑 25 次；`dotnet SmokeTest.dll 视频` 连跑 20 次。
- 结论四选一：修 / 收紧 / 显式跳过 / 留证据记成已知偶发；**不放宽任何判据**。
- 若复现出产品缺陷（挂死 / 界面冻结），先修再加断言；修的时间超过 0.5 天先报所有者。

## 9. 假设与如实说明

- 「视频信息更详细」按**侧栏「媒体信息」页里每轨那一行**理解（不是视频窗口浮层、也不是新对话框）。
- libvlc 3 的 `Profile` / `Level` / `Description` / 轨道码率**不保证有值**：实测这个样本上全是空，
  所以界面不写；H.264 的 `Profile@Level` 翻译只有 libvlc 真给了值才出现（纯逻辑已断言）。
- Ogg / Opus / APE 只做标签读取，不改播放路径；`.wma`（ASF）与 Ogg-FLAC / Theora 不做。
- **没有真实 `.ape` 音频样本可造**（ffmpeg 没有 Monkey's Audio 编码器）：标签只用手写字节的样本验证；
  `.ape` 的播放路径本来就走 libvlc，本轮不动。
- 第 6 / 13 步的结论**可能是「不复现」**：那就是"探针与看门狗留下、判据不动、记为已知偶发"，
  不等于修好了。
- 转储本机不能分析；看门狗保证"不再白等 15 分钟、现场留下来"。

| A6 | APE 封面不去「文件名 + 0」前缀 | `APE 的 Cover Art (Front) 不正确：149 字节 / image/jpeg` |
| B1 | 显示比例忽略 SAR | `媒体信息检查：显示比例换算不正确（640×480 SAR4:3=4:3、640×480=4:3、1920×1080=16:9、100×100=、1920×804=2.39:1）` |
| B2 | 语言码不映射中文名 | `媒体信息检查：语言码映射不正确（und=、eng=eng、CHI=CHI、xyz=xyz）` |
| B3 | 码率 0 也照写 | `媒体信息检查：码率换算不正确（0=0 kbps、999=0 kbps、128000=128 kbps、1530000=1.53 Mbps）` |
| B4 | `DescribeCodec` 又传轨道 id | `媒体信息：视频编码没有写成「H264 - MPEG-4 AVC」（「h264 · 640×480 · 显示 16:9 · 25 fps」）` |

> 与初稿的两处修正（如实记）：A3 原本写"键名不归一（只认大写）"，但手工样本的键本来就是大写，
> 那样变异打不红——改成"归一不删下划线"，`METADATA_BLOCK_PICTURE` 立刻露出来。
> A4 原本想验"base64 体积上限"，但 12 MB 的图片在 Ogg 的 8 MB 单包上限之前就被挡掉、测不出"只丢封面"；
> 改成"坏 base64 不吞异常"，验的是同一段代码的另一道防线。

### 10.5 如实说明

1. **第 13 步的挂死复现了，但这一版没有修**：`视频` 连跑第 18 次卡在「音轨记忆」——日志最后一行是
   「默认 音轨 1 / 字幕 3，准备选「Japanese - [Japanese]」与「ChineseSub - [Chinese]」」，
   之后界面不再响应；Windows 事件日志记 **Application Hang**（进程 `dotnet.exe`），
   约 52 秒后 Windows 直接把进程关掉，退出码 **`0xCFFFFFFF`**。这比 1.21.0 那次（15 分钟没人管）
   更短，但形状一样：**卡在切音轨 / 字幕轨那一段**。
   ⚠ **不能排除环境干扰**：22:14 实测前台是游戏（`umamusume`，可能全屏独占），而这几轮连跑
   都在同一时段；挂死那几次没有当场记前台。所以这一条记为「**复现到形状、根因未定**」，
   不当成已定位的产品 bug（全量连跑同一时段也撞到两次 Application Hang，位置在关音频窗口那一段）。
2. **看门狗这次没来得及**：阈值 180 秒，Windows 在 ~52 秒就动手了，所以没写成转储。
   这是 180 秒阈值的一条真实边界，写进 README；下一轮若要抓现场，得改成"UI 无响应探测（~10 秒）
   + 给 ffmpeg 等待显式豁免"，或者靠 WER / 事件日志。**没有假装看门狗已经兜住挂死。**
3. **「画面右键菜单」红过一次**（20 次里 1 次）：右键是产品里"轮询 + 光标是否在画面上"的实现，
   窗口刚激活/光标刚挪过去那一拍可能还没轮到。改成**最多试 3 次**（每次重新激活 + 重摆光标），
   三次都弹不出来仍然判失败（判据没放宽），并在这条红的时候把"窗口激活 / 光标在画面上"打印出来。
   之后 20/20 绿。
4. **「全屏进度条自己变前台」红过一次**：只有在**进全屏之前主窗口就是前台**时才硬失败；
   整个程序都不是前台时打印原因按环境跳过（用 `formWasForeground` 判的）。产品变异
   （让进度条窗口激活自己）仍会红，因为那时主窗口是前台。
5. 第 6 步的偶发红是**真实鼠标在捕获期间把滑块带走**（见 §4.2），不是产品 bug：
   收口是"停光标 + 三态跳过"，判据没改；B5 那条老 bug 的形状（拖动状态被清掉）仍然硬失败。
6. 「媒体信息」实测 libvlc 3.0.24 对 mp4 报 `profile=-1` / `level=-1` / `bitrate=0` / `description` 空，
   所以那几项**界面不写**（不编造）；文件级「总码率」是按大小 ÷ 时长算的容器平均。
7. **没有真实 `.ape` 音频样本**（ffmpeg 没有 Monkey's Audio 编码器）：APE 只用手写字节的标签样本验证。
8. 本机没有 `cdb` / `dotnet-dump`：转储当场分析不了，与 1.20.0 的崩溃取证同一条口径。
9. **全量连跑里的几次失败是环境，不是产品结论**：22:00 前后连续跑全量时出现过「画面右键菜单弹不出」
   「进度条右键把位置拽回 0 ms」「桌面歌词右键菜单弹不出」——当时前台是游戏（`umamusume`，可能全屏独占），
   合成输入、前台判断与窗口关闭时序都失真。README 的冒烟一节因此加了一句"跑冒烟时别让全屏游戏占着前台"。
   最终三连绿是在游戏退出前台之后跑的（见 §10.3）。

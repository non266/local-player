# 1.23.0 计划：字幕外观 + 标签第三批（WMA/ASF、Ogg-FLAC、Theora）+ 串流最近地址

> 版本：1.23.0（2026-11-16 起做）。范围 = 所有者 2026-11-16「制定下个版本的计划」时选的三项：
> **C 标签第三批**、**B 字幕外观**、**D 串流最近地址**。三项都是用户看得见的新能力，按次版本走；
> **本轮不发版**，等所有者说「发布」。
> 顺序：先跑 B 的探针（它决定这个功能存不存在），再做标签 → 最近地址 → 字幕外观 → 收尾。

## 0. 目标与成功判据

1. `.wma` / `.asf` / `.wmv`（ASF 容器）、Ogg-FLAC（`.oga`）、Theora（`.ogv`）的标题、艺术家、专辑、
   年份、音轨号、流派、备注、内嵌歌词、内嵌封面能读出来；已有格式的断言一条不改、仍然全绿。
2. `字幕 → 字幕外观…`：字号 / 颜色 / 描边 / 背景四组预设，**先探针证明真的改变了画面**；
   没证明就不上线（探针不成立 → 停做，只交另外两项，并回来问所有者）。
3. `文件 → 最近地址`：最近 10 条网络串流（最新在前、可清空），**落盘 DPAPI 密文**、
   菜单只显示脱敏短标签、清除当场落盘。
4. 新断言都落在现有步骤里：冒烟仍是 **27 个运行步骤 / 32 项检查**（`StepCount` 不动）。
5. 14 条变异全部按预期变红；全量冒烟 32/32 三连绿；`docs-check` 与干净树 `release-check` 绿。
6. 版本 `1.23.0`；CHANGELOG / README / 介绍 / ARCHITECTURE / 维护手册同批更新；**不发版**。

## 2. M0 · 字幕外观探针（先跑，结果决定走哪条路）

新建 `播放器_TEST_SUBTITLEPROBE=1` 才跑的 gated 探针：ffmpeg 现造 640×360 黑底 6 秒视频 +
外挂 `.srt`（1~5 秒），播到 2 秒截图；同一配置分别给「默认 / 内核级 / 媒体级 / 只改颜色」，
量画面下半区的**墨迹像素、红色像素、字高**；另外抓屏一次作为「截图不含字幕」时的退路。

### 2.1 实测（2026-11-16，本机）

| 配置 | 截图墨迹 | 红像素 | 字高 |
| --- | --- | --- | --- |
| 基线（默认外观） | 1859 | 0 | 20px |
| 关字幕（对照） | 0 | 0 | 0 |
| 内核级 `--freetype-rel-fontsize=30 --freetype-color=16711680 --freetype-outline-thickness=4` | 423 | 402 | 10px |
| 媒体级 `:freetype-…`（同一组） | **1859** | **0** | **20px** |
| 只改颜色（内核级红） | 1371 | 1308 | 20px |
| 只改字号 30 / 15 / 12 / 8 | 638 / 1995 / 3004 / 6167 | 0 | 11 / 21 / 27 / 42px |

**结论：C 路线**——截图里包含字幕（关字幕后 0），内核级参数生效，**媒体级写法逐像素不生效**。
另外量出一个语义：`--freetype-rel-fontsize` 是**分母**（画面高度 ÷ 值），不是"越大字越大"。
所以外观进 `CoreArguments`（建内核时给）；会话内不新建内核（避开 M8 那个坑），
**改完设置下次启动程序生效**，对话框与状态栏都写明。

### 3.3 边界与失败模式

- 头长度 / 对象数 / 条目数撒谎、截断、值越界：**吞掉并停在原地**，返回已读到的部分，绝不抛。
- 上限：头 ≤ 16 MB、对象 ≤ 64、单条名 / 值 ≤ 1 MB、条目 ≤ 4096、封面 ≤ 12 MB。
- 同一键多次出现：沿用 `??=`（先到的赢）。
- UTF-16 一律小端、去尾部 NUL；奇数长度丢最后 1 字节。
- Ogg 里的封面受 32 页 / 2 MB 上限约束（≳ 1.5～2 MB 读不到，README 写明）。
- 不做：WMA Pro / DRM、ASF 的 Metadata Object、链式 Ogg。

### 3.4 断言（第 9 项）

1. ASF：`.wma` 全字段（含 DWORD 音轨号、封面 MIME 与**逐字节**图片）；`.bin` + ASF 魔数也认得出。
2. ASF 坏样本：头长度撒谎 / 封面长度离谱 / 截断到字符串中间 → 不抛、已读字段保留、坏封面丢掉。
3. Ogg-FLAC：STREAMINFO（44100 / 2 / 16 / ~3000 ms）+ 评论块 + PICTURE 块（逐字节）。
4. Theora：标题 / 歌手 / 歌词。
5. GATED（`播放器_TEST_TAGPROBE=1`）：ffmpeg 现造真实 `.wma` / `.ogv` / `.oga(flac)`；缺哪个编码器就跳过哪个。

### 3.5 变异（6 条，实际红在哪一句见 §10.2）

| A2 ASF 标题 / 作者对调 | 红：ASF 基本字段不正确（歌手 / 曲目） |
| A3 WM/Picture 不跳过 MIME + 描述前缀 | 红：ASF 封面字节与样本不一致（**这一条第一次是绿的**，说明"只比长度 + MIME"的断言太弱，补了逐字节比较之后才红） |

## 4. B · 串流最近地址

### 4.1 用户看见的行为

`文件 → 最近地址`：最近 10 条（最新在前，`&1`～`&9`），选一条就播；空时是灰的「（暂无记录）」，
末尾「清除最近地址」。条目文字是**去掉 userinfo / query / fragment** 的短标签

### 4.3 边界

- 只记"打开过"，死链也会进列表；去重按完全相同字符串（URL 的 path 区分大小写）。
- DPAPI 解不开（换用户 / 换机器）：丢那一条，其余设置不受影响。
- **导出 / 设置方案里仍是密文**（不给明文出口）；换机器导入后这份列表为空，README 写明。
- 清除立即落盘；新增条目随退出时的设置落盘（与别的设置一致）。

### 4.4 断言与变异

- 第 8 项：12 条输入（含重复、本地路径、带口令地址）→ 3 条、MRU、上限 10；`Describe` 不含
  `user` / `pass` / `token` / `?`；JSON 里没有明文、有 `dpapi:`；坏密文只丢一条；本地路径不读进来。
- 第 22 项：菜单条目数 = N + 分隔线 + 清除；第一条 `Tag` 是最新地址、文字不含凭据；
  清除后菜单变灰、设置清空、**磁盘也空**（先落盘一次再清除，否则"只清内存"验不出来）。
- 变异 C1 明文落盘 → 红；C2 不去重 → 红；C3 上限 11 → 红；C4 清除不落盘 → 红。

## 5. C · 字幕外观

### 5.1 行为（探针结论：C 路线）

`字幕 → 字幕外观…`：字号（小 / 默认 / 大 / 特大）、颜色（默认 / 白 / 黄 / 青 / 绿）、
描边（默认 / 细 / 粗）、背景（默认 / 淡 / 浓）；预览板是 GDI+ 的**近似**效果。

### 5.3 断言（第 13 项，真播放）

- 黑底素材：字号「小」< 默认 × 0.8；「特大」≥ 默认 × 1.8；颜色「黄」的黄色像素 ≥ 200。
- 白底素材：描边「粗」的墨迹 ≥「细」× 1.05；背景「浓」让下半区平均亮度至少低 8。
- 实测（2026-11-16）：默认字高 20px、小 11px、特大+黄 42px（黄像素 4805）、
  白底细描边墨迹 9358 / 粗 13048、背景平均亮度 205.7（无背景约 254.9）。
- 截图量不到时打印原因后跳过（三态）；产品变异仍必须红。

### 5.4 变异（4 条）

| 变异 | 结果 |
| --- | --- |
| B1 外观参数不进内核 | 红：字号「小」没有变小（字高 20 = 默认） |
| B2 颜色恒为绿（无视选择） | 红：颜色「黄」没有生效（黄像素 0） |
| B3 签名不含颜色 | 红：四个值没有全都进签名 |
| B4 不传描边厚度 | 红：描边「粗」和「细」画出来差不多（13048 / 13048） |

> B2 第一次写的是"颜色值恒为 0"（黑色）：文字在黑底上直接看不见，红在"字高 0"那条上，
> 虽然也是红，但证据指向字号——改成"恒为绿"之后，红的正是颜色那一条。

## 9. 本轮不做

| 事项 | 理由 |
| --- | --- |

### 10.7 如实说明

- **字幕外观要重启程序才生效**：参数是内核级的，会话内不新建内核（避开 M8 那套）。
  对话框、状态栏、README 都写明，不假装"已经变了"。
- **ASS / SSA 与 DVD 图形字幕不受外观影响**：libass / 位图，改 freetype 参数对它们无效。
- 探针量的是 640×360 合成素材上的**相对**变化（字号 / 颜色 / 描边 / 背景），不是"哪个预设最好看"。
- 真实 `.wma` / `.ogv` / `.oga` 依赖 ffmpeg 编码器；缺哪个就跳过哪个（不算失败）。
- 最近地址只记"打开过"，死链也会在列表里；换机器后密文解不开的那条会被丢掉。
- **第 11 项「音频窗口」那两次 Application Hang 没有修**（`0xCFFFFFFF`）：与 1.18.0 / 1.22.0
  记过的是同一个形状（关那个窗体时被 Windows 判成挂起），本轮三项功能都不碰那一段；
  "偶发挂死"是所有者本轮没选的那一项，如实留在这里，不当成本轮已解决。

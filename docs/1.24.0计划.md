# 1.24.0 计划：内置文件浏览器（侧栏第 5 页 + 可分离独立窗口）

> 状态：**已实现、待发布**（2026-11-17）。所有者说「发布」后再走打包 / 安装 / 卸载 / GitHub Release。

## 1. 范围（所有者选定）

| 项 | 选择 |
| --- | --- |
| 功能范围 | **基础 + 深度整合**：浏览 / 导航 / 地址栏 / 过滤 / 排序 / 双击播放 / 多选加入 + 右键菜单 / 下一首 / 整个文件夹递归 / 收藏 / 最近 |
| 分离方式 | **文件页可单独弹出**：侧栏第 5 个「文件」标签 + 自己的独立窗口（位置 / 大小 / 吸附）+ 侧栏「已分离 / 归位」占位 |
| 不做 | 搜索框、封面缩略图、拖放到播放列表、删除 / 重命名 / 移动、SMB 自动发现、文件夹树 |

理由：侧栏默认 300 DIP，树 + 列表会把两边都挤到不可读；地址栏 + 返回 / 上级已经能到任意目录。
缩略图要解码大量图片，内存与卡顿风险明显，留到以后单独一轮。

## 2. 设计

### 2.1 数据所有权

| 数据 | 主人 | 说明 |
| --- | --- | --- |
| 当前目录 / 历史 / 收藏 / 最近 / 排序 / 显示所有 | `Core/FileBrowserState` | 纯逻辑；历史 50、收藏 20、最近 10 |
| 一次目录读取 | `Core/FileBrowserService` | 阻塞、无界面；只读当前层；20,000 项上限；磁盘列表不读卷标 / 不碰 `IsReady` |
| 路径归一 / 父目录 / 短标签 | `Core/FileBrowserPaths` | 不碰磁盘 |
| 播放 / 添加 / 下一首 / 整文件夹 | `MainForm.FileBrowser` | 复用现有 `AddPathsWithFolders` / `AddPathsToPlaylist` / `PlayIndex` / `PlaybackQueue` |
| 视图 | `Ui/FileBrowserView`（2 份 partial） | 只发事件；后台读取结果回 UI 线程才改控件 |

文件页不认识 VLC；播放列表也不认识文件页。

### 2.2 UI 线程零 I/O

`FileBrowserView.StartLoad` 把 `FileBrowserService.ReadDirectory` 丢到 `Task.Run`；导航调用立即返回。
每次导航取消上一条 CTS、递增代际号；结果回 UI 线程时版本不一致就丢掉。CTS 在任务结束后才
`Dispose`（读取线程可能还在用 `WaitHandle`）。

### 2.3 有界递归

「添加整个文件夹 / 播放整个文件夹」走 `MediaScanner.Walk` + `MediaScanLimits.LocalBounded()`：
**32 层 / 200,000 文件 / 不跟重解析点**。`MediaScanLimits.FollowReparsePoints` 默认 true，
现有本地"打开文件夹"行为不变；网络导入默认不跟。

### 2.4 分离窗口

三个悬浮窗（侧栏 / 播放列表 / 文件浏览器）共用 `MainForm.Floating.cs` 的几何保存、吸附与全屏隐藏。
文件页分离时控件搬进 owned Form，侧栏显示占位；点窗口 ✕ 等同归位；归位时（用户动作）打开侧栏并切到
文件页，但载入设置方案时 `revealInSidebar: false`，不推翻方案里的"侧栏收起"。

### 2.5 键盘

焦点在文件列表时，无修饰的方向键 / PageUp / PageDown / Home / End 原样还给 `ListView`；
Enter 打开、Backspace 上级、F5 刷新、Alt+←/→ 后退 / 前进；**Delete 被吞掉**（不删文件，
也不漏到播放列表的"移除"）。

## 10.2 变异原文（8 条，逐条变红）

| # | 变异 | 实测失败原话 |
| --- | --- | --- |
| 1 | `StartLoad` 改回 UI 线程同步读 | `文件页检查：导航在 UI 线程上等了 602 ms（期望 < 200 ms）` |
| 2 | 去掉 `ApplyLoad` 的代际号检查（假服务改成不响应取消的 600 ms Sleep） | `文件页检查：慢目录的结果盖到了后一个目录上` |
| 3 | 忽略「显示所有文件」 | `目录读取：打开「显示所有文件」之后仍然看不到 .bin / 隐藏文件` |
| 4 | 排序不把文件夹放最前 | `目录读取：按名称排序时文件夹没有排在最前` |
| 5 | 新导航不清前进栈 | `文件状态：后退之后进新目录，前进栈没有清空` |
| 6 | 收藏上限多放一条 | `文件状态：收藏上限不对（21）` |
| 7 | 文件浏览器发起的整文件夹导入只扫一层 | `文件页检查：整个文件夹没有递归加入（nested\sub\inside.mp3 不在列表里）` |
| 8 | 分离状态故意不写进设置 | `文件页检查：分离状态没有存进设置` |

两条测试是在变异"第一次没红"之后**收紧**的，不是产品改好：
① 假服务原先在取消时返回 `Cancelled`，代际号变异也能过；改成 `Thread.Sleep(600)` 且不看 token
（模拟 SMB 超时里真实枚举不响应取消），并等过 600 ms 再断言，才逼出"慢结果盖掉新目录"；
② 整文件夹测试原先把 `inside.mp3` 放在 `nested` 根下，`MaxDepth = 0` 也能扫到；改成
`nested\sub\inside.mp3` 才验得出"只扫一层"。

## 10.3 GATED 探针

`播放器_TEST_FILEBROWSERPROBE=1`：造 5,000 个空 `.mp3`，`FileBrowserService.ReadDirectory`
**2 ms / 5,000 条 / 未截断 / 托管内存 6,713 KB**。⚠ 这 5,000 个文件刚写完、全在系统文件缓存里，
2 ms 不代表冷盘或网络盘；探针只量不判，别拿它当性能承诺。

## 10.4 环境记录：两次挂死与"关掉另一个播放器"

最终验收前，本机有一个 14:09 打开、正在放歌的播放器（`%LocalAppData%\Programs\全能本地播放器`
里的 1.23.0）。全量冒烟**连续两次**在第 2 步「音频窗口」关闭处挂死：看门狗 180 秒到点，
写了两份 `smoke-hang-*.dmp`（1,619,328 / 1,619,912 字节），退出码 1；单独跑第 2 步能过。
按所有者确认，用 `CloseMainWindow()` 正常关掉那个播放器，再跑全量即绿（275.4 / 286.2 / 285.3 秒）。
这是 1.18.0 / 1.22.0 起就记过的 **Application Hang（`0xCFFFFFFF`）形状**，**本版没有修**；
如实记在这里，不把"关掉别的播放器之后绿了"说成"修好了"。关掉之后紧接着连跑时，
还遇到过一次在第 2 步 `form-charlie.wav` 附近停住（没有走完看门狗）；停掉、隔一会儿再跑才恢复。
所以最终三次是"每次之间留间隔"跑出来的，不是连发。

> 三次全量都在这台机器上跑；`主窗体与主题` 一步 112～117 秒（比 1.23.0 的约 70 秒慢，
> 机器负载 / 音频设备初始化占多数）。全量合计比 1.23.0 的 225.9 秒慢，不是文件页单独慢
> （文件页 5.1 秒）。桌面歌词那一步还撞到过一次 `IsCursorIdle` 自检不成立（真实鼠标 / 系统活动），
> 重跑即绿，判据没改。

# 1.26.0 计划：文件页递归搜索

> 状态：**已发布（2026-11-19）**。范围 = 所有者选定的 **B（文件页递归搜索）**；
> 版本 1.26.0（用户看得见的新能力，按次版本）。本轮只做到“实现 + 全量验收”，
> **不发版、不打 tag、不新增第 34 项检查**。

## 1. 目标与成功判据

文件页的搜索框从“只筛当前文件夹”扩展为“可选包含子文件夹”；递归搜索有界、可取消、
在后台执行，结果能看出文件在哪一层。

- 勾选「含子文件夹」后按 `Enter`，能找到根目录、`nested`、`nested\sub` 下的匹配文件；
  结果列表有「位置」列（根层为空，深层写 `nested\sub`）。
- 输入过程中**不扫盘**；当前文件夹模式仍是原来的即时过滤。
- 启动搜索调用 < 200 ms（慢搜索假服务验证）；旧搜索的迟到结果不能覆盖新结果。
- 本地上限 **32 层 / 20,000 条结果 / 200,000 个已看条目**；网络 **16 层 / 10,000 条 /
  100,000 条**；触到上限在状态行说明。
- 搜索取消、导航、编辑查询、清空、`Esc` 都不留下上一轮结果；`F5` 在结果页重搜。
- 第 33 项（第 28 个运行步骤）新增断言全部通过，冒烟口径仍 **28 / 33**；设置仍 **7 组 92 项**；
  8 条变异按预期红。
- 现有 1.25.0 的搜索 / 类型筛选 / 拖放 / 定位断言一条不改仍全绿。

**不做**：索引 / 缓存、自动刷新、实时（每敲一个字就扫盘）递归、文件夹树、封面缩略图、
删除 / 改名 / 移动、SMB 自动发现、把搜索范围写进设置。

## 2. 行为规格

| 场景 | 规格 |
| --- | --- |
| 默认 | 「含子文件夹」不勾选，行为与 1.25.0 完全一致 |
| 勾选后 | placeholder 改为「输入关键字，按 Enter 搜索子文件夹」；打字只更新查询，不扫盘；`Enter` 才启动 |
| 空查询 | 不扫盘；列表显示当前层全部可显示条目；状态行提示「含子文件夹：输入关键字后按 Enter 搜索」 |
| 有结果时改查询 | 立即丢弃上一轮结果，回到当前层，状态行提示「按 Enter 搜索「新词」」 |
| 搜索结果 | 扁平列表，按现有排序（文件夹永远在前，名称 / 大小 / 修改时间 / 类型）；新增「位置」列 |
| 结果里的文件夹 | 双击进入该文件夹；导航后清空搜索与范围 |
| 类型筛选 | 搜索结果已经按查询筛过；「只看类型」在内存里再筛文件，不重新扫盘 |
| 状态行 | 搜索中「正在搜索子文件夹…（看了 N 个文件夹 / M 项 / 找到 K 个） · 按 Esc 取消」；完成后「含子文件夹 · 搜索「q」：N 项 · 看了 M 个文件夹 / K 项」；触限 / 读不了的文件夹追加说明 |
| `Esc` | 搜索中取消并清空，回当前层；有结果时清空结果并回当前层 |
| `F5` | 结果页重新执行同一查询；非结果页保持“刷新当前目录并保留查询” |
| 导航 | 打开 / 前进 / 后退 / 上级 / 恢复设置 / 定位当前文件：取消搜索，清空查询、类型筛选与「含子文件夹」 |
| 此电脑 | 「含子文件夹」禁用并自动落下；递归只从真实文件夹开始 |
| 键盘 | `Ctrl+F` 聚焦搜索框；未勾选时 `Enter` 回列表，勾选时 `Enter` 启动搜索；开关上空格 / 回车不被命令层抢 |

## 3. 设计

### 3.1 `Core/FileBrowserSearch`

- `FileBrowserSearchLimits`：`MaxDepth` / `MaxResults` / `MaxEntriesVisited`；
  `ForPath(root)` 用 `MediaFormats.IsNetworkPath` 选本地 / 网络两套。
- `FileBrowserSearchProgress` / `FileBrowserSearchResult`：进度、命中、截断、取消、错误、
  已访问文件夹 / 条目、读不了的子目录数。
- `FileBrowserSearch.Search(root, query, showAllFiles, token, IProgress<…>?)`：阻塞、无界面、
  `virtual` 供测试注入慢搜索。

遍历规则：

- 显式栈 DFS，根目录深度 0；每个目录 `EnumerateFileSystemInfos()` 只枚举一次。
- 每个条目复用 `FileBrowserService.CreateEntry`（改成 `internal static`），
  分类 / 隐藏 / 大小 / 时间只有一套判断。
- 默认跳过隐藏 / 系统项（含目录，不进入）；「显示所有文件」才收。
- 重解析点（目录联接 / 符号链接）不向下走；名字命中的链接可以作为结果出现，但不展开。
- 深度到上限不再压子目录；结果 / 已看条目到上限停止；三者都置 `Truncated`。
- 每个条目 / 目录之间检查 token；取消保留已找到条目，视图侧丢弃。
- 根目录不存在 / 是文件 / 无权限 / IO 失败分别给可读错误；子目录读不了只跳过并累加
  `UnreadableFolders`。
- 查询词只 `Split` 一次，对 200,000 条复用同一组词（`FileBrowserFilter.Matches(entry, terms)`）。
- 进度约每 100 ms 报告一次；core 不排序，视图按当前排序字段排。

上限：

| 路径 | 层数 | 结果 | 已看条目 |
| --- | --- | --- | --- |
| 本地 | 32 | 20,000 | 200,000 |
| 网络 | 16 | 10,000 | 100,000 |

### 3.2 相对位置

`FileBrowserPaths.RelativeFolder(root, path)` 取所在目录相对 `root` 的路径，`.` 回空串；
不同盘符 / UNC 根、越界、坏路径都回空串。文件夹结果取父目录（“在哪一层找到”，不是重复名字）。

### 3.3 视图

- `Ui/FileBrowserView` 增加 `CheckBox _recursiveSearch`（「含子文件夹」，`Appearance=Button`）、
  第三个 `ColumnHeader _folderColumn`（「位置」）、显式 `SetBounds` 排版、主题色、DPI 重排。
- `FileBrowserView.Behavior` 新增 `_searchResults` / `_searchActive` / `_searching` /
  `_searchQuery` / `_searchCts` / `_searchVersion` / 统计字段。
- `_entries` 永远是当前目录；搜索结果不覆盖它。`FillList` 按状态选源：
  搜索结果 → 只再应用类型筛选；递归勾选但未搜索 → 当前层全部条目；普通 → 查询 + 类型。
- `ListViewItem.Tag` 仍是 `FileBrowserEntry`；播放 / 添加 / 下一首 / 拖放 / 复制路径都按完整路径。
- 搜索启动 / 完成 / 取消 / 进度共用 `_searchVersion`；CTS 在任务结束的续体里释放。
- 进度**不用 `Progress<T>`**：测试宿主里 `SynchronizationContext` 可能为空，回调跑到线程池会
  与完成后的状态行竞争。`SearchProgressRelay` 用控件 `BeginInvoke` 搬回 UI 线程，
  再校验代际号与 `_searching`。
- `SetSort` 在结果页排 `_searchResults`；`SetTypeFilter` 只重排；`SetShowAllFiles` 在结果页 /
  搜索中按同一查询重搜；`Reload` 结果页重搜；`ResetFilter` 导航时清范围。
- 测试钩子：`ScopeToggleForTest`、`SetRecursiveSearchForTest`、`IsRecursiveSearchForTest`、
  `IsSearchingForTest`、`IsSearchActiveForTest`、`ProcessSearchKeyForTest`、
  `SetSearchServiceForTest`；只加只读属性 / 方法，避免 `WFO1000`。

### 3.4 快捷键

`MainForm.Shortcuts.IsTypingTarget` 把 `CheckBox` 也算进去：焦点在「含子文件夹」上时，
空格 / 回车归开关，不再被命令层当播放 / 暂停或打开选中项。冒烟把焦点放上去，
断言 `ProcessShortcut(Keys.Space)` 没有被命令层接住。

## 5. 测试

### 5.1 Core

`search-core` 夹具：根 / `nested` / `nested\sub` 三层命中，隐藏文件与隐藏目录，40 层深链
（`probe` 不命中 `hit`）。断言：

- `hit` 三层命中 3 条；不含隐藏项；相对位置空 / `nested` / `nested\sub`。
- `HIT` 大小写不敏感；`nested hit` 与关系；`sub` 命中文件夹，位置 `nested`。
- `showAll=true` 收隐藏项（3 条），`false` 时 0 条。
- `MaxDepth=32` 时 40 层深链不命中且 `Truncated`；`MaxResults=2` 截断；`MaxEntriesVisited=1` 截断。
- 预取消 token 返回 `Cancelled` 且 0 条；根不存在 / 根是文件有可读错误；进度至少报告一次。
- `RelativeFolder` 根层 / 两层 / 文件夹 / 跨盘；`ForPath` 本地与网络上限。

### 5.2 视图（仍在第 33 项内）

`uiRoot` 增加根 / `nested` / `nested\sub` 的 `search-hit`、隐藏项、40 层 `search-deep`。

- 勾选 → 输入 `search-hit` → `Enter`：启动 < 200 ms；结果 3 条；「位置」列空 / `nested` / `nested\sub`；
  状态行含「含子文件夹」。
- 「只看音频」只剩根 `.mp3`；「只看视频」只剩 `nested .mp4`；切回全部恢复 3 条。
- 改查询立即清结果并提示按 Enter；再 `Enter` 搜 `inside`，选中 `nested\sub\inside.mp3`。
- `Esc` 回当前层；`F5` 重搜（计数假服务调用 2 次）。
- 慢搜索：启动 < 200 ms；改查询 / `Esc` 后 600 ms 的迟到结果不能出现。
- 此电脑：开关禁用并落下；开关上空格不被命令层接住。
- 既有 1.25.0 断言不改，继续通过。

### 5.4 变异（8 条）

| # | 变异 | 实测红（原文） |
| --- | --- | --- |
| 1 | 只搜根层，不压子目录 | `递归搜索：三层以内的命中不对（direct-hit.mp3）` |
| 2 | `showAll=false` 时仍进入隐藏目录 | `递归搜索：三层以内的命中不对（direct-hit.mp3 / hidden-hit.mp3 / nested-hit.mp4 / deep-hit.srt / hidden-hit.mp3）` |
| 3 | 搜索态 `FillList` 不应用类型筛选 | `文件页检查：只看音频时搜索结果里还有视频或字幕（search-hit.mp3 / search-hit.mp4 / search-hit.srt）` |
| 4 | 「位置」列恒为空 | `文件页检查：搜索结果的位置列是「」，期望「nested」（search-hit.mp4）` |
| 5 | `MaxResults` 不生效 | `递归搜索：结果上限没有截断（3 条，截断 True）` |
| 6 | 忽略 token，取消后仍返回结果 | `递归搜索：取消之后没有报告 Cancelled` |
| 7 | 导航不取消上一轮搜索 | `文件页检查：导航到别的目录之后还显示着上一轮搜索结果` |
| 8 | 勾选后 `Enter` 不启动搜索 | `文件页检查：按 Enter 没有开始递归搜索（状态：含子文件夹：按 Enter 搜索「search-hit」）` |

流程：备份 → 改坏 → 两个工程 `-t:Rebuild` → 只跑 `文件浏览器` → 记录原话 → 复原 →
`-t:Rebuild` → 再跑绿；8 条全部按预期红，复原后单步 **12.3 秒**绿。

## 8. 边界

- 不建索引、不自动刷新、不做实时递归；每次 `Enter` / `F5` 都重新读盘。
- 离线 SMB 上正在返回的那次枚举不可立即取消；`Esc` 只阻止后续条目，界面不冻。
- 不跟目录联接 / 符号链接；自动化未造 junction（清理风险），代码检查 + 手工覆盖。
- 不新增设置字段（仍 7 组 92 项）；范围是临时视图态，导航即清。
- 缩略图、文件夹树、删除 / 改名 / 移动、SMB 自动发现仍不做。
- 已知 Application Hang（`0xCFFFFFFF`）本轮未修。
- **没有做人工鼠标 / DPI 验收**：100% / 125% 的肉眼检查与真实 UNC 递归搜索未做；
  自动化覆盖了 125% 渲染、220×200 绘制、搜索启动 < 200 ms、慢搜索取消与迟到结果。

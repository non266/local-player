# 1.27.0 计划：文件页封面缩略图（平铺视图）

> 状态：**已实现，待验收记录**。范围 = 所有者选定的 **B（文件页封面缩略图 / 平铺视图）**；
> 版本 **1.27.0**（用户看得见的新能力，按次版本号）。本轮只做到「实现 + 全量验收 + 文档」，
> **不发版、不打 tag、不动 `dist\`、不加第 34 项检查**。
> 基线：`HEAD` = `a663719`（1.26.0 发行记录），工作树干净，`<Version>` 从 1.26.0 升到 1.27.0。

## 1. 目标与成功判据

文件页多一种「平铺」形态：每个音视频文件显示它的**封面缩略图**（内嵌图优先，其次同目录外挂图），
没有封面的保持类型图标；读取全部在后台、有界、可取消、可缓存，界面不等磁盘。

- 打开「位置 → 缩略图（平铺）」后：列表切到 `View.LargeIcon`，缩略图边长 **56 逻辑像素**（按 DPI 缩放）；
  有封面的文件显示封面（**逐像素断言**），没有封面 / 封面坏掉的显示类型图标。
- 解码只发生在**专用后台线程**（断言线程号 ≠ 界面线程），打开 / 切换 / 导航调用 **< 200 ms**。
- 快速导航后旧目录的迟到缩略图**不能贴到新列表上**（代际号）；重复进同一目录**不重复读封面**
  （正缓存 + 负缓存）；同一个路径换了封面（大小 / 修改时间变了）**要重新做**。
- 每目录最多请求 **300** 个文件、队列待处理上限 **400**、内存缓存 **512** 条；触到每目录上限时状态行写
  「缩略图只做了前 300 个文件」，**不静默少做**。
- **网络路径不做缩略图**（保留类型图标，理由见 §8）；文件夹 / 字幕 / 播放列表 / 其他类型不做。
- 递归搜索结果（`含子文件夹` 的 `Enter` 结果）**强制回「详情」视图**，因为平铺里放不下「位置」列；
  清空搜索后回到平铺。其余既有断言（搜索 / 类型筛选 / 拖放 / 定位 / 分离窗口）一条不改仍全绿。
- 设置新增 **1 个字段**（7 组 **93** 项），默认**关**——不打开的人看到的界面与 1.26.0 完全一致。
- 冒烟口径仍 **28 个运行步骤 / 33 项检查**；第 33 项内新增断言全部通过；8 条变异按预期红；
  Debug / Release 0 警告；`docs-check` 绿。
- **顺带修一处所有者报的显示缺陷**：「位置」与「含子文件夹」两个按钮的文字被切掉
  （所有者 2026-11-20 截图：「位置」只剩「位」）。两个控件的宽度原来写死成 42 / 88 逻辑像素，
  现在**现量文字宽度**再加两侧留白；第 33 项新增断言钉住"文字宽 ≤ 按钮内宽、按钮右边界 ≤ 文件页宽"。

**不做**：视频首帧缩略图（第二条解码链）、图片文件缩略图（程序不认图片格式）、缩略图落盘缓存、
缩略图尺寸设置项、新快捷键、文件夹树、自动刷新、删除 / 改名 / 移动、SMB 自动发现。

## 2. 行为规格

| 场景 | 规格 |
| --- | --- |
| 默认 | 缩略图**关**，`View.Details`，行为与 1.26.0 完全一致 |
| 打开缩略图 | 「位置」菜单新增可勾选项「缩略图（平铺）(&K)」；勾上后立即切 `View.LargeIcon`，不重新读目录 |
| 平铺里的项 | 类型大图标（7 种）+ 名称在下；悬停提示仍是完整路径 + 类型 / 大小 / 时间 |
| 哪些文件做缩略图 | `Kind` 为视频 / 音频、且不是网络路径、且在列表顺序前 `MaxThumbnails`（默认 300）个之内 |
| 封面来源 | ① 内嵌图（`TagReader.Read` 的 `CoverArt`，上限沿用 12 MB）→ ② 同目录外挂图（`SidecarCover`，每目录只解析一次）→ ③ 类型图标 |
| 缩略图形状 | 等比缩放放进 56×56 框、居中、不裁切不拉伸、透明边；不做圆角 / 边框 |
| 坏数据 | 图片解不开、像素数超限（> 4,000×4,000 或 > 64 MB）、文件读不了 → 类型图标，**负缓存**这条路径，重进目录不再重试 |
| 搜索结果 | 结果页（`_searchActive`）强制 `View.Details`、「位置」列照常；清空 / 改查询回到平铺 |
| 排序 / 只看类型 / 显示所有文件 | 只重排，缓存命中不重新解码；未命中才排队 |
| 导航 / 刷新 / 前进后退 | 取消上一批请求（代际号 +1），新列表先给类型图标，缩略图到一张贴一张 |
| `Esc` / 清空搜索 | 回当前层；平铺开关保持用户的选择 |
| 此电脑 | 平铺里显示磁盘大图标；不排队 |
| 主题 / DPI 变化 | 重建大小两套图标；缩略图缓存整份丢弃并按新边长重做 |
| 极小尺寸 | 220×200、1×1 绘制不抛异常 |
| 滚轮转发 | 平铺下不按 `TopItem` 滚动（那是详情口径）：按"第一项可见项"的 `Bounds` 算目标项再 `EnsureVisible` |
| 关闭 / 释放 | 先摘 `LargeImageList` 再释放位图与图标；后台线程置停止信号、最多等 200 ms，不为一个卡住的读盘 join |

## 3. 设计

### 3.1 `Core/CoverArtLoader`（新增，纯 I/O、无界面）

- `internal class CoverArtLoader`，`internal virtual byte[]? Load(string path)`：
  内嵌封面（`TagReader.Read(path).CoverArt`）→ 没有则 `SidecarCover.FindFor(path)` 读文件字节（≤ 12 MB）。
- 外挂封面按目录缓存一份（字典，上限 64 个目录），避免 300 个文件各枚举一次目录。
- 只吞异常、写 `AppLog.Swallowed`，永远返回 `null` 而不是抛；**不判断网络**（网络策略只在视图侧一处）。

### 3.2 `Ui/CoverThumbnails`（新增，解码 / 缩放 / 上限）

- `Decode(byte[]? art, int edge)`：`Image.FromStream` → 像素 / 内存上限 → `Graphics.DrawImage`
  等比放进 `edge×edge` 居中（`HighQualityBicubic`）→ 新 `Bitmap`；任何异常 → `null`。
- `AcceptSize(width, height)`：像素数 ≤ 4,000×4,000、估算内存 ≤ 64 MB 的纯函数（给单测）。
- `ClampEdge`：边长夹到 16～256。
- 解码在**后台线程**调用；界面线程不 `Image.FromStream`。

### 3.3 `Ui/ThumbnailQueue`（新增，专用线程 + 有界 + 可取消）

- **1 条专用后台线程**（不占线程池，照 1.19.0 标签队列 / 1.24.0 目录读取的做法）；FIFO，容量 **400**。
- `CancelAll()` 清队列（正在读的那一张允许跑完，取件方按代际号丢弃——文件读取不可取消）。
- `Ready` 事件带 `ThumbnailResult(Key, Path, Version, Bitmap?)`；`null` 位图表示"没有可用封面"。
- 所有权一条线：位图由队列生产、随事件交付；交付不成就由队列释放。
- `Dispose` 置停止信号 + 最多等 200 ms（`IsBackground`，卡在 Read 里的线程不 join 到死；
  也不 `Dispose` 唤醒用的事件，避免线程醒来踩已释放对象）。

### 3.4 `Ui/FileBrowserView.Thumbnails`（新增 partial）

- 大图标集 `FileIconSet(_palette, Scaled(56))` 的 `Images` 直接当 `_list.LargeImageList`；
  缩略图**追加**在 7 个类型图标之后（索引 ≥ 7 即"这是缩略图"）。详情与平铺共用同一套索引
  （两个 ImageList 前 7 位的种类顺序相同），所以 `ImageIndex` 换形态时才对得上。
- 缓存：`_thumbnailIndices`（键 = 路径 + 大小 + 修改时间 ticks）、`_thumbnailMisses`（负缓存）、
  `_thumbnailPending`；上限 512，满了整份丢掉重建（先摘 `LargeImageList` 再释放位图）。
- `ApplyThumbnailMode()`：平铺 → `LargeImageList` + `View.LargeIcon` + `FullRowSelect = false`；
  详情 → `View.Details` + `FullRowSelect = true` + **把每行 `ImageIndex` 复位成小图标那一套** + `AdjustColumns`。
- `FillList()` 末尾 `RefreshThumbnails()`：平铺才排队，详情取消未跑完的请求。
- `RequestThumbnails()`：只挑视频 / 音频、非网络路径、前 `MaxThumbnails` 个；缓存命中直接贴、
  负缓存跳过、其余排队；超出预算的记 `_thumbnailSkipped` 供状态行说明。
- `OnThumbnailReadyFromWorker` 用控件 `BeginInvoke` 搬回 UI 线程（**不用 `Progress<T>`**，
  与 1.26.0 递归搜索同一个坑），回 UI 后校验代际号、`IsDisposed`、`WantsThumbnails`。
- 主题 / DPI：`RebuildIcons()` 里连带作废大图标与缩略图缓存（索引都是旧的）。
- `ScrollTilesBy`：平铺下按 `ListViewItem.Bounds` 找第一项可见项，再 `EnsureVisible` 目标项。

### 3.5 视图 / 行为 partial 的改动

- 「位置」菜单在「显示所有文件」后新增可勾选项「缩略图（平铺）(&K)」。
- `SetThumbnails(bool)`：改 `_state.ShowThumbnails` → `RaiseStateChanged()`（沿用退出 / 方案统一落盘）
  → `FillList()`（换形态 + 排队）→ `UpdateStatusCount()`。
- `DescribeCount()` 末尾：触到每目录预算时追加「· 缩略图只做了前 N 个文件」。
- `RestoreState()` 里调用 `ApplyThumbnailMode()` + `RefreshThumbnails()`：载入方案只换了这一项时也摆得回来。
- `AdjustColumns()` 在平铺下直接返回；`RebuildIcons()` / `Dispose()` 都按"先摘再放"处理两套 ImageList。
- 测试钩子（只加只读属性 / 方法，避免 `WFO1000`）：`SetThumbnailsForTest`、`IsTilesForTest`、
  `ThumbnailEdgeForTest`、`ThumbnailCountForTest`、`PendingThumbnailCountForTest`、

### 3.6 设置（1 个新字段）

- `Core/AppSettings.cs`：`public bool FileBrowserThumbnails { get; set; }`（默认 `false`）。
- `Core/FileBrowserState.cs`：`ShowThumbnails` + `FromSettings` / `ApplyTo`（照 `ShowAllFiles` 的写法）。
- `Core/SettingsProfile.cs`：加入「界面与主题」组清单；总项数 **92 → 93**。

### 3.7 按钮文字被切（所有者报的显示缺陷）

- 根因：`LayoutToolbar` / `LayoutFilterBar` 里「位置」写死 `Scaled(42)`、「含子文件夹」写死 `Scaled(88)`。
  字号 / DPI / 字体替换任意一项偏一点，文字就比按钮宽，字被切掉一半。
- 修法：新增 `MeasureButtonWidth(control, minimum)` = `max(Scaled(minimum), 文字宽 + Scaled(18))`，
  两个控件都用它算宽度；位置按钮随之左移、地址框让出空间。
- 断言：`CheckFileBrowserChromeFits` —— 两个控件的 `TextRenderer.MeasureText` 宽度必须 ≤ 控件内宽，
  且控件右边界必须 ≤ 文件页宽度。冒烟在 125% DPI 下跑，实测「位置」文字 44 / 内宽 66，
  「含子文件夹」文字 95 / 内宽 117（改前分别是 52 / 110）。

## 5. 测试（全部放进第 33 项）

### 5.1 夹具（`smoke-fb\ui\thumbs\`）

| 目录 | 内容 |
| --- | --- |
| `embedded\` | `a.mp3` = ID3v2.3 + APIC(64×64 纯蓝 PNG)、`b.mp3` = 无标签、`c.mp4` = covr(纯绿 PNG) |
| `sidecar\` | `d.mp3` = 无标签 + `cover.png`（纯红 64×64） |
| `bad\` | `broken.mp3` = APIC 里放非图片字节 |
| `many\` | `m0..m4.mp3` = 5 个都带封面（验每目录预算） |
| `late1\` / `late2\` | 各一个带封面的 mp3（验"后台在飞时导航走"与迟到结果） |

复用现有 `BuildId3File` / `Id3Frame` / `PictureBody` / `BuildMp4` 的字节构造；
新增本地 `MakeSolidPng(color, size)`，纯色缩放后仍同色，像素断言才有意义。

### 5.2 视图断言（真窗体）

1. 打开平铺：`View.LargeIcon`、`LargeImageList.ImageSize == ThumbnailEdgeForTest`、条目数不变。
2. **像素证据**：`a.mp3` 行索引 ≥ 7，取出的图尺寸 = 边长、中心像素 ≈ 蓝；`c.mp4` ≈ 绿。
3. 没有封面的 `b.mp3` 仍是类型图标（索引 < 7）。
4. 外挂封面 `d.mp3` ≈ 红。
5. 坏封面 `broken.mp3` 类型图标、不崩；重进目录**不再重读**（负缓存）。
6. 正缓存：再进 `embedded`，`a.mp3` 的读取次数不增加、行上仍有缩略图。
7. **缓存键**：改写 `a.mp3` 的封面并把修改时间推后 → 重新进目录，颜色跟着换（键含大小 / 时间）。
8. 迟到结果：假 loader 卡住 `late1-a.mp3` → 导航到 `late2` → 放行 → `late2-b` 有缩略图，
   缓存键里**没有** `late1-a.mp3`；导航调用 < 200 ms、队列在飞 / 排队在上限内。
9. 每目录预算：`MaxThumbnails = 3` 的 `many` 只有 3 行有缩略图，状态行写「缩略图只做了前 3 个文件」。
10. 网络规则：UNC 音频 = 不做、本机音频 = 做、目录 = 不做。
11. 搜索结果强制详情：`View.Details`、位置列宽 > 0；清空搜索回平铺。
12. 切回详情：列宽回来、`FullRowSelect` 回来、所有行索引 < 7（在 `embedded` 里验，行上真的贴着缩略图）。
13. 平铺 220×200 渲染 + 平铺滚轮不抛。
14. 设置：状态对象字段、`ApplyTo` / `FromSettings` 往返；外层再验一次磁盘（关窗时的统一落盘）。
15. **按钮文字**：`位置`、`含子文件夹` 的文字宽 ≤ 内宽、右边界 ≤ 文件页宽。

### 5.3 探针（GATED，只量不判）

- `播放器_TEST_THUMBNAILPROBE=1`：造 100 个带 256 像素 PNG 封面的 mp3，
  打印"读取 + 解码"总耗时、命中数、封面字节合计、托管内存。
- `播放器_TEST_LAYOUTPROBE=1`：打印窗体 / 侧栏 / 文件页 / DPI、两个按钮的位置与文字宽度、列表列宽。

### 5.4 变异（8 条，全部按预期红）

| # | 变异 | 实测红（原文） |
| --- | --- | --- |
| 1 | 在调用线程上同步读 + 解码 | `文件页检查：封面在界面线程上读了（线程 2 / 2 / 2，界面线程 2）` |
| 2 | 贴图不看代际号 | `文件页检查：离开目录之后迟到的封面贴到了别的文件上` |
| 3 | 不记负缓存 | `文件页检查：封面坏掉的文件每次进目录都重新读（调用 2 次，第一次 1 次）` |
| 4 | 没有封面也返回占位图 | `文件页检查：没有封面的 b.mp3 也用上了缩略图（索引 8）` |
| 5 | 每目录预算不生效 | `文件页检查：超过上限仍然给全部条目排了缩略图（5 个）` |
| 6 | 搜索结果仍停在平铺 | `文件页检查：递归搜索结果里还停在平铺，「位置」列看不见` |
| 7 | 缓存键只看路径 | `文件页检查：a.mp3（换过封面） 的缩略图颜色不对（51,153,255，期望 224,204,51）` |
| 8 | 网络路径也排队读封面 | `文件页检查：网络路径也去读了封面` |

流程：备份被改的那个文件到 `%TEMP%` → 改坏 → **两个工程** `-t:Rebuild` → 只跑 `文件浏览器` →
记录原话 → `Copy-Item` / 原文本写回复原 + 推 `LastWriteTime` → 两个工程 `-t:Rebuild` → 再跑绿。

> 变异 7 的第一次尝试是"切回详情不复位行图标"，结果**绿**：`SetThumbnails` 会重建列表，
> 而重建时本来就按类型图标赋值，"复位"那一步被重建掩盖了。换成"缓存键只看路径"之后立刻变红——
> 这与 1.18.0「排序没移动任何行等于没断言」是同一类教训：**变异要落在断言真的能看见的地方**。

## 8. 边界与如实说明

- 平铺里**没有**「大小 / 位置」列（`ListView` 的大图标形态不放表头）：要这些信息切回详情或用悬停提示。
  搜索结果因此**强制详情**，位置列不丢。
- 缩略图只做**封面**（内嵌 / 同目录外挂），**不从视频画面截帧**：那要第二条解码链（F6 那一族），本轮不做。
- **网络路径不做缩略图**：离线共享上的读盘不可取消（与 1.26.0 的递归搜索同一条理由），
  宁可只给类型图标，也不让一条队列卡在 SMB 上。
- 只做内存缓存（**不落盘**），退出即丢；缓存键含「路径 + 大小 + 修改时间」，文件被换掉会重做。
- 每目录 300 个、队列 400、缓存 512 条都是**固定值**，不提供设置项；触上限在状态行说明。
- 缩略图开关默认**关**：不打开的人界面与 1.26.0 完全一致。
- 已知 Application Hang（`0xCFFFFFFF`）**仍未修**，本轮不碰那一段。
- **没有做人工鼠标 / DPI 验收**：按钮宽度是**程序量出来的**（125% 下「位置」44 / 66、
  「含子文件夹」95 / 117）；所有者截图里那种"字被切掉"是否在别的 DPI / 字体下还会出现，
  需要再看一眼真机。

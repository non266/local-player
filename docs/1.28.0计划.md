## 2. 行为规格（摘要）

- **文件夹树**：「位置 → 文件夹树(&T)」，默认关；`Dock=Left` 在工具栏下面；懒展开；根是「此电脑」+ 磁盘；
  每节点 ≤ 2,000 个；不跟目录联接；点节点即导航；列表导航反过来把树展开到当前目录；窄视图置灰。
- **自动刷新**：「位置 → 自动刷新(&R)」，默认开；只盯当前**本地**一层；尾部去抖 500 ms + 最短间隔 1 s；
  静默重读 → 比签名（路径 + 大小 + 修改时间）→ 变了才重建并恢复选中 / 焦点 / 顶部项；
  搜索页不刷新；目录没了停 watcher 并走普通 `Reload`；溢出 3 次停用并说明。
- **缩略图二轮**：无封面才截视频首帧（RV32 / vmem，不建窗口）；每目录 60 帧、单文件 6 秒；
  预算三档；落盘缓存 128 MB（`%AppData%\播放器\thumbnails`）；「清空缩略图缓存」；主菜单「视图」新增同名开关。
- **音频窗口**：停靠侧栏 / 播放列表照旧收起；「侧栏分离为悬浮窗」可用；归位后仍收起；文件页在
  侧栏已分离时可用（`ShowFileBrowser` 亮出侧栏窗口并切到文件页）。

**抓帧的三个坑（实测，已写进代码注释）**：
① `SetVideoCallbacks` 不给 opaque，只能用一个静态"当前实例"；
② `pitches` / `lines` **必须写**（不写 VLC 根本不往我们的缓冲里写，整帧几乎全黑）；
③ 缓冲**只增不减**（按尺寸共用一块、播放中 Free 旧缓冲 → 全黑，甚至 `STATUS_HEAP_CORRUPTION 0xC0000374`）。

## 4. G1 探针（视频帧可行性）

`播放器_TEST_FRAMEPROBE=1`（GATED）：ffmpeg 现造四象限 320×240 短片，同一个抓帧器连抓 20 次。实测：

- 20 次共 **4.6 秒**；首次（含初始化）**430~470 ms**；其余平均 **208~212 ms**、最大 **232 ms**；
- 失败 **0**；帧 **320×258**（VLC 的 vout 尺寸，画面按原生宽高缩放）；四象限 红 / 绿 / 蓝 / 黄 全对；
- 线程 **34 → 34**、句柄 **855 → 855**、托管内存约 +600 KB；释放 **177 ms**。

对照门禁（单次 ≤ 3 秒、20 次不崩、线程增量 ≤ 50、释放 ≤ 1 秒）**全部通过**，所以视频首帧留在 1.28.0 里。

## 7. 已完成 / 未做（如实）

**已完成**：§1 的 A1~A3、B1~B3、C1、C3~C6、E1~E3、D1~D3；B4（溢出停用）代码与日志就绪，
但本机没有真实溢出样本；C2 的"连续失败 3 次停用"有代码与日志，没有专门的坏视频夹具
（默认冒烟用假帧来源，真实抓帧只在 GATED 探针里跑）。

**没做 / 边界**：

- 树**不跟目录联接 / 符号链接**展开（联接照常列出、但没子节点）；网络目录只在用户展开时读，
  离线 SMB 上展开会等系统超时，界面不冻。
- 树里没有"网络"根：SMB 自动发现仍不做，UNC 只能从地址栏进（进去之后能展开）。
- 自动刷新**只盯当前一层**；子目录变化不会上浮；搜索页（递归结果）不刷新。
- 视频首帧是"解码出来的画面"，片头黑场 / 可解码失败时会退回类型图标（**全黑的缩略图不如没有**）；
  每目录 60 张、首次进大视频目录会明显变慢，第二次走磁盘缓存。
- 磁盘缓存 128 MB、卸载不删（在数据目录里）。
- 默认值变化只有一处：`FileBrowserAutoRefresh` 默认**开**。
- 音频窗口仍然**不给停靠的侧栏 / 播放列表**（1.9.0 的结论不变），只放开"分离成悬浮窗"。
- 没有人工鼠标 / DPI 验收：只做了 125% DPI 的程序渲染（`file-browser-tiles.png`）与自动断言。
- 一棵树上"展开 1,000 个子目录"的耗时探针没跑（测试里展开的层级少）；只量了常规目录。

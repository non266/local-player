## 2. 行为规格（摘要）

- **A 关窗收尾**：正常释放顺序**不变**（先 `videoView.MediaPlayer = null`，再放引擎），只是把"放引擎"
  挪到后台线程并给界面 **2 秒**上界；上界内完成就照原样走完，超时记一行、窗体照常关，剩下的交给
  进程退出回收。每一步写进环形追踪（`Ui/ShutdownTrace`），挂死时看门狗把追踪一起写进 journal。
  **等待期间不泵消息**（第一版泵消息时原生崩在 `libvlc_audio_get_delay`，见 §3 的坑）。
- **B 快捷键**：`帮助 → 快捷键设置…`；每条命令最多两个键（主键上菜单）；可清除（暂时没有键）、
  可恢复本项 / 全部默认。冲突和保留键挡在保存前；无效存盘条目忽略并提示一次。
  只覆盖命令目录里的 24 条；全局热键（`Ctrl+Alt+D`）、多媒体键、逐帧 `E` / `Shift+E`、
  延迟 `G·H·J·K`、歌词偏移 `Ctrl+[ ]`、`F1` / `Delete` / `Esc` / `Enter` / 文件页与 DVD 菜单键不可改。
- **C 便携模式**：判定顺序 `环境变量 → portable.ini → %AppData%`；marker 是 exe 旁的普通文件，
  数据落 `<exe 目录>\data`；**便携 zip 不预置 marker**；程序目录写不进去退回 `%AppData%` 并说明。

**两个坑（实测，已写进代码注释与维护手册坑表）**：

1. **等待引擎收尾时不能泵消息**：第一版"一边等一边 `DoEvents`"在冒烟里当场原生崩
   （`0xC0000005`，崩在 `libvlc_audio_get_delay`）——后台在拆引擎，泵进来的消息里却有引擎刚投递的
   状态回调，正要去读一个已经在拆的 libvlc 对象。改成纯 `Wait(2 秒)`；关窗最多静默 2 秒。
2. **只断言"追踪里有没有那一行"守不住顺序**：把 `videoView.MediaPlayer = null` 挪到放引擎之后、
   追踪行留在原地，测试照样绿。所以另记一个**事实**字段 `VideoOutputDetachedBeforeTeardown`
   （赋值之后 `videoView.MediaPlayer` 是不是真的空了），两条一起断言。

## 4. G1 探针（先量后改）

`播放器_TEST_TEARDOWN=N`（1.18.0 就有，**但调用点在 1.22.0 重排步骤时被整段替换掉、从来没跑过**；
本轮接回主流程并加门槛）。同一进程里连做 N 轮"音频卡片 → 视频 → 关窗"，每轮记关窗毫秒与
**关窗那一段**的线程 / 句柄增量（创建窗体 / 开引擎那部分单独记为"累计"，只打印不判定）。

| 时点 | 轮数 | 关窗 P50 / P95 / 最大 | 关窗那一段资源 | 累计（只记录） | 挂起 |
| --- | --- | --- | --- | --- | --- |
| 基线（改动前） | 20 | 123 / 162 / **180 ms** | −14 线程 / −200～−400 句柄 | +23 线程 / +888 句柄 | 0 |
| 修后 | 20 | 131 / 176 / **196 ms** | −13 线程 / −99～−410 句柄 | +25 线程 / +970 句柄 | 0 |

门槛（写在探针里）：单轮 **≤ 2500 ms**、关窗那一段线程 **+≤ 5** / 句柄 **+≤ 30**、失败 0。
**20 轮没有复现挂死**——所以这一版按"机制"修：界面不再陪着卡、卡在哪一步能看见；
根因（libvlc 收尾里到底卡在哪）仍未定，如实留在 README / 参考手册 / 坑表里。

## 5. 测试

### 5.1 新增第 30 个运行步骤「关窗收尾」= 第 35 项检查

`tools/SmokeTest/Program.Teardown.cs`：`RunCloseRounds(rounds)` 造"只有音轨的 mkv + 只有视频轨的 mkv"
（`WindowMode = Auto` 才能进音频卡片；结束时把原设置写回去）→ 音频卡片 → 切回三栏 → `Close()`。
断言：① 6 轮全部 ≤ 2500 ms（打印 P50 / max）；② 追踪含全部关键步骤且「摘画面输出」在「放引擎」之前；
③ `VideoOutputDetachedBeforeTeardown` 为真；④ 关窗那一段线程 +≤ 5 / 句柄 +≤ 30；
⑤ 正常轮次 `LastShutdownTimedOut=false`；⑥ 慢收尾注入：关窗 ≤ 3500 ms **且 ≥ 1500 ms**（上界真的生效，
不是 0）、`LastShutdownTimedOut=true`、追踪含「收尾超时」。实测这一步 **13.0 秒**。

## 7. 已完成 / 未做（如实）

**已完成**：§1 的 A1～A5、B1～B5、C1～C4。

**没做 / 边界**：

- **关窗挂起的根因未定**：本机没有 `cdb` / `windbg`，转储当场分析不了。这一版修的是"不让它把界面挂住 +
  卡在哪一步能看见"；若超时被频繁触发，追踪会指出是哪一步，下一轮再按那一步查。
- **关窗最多静默 2 秒**（等待期间不泵消息，见 §3 的坑）；Windows 判"无响应"要 5 秒以上，
  所以不会触发挂起判定，但确实有 2 秒内界面不刷新。
- **快捷键只覆盖命令目录里那 24 条**：逐帧 `E` / `Shift+E`、延迟 `G·H·J·K`、歌词偏移 `Ctrl+[ ]`
  还没进目录，本轮不可改；全局热键与多媒体键走另一套（`RegisterHotKey`），不参与。
- **便携模式不预置 marker**：便携 zip 内容不变（载荷仍是 647 文件），要让"解压即便携"得用户自己
  放一个 `portable.ini`；**不做**从 `%AppData%` 自动搬迁（那会变成"我升级了一下，设置没了"）。
- **E 没选**：桌面歌词右键那条假红（依赖前台窗口）本轮不修、不收紧判据；验收时照 1.21 的口径
  如实记录。（本轮全量一次通过，没有撞到它。）
- 仍**不做**：网络位置缩略图、树里的「网络」根、缩略图尺寸档（D 没选）；画面调整（C1 结论不变）。

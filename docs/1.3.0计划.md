## 0. 先修再增：1.2.1

### 0.1 进度条：拖动时"当前时间"被真实播放时间反复覆盖（所有者报告）

- **现象**：播放中拖动进度条，右下角"当前时间"**反复跳回真实播放时间**。
- **根因（已读代码定位）**：`MainForm.UiTimer.cs` 的 `UpdateProgress()` 里
  `if (!_userSeeking && length > 0)` **只护住了 `trackSeek.Value`**，紧跟其后的
  `lblCurrentTime.Text = …` 在护罩**外面**——计时器每 200 ms 都用真实播放时间写它一次；
  而拖动时 `OnSeekScroll` 又把同一个标签写成拖动目标。两个写者互相覆盖，看起来就是"反复显示"。
- **同一小段里另外两处确认过的毛病**（一起收掉）：
  1. `Ui\FlatSlider.cs` 的 `OnMouseLeave` 无条件把 `_dragging` 清掉——鼠标其实还在**捕获**中，
     于是**按住拖到进度条外面（比如下方）之后就不跟手了**；
  2. `MainForm.Startup.cs` 的 `trackSeek.MouseDown += (s, e) => _userSeeking = true;` **不分按键**，
     而 `OnSeekMouseUp` 会无条件定位——**右键点一下进度条也会 seek 一次**（并让计时器停止刷新进度）。
- **修法**（都在这一小片代码里）：
  1. `UpdateProgress()`：拖动期间**不要**用引擎时间覆盖 `lblCurrentTime`（总时长照旧刷新）；
  2. `FlatSlider`：拖动中只在"真的没有捕获"时才复位拖动状态（拖出控件范围继续跟手）；
  3. 只有**左键**按下才算"用户在拖动"。
- **断言**（第 6 步新增一段；自己造一段 20 秒的 WAV 起播，别借别的步骤的媒体）：
  按住左键 → 移到 50% → **保持不动**泵 600 ms（够 3 个计时器周期）→ 断言
  `trackSeek.Value` 仍在 50% 附近、`lblCurrentTime` 仍是**拖动目标**而不是播放时间、
  且期间 `_engine.Time` 是**照常推进**的（没有被 seek 打断）；
  再按住拖到控件下边界之外 → 断言取值仍跟着走；
  最后右键按下抬起 → 断言**没有**发生 seek（`_engine.Time` 连续）。
- **变异**：① 把 `lblCurrentTime` 那行移回护罩外 → 必须以"标签被播放时间覆盖"变红；
  ② `OnMouseLeave` 恢复成无条件清 `_dragging` → 必须红；③ `_userSeeking` 改成不分按键 → 必须红。
- **文档**：README 的传送栏那一节补一句"拖动时时间标签显示的是**你要跳到的位置**，
  松手才真正跳转"。

### 0.2 M7：`SaveInBackground` 在"写入在飞"时丢掉那次快照

原文与判据见 [维护手册](维护手册.md) 第 3 节「M7」。一句话：关掉「记住播放进度」之后，
按文件的调整（歌词偏移 / 音画 / 字幕延迟）只剩 `PerFileAdjustments.Record*` 这一条落盘路径，
而它在"已有一次后台写入在飞"时会早退——"调完立刻关程序"可能把这次调整留在内存里。
修法（写到不脏为止 + 理清退出时那条同步 `Save()` 与在飞写入的关系）、
断言（给 `PlaybackHistory` 加一个测试用的写入门闩把一次写入按住）与变异都在 M7 那条里写好。

## 1. 1.3.0：所有者点名的六件事

拆成三批，**每批做完都要** `release-check` 全绿 + 至少一个变异 + 文档同批。
新设置项与分组要同时改 `Core/SettingsProfile.cs`，否则第 20 步的"不重不漏"会红。

### 批次 A（小、互相独立，先出价值）

#### A-1 A-B 循环（3 小时）

- **行为**：`播放 → A-B 循环` 子菜单：`把 A 点设在当前时间` / `把 B 点设在当前时间` / `清除 A-B`。
  设好后播放越过 B 就跳回 A；菜单里写出当前 A/B；**A ≥ B 时如实拒绝并说明原因**；
  换歌 / 停止时清除。先不给快捷键（现有单键快捷键很挤，避免撞车）。
- **改动点**：`MainForm.Playback.cs`（两个 `TimeSpan?` 字段 + 三个动作 + 菜单）、
  越界判断放在 `UpdateProgress()` 里（用引擎时间，不另起计时器；那里已经每次都在算时间）。
- **断言**：造 6 秒 WAV 起播 → A=1 s、B=2 s → 泵到 3 s → 断言 `_engine.Time` 落在 `[1s, 2s)`
  （回跳确实发生过）；A > B → 断言被拒绝且状态栏写了原因；清除后 → 断言不再回跳。
- **变异**：越界判断写成 `>`（正好到 B 那一帧不回跳）→ 红；A > B 不拒绝 → 红。

#### A-2 音量均衡（normalize）（4 小时）

- **行为**：`播放 → 音量均衡（normalize）` 开关，设置项 `NormalizeVolume`（默认关，归**「音视频输出」**组）。
  切换后**重新起播当前这一首**才生效（状态栏说明"已从头开始以应用"）。
- **改动点**：`Core\PlayerEngine.cs` 的 `CreateMedia()`（媒体选项唯一的拼装点）按设置加
  `:audio-filter=normvol`；把选项拼装抽成**纯函数** `Core\MediaOptions.cs`（便于直接断言）；
  `SetNormalize(bool)` 触发重载（复用 `PlayIndex(_playlist.CurrentIndex)`）。
- **断言**：① 纯函数：开关打开时选项串里有 `normvol`、关掉时没有（这条是硬判据）；
  ② 第 6 步：切换后 `_engine.CurrentPath` 不变、`_engine.Time` 从头开始、状态栏说了"从头开始"。
- **变异**：把 `normvol` 从拼装里删掉 → 纯函数断言红。
- **如实说明**：**响度效果不做数字断言**——进程里量不到输出电平（真要量化得给引擎加一条
  只在测试里用的 PCM 回调，那是 M 级工作量，先不做）。README 里写清"能挂上滤镜、效果靠耳听"。

#### A-3 「下一首播放」队列（半天）

- **行为**：列表右键与 `播放` 菜单各两个入口：`下一首播放`（把选中项入队，最多 20 条、重复入队去重）、
  `清空下一首队列`。入队的行在标题前显示 `▶ `。当前这首**自然播完**时：队列非空 → 播队首并出队，
  **列表的当前项不动**；队列空 → 照旧播列表的下一首。状态栏说明"队列里还有 N 项"。
- **改动点**：新增 `Core\PlaybackQueue.cs`（纯逻辑：入队 / 出队 / 去重 / 上限）；
  `Core\PlaylistItem.cs` 加一个**只在内存里用**的标记字段（不写盘）；
  `MainForm.EngineEvents.cs` 的"自然播完"那一支先问队列；右键菜单 + 播放菜单入口。
- **断言**：纯逻辑（去重、上限、出队顺序）+ 第 6 步：起播 A、把 C 入队 → 触发播完 →
  断言引擎在播 C 且 `_playlist.CurrentIndex` **没变**；C 播完 → 断言回到列表里 A 的下一首。
- **变异**：播完不看队列 → 红；看了却把列表当前项也改掉 → 红。

### 批次 B（中）

#### B-1 歌单窗口：拖拽排序 + 批量重命名（1 天）

- **行为**：歌单窗口的列表可拖拽换位（带插入位置提示）→ **拖完立即按新顺序改写那份歌单文件**
  （和这个窗口里已有的重命名 / 删除一样，直接动文件），状态栏说明；
  选中多份 → `批量重命名…` → 输入基名 → 按当前显示顺序依次 `基名 1` / `基名 2` …；
  名字非法或冲突时**先挡住、一个文件都不动**；被改名的正好是当前歌单 → 主窗体的关联跟着走。
- **改动点**：`Ui\PlaylistLibraryDialog.cs`（`ListView.ItemDrag` + `InsertionMark`，照主列表
  `MainForm.Search.cs` 的拖动做法）、`Core\PlaylistLibrary.cs` 加 `Reorder(name, paths)`
  （读出条目 → 按新顺序写回，复用现成的 `Save`）、名字规则与去冲突复用 `Core\SavedName.cs`。
- **断言**：第 17 步：造 3 份歌单（各 3 项）→ 把第 3 份拖到第 1 份之前 → 断言
  `PlaylistLibrary.List()` 的顺序**和磁盘上文件里的条目顺序**都对；批量重命名 3 份 →
  断言文件名、内容、当前歌单关联；名字冲突 → 断言一个文件都没动。
- **变异**：拖动只改界面不改文件 → 红；批量重命名把条目写丢 → 红。

#### B-2 画面旋转 / 上下翻转（按文件记住）（1 天）

- **行为**：`视图 → 画面旋转` 子菜单：`不旋转 / 顺时针 90° / 180° / 逆时针 90° / 水平翻转 / 垂直翻转`；
  **按文件记住**（和音画 / 字幕延迟一样）；**只对视频有效**（音频时禁用并写明原因）；
  切换时**重新起播当前这一首**才生效（状态栏说明）。
- **改动点**：`Core\MediaOptions.cs`（和 A-2 共用那个纯函数）拼 `:video-filter=transform` +
  `:transform-type=<类型>`；`Core\PerFileAdjustments.cs` 与 `PlaybackRecord` 加第 4 个字段
  （**只增字段**，`history.json` 老文件照读）；`MainForm.Video.cs` 的菜单 + 勾选刷新。
- **动手前先验 10 分钟**：libvlc 里"有插件"不等于"真的有效"（C1 就是这么翻车的）——
  先手写一条最小命令确认 `transform` 在这台机器上真的转了画面，再写菜单。
- **断言**：① 纯函数：给定"顺时针 90°"拼出的选项串正确；② 第 13 步（真视频）：
  用 ffmpeg 造一个**四个象限颜色各不相同**的短片（一次性命令，不入库；
  没有素材就照 `播放器_TEST_VIDEO` 的先例跳过），旋转前后各截一帧 →
  断言四个象限的颜色**按预期搬家**（不是"像素差很大"这种弱判据）。
- **变异**：把 `transform-type` 写死成 0 → 象限断言红。
- **风险**：滤镜要重载媒体 → 切换有一下停顿；transform 只转画面、不改窗口比例，说明书里要写清。

### 批次 C（大）

#### C-1 SMTC（Win10/11 音量弹窗里的媒体控件）（1~2 天）

- **行为**：系统音量弹窗（与锁屏界面）里显示曲名 / 歌手 / 封面，以及播放 / 暂停 / 上一首 / 下一首按钮。
  系统媒体键**保持现状**（仍走 `RegisterHotKey`），SMTC 只负责"显示 + 那几个按钮"。
- **改动点**：新增 `Ui\SmtcSession.cs`，**手写 COM 互操作**
  （`ISystemMediaTransportControlsInterop` / `ISystemMediaTransportControls` /
  `…DisplayUpdater` / `…TimelineProperties` / `IRandomAccessStreamReference`），
  照 `Ui\TaskbarThumbnailButtons.cs` 已有的手写 COM 写法；主窗体在切歌与播放 / 暂停变化时喂它
  （钩子用现成的 `ApplyMetadata` / `UpdateLyricsPosition`）。
- **为什么不改目标框架**：C2 当初判"要引 WinRT、得把 TFM 改成 `net8.0-windows10.0.19041.0`"——
  手写 COM 绕开了它（任务栏缩略图按钮就是这么干的），代价是自己写那份接口声明，
  好处是**老 Win10 不会被这一版丢掉**。
- **兼容**：`ISystemMediaTransportControlsInterop` 要 **Win10 1809+**；拿不到接口就**安静降级**
  （记一条日志、不打扰用户）。本机是 Win10 19045（22H2），能验。
- **断言**：起播一首 → 断言我们这层包装真的建起来了、`IsEnabled` 为真、曲名 / 歌手 / 时长
  都喂了进去（读自己的包装对象，不去问系统）；切歌 → 断言喂的是新歌。
  **变异**：切歌时忘了喂新标题 → 红。
- **如实说明**：**系统那侧真的显示出来了没有，冒烟里验不到**——要人眼看一次；
  README 里写清"验到哪一层"。

## 4. 每条都要交的东西（house rules）

1. **断言**：判据要能区分"环境不成立"与"功能坏了"，跳过必须打印原因；
   别拿"早先拍下的状态"当基准（第 1 节的两条经验）。
2. **变异**：把被测行为改坏，必须**以一句具体的话**变红。
3. `tools\release-check.ps1` 全绿（Debug / Release 0 警告 0 错误 + 全量 20 步）。
4. 文档同批：README（功能面）、[docs/介绍.md](介绍.md)（入门）、[CHANGELOG.md](../CHANGELOG.md)、
   本手册的分诊表 / 更新节奏。

## 5. 明确不做（这次翻不了案）

- **画面调整（亮度 / 对比度 / 饱和度 / 色相 / 伽马）**：C1 实试过五种办法都不影响输出画面——
  "1.3 要加功能"不是翻案的理由。
- **逐字染色（卡拉 OK）**：LRC / SYLT 里没有逐字时间轴（C8）。
- **虚拟列表、封面 / 歌词重绘优化、`IsOpenable` 剩余角落**：D 档，各自的触发条件见维护手册。
- **B4 筛选状态下拖动换位**：这次没有点名，维持"有人被绊住再说"。

## 2. 先量后改（A）

基线（HEAD，同一夹具，旧管线）：打开 600 项 **4,764 ms** 才稳定、做出 **401** 张
（队列上限 400，后 200 个请求被丢弃）、来源调用 401、可见 12 项有图 12、UI 最大停顿 109 ms；
滚到第 600 项 **末项没有图**（后来的请求没进队列），停止时也没有新的可见范围请求。

修后（同一夹具）见 §1 A1～A7。关键差别不是"解码变快"，而是：

- 只排可见范围：初始请求 600 → **24～60**（随视口宽度）；
- 不再让队列上限丢掉可见项（队列满会下一拍重试）；
- 缓存满 512 时只重建可见范围，**不再把整个目录重排**；
- 贴图改成每 50 ms 一批，**不再每张 BeginInvoke + 全表扫描**；
- 截帧可取消，换目录时封面不再等 2.5 秒。

## 6. 如实说明

- A 的数字来自**合成夹具**（2 ms 假封面），不是冷盘 / 网络盘 / 真实 4K 解码；真实视频截帧仍可能慢。
- 不做 20,000 项平铺虚拟化；只量 600 项，超大目录建行仍随行数增长。
- 缓存仍 512 条：极长单目录滚动会触发一次"可见范围重建"，可能短暂看到类型图标。
- 可见优先意味着没滚到的文件不会预先做图，这是行为变化；状态行与文档写明。
- 批量贴图最多引入 50 ms 额外延迟；没有人工鼠标 / 200% DPI 验收。
- B 只扩这 8 条；F1 刻意不改（帮助必须永远可达）；文件页 / DVD / 全局热键 / 多媒体键仍固定。
- 本轮**不发布**。

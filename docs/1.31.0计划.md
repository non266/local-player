## 1. 为什么是这两件事

- **主播放列表其实已经按“多项”写了，但列表从来没开多选**：
  `RemoveMany`、`QueueSelectedForNext`、`CopySelectedPaths`、`FindDuplicateItems` 都按多项工作，
  「找出重复项」甚至在状态栏写「按 Delete」；但 `listViewPlaylist.MultiSelect` 一直是默认的
  **false**，用户用 Ctrl / Shift 根本选不中第二项。这是“代码支持、入口没开”的缺口，
  也解释了为什么「找出重复项」的程序化多选用户没法再手动调整。
- **1.30.0 的文档有两处当前状态互相矛盾**：
  - `docs/参考手册.md` 第 2992 行仍把逐帧 `E` / 延迟 `G·H·J·K` / 歌词偏移 `Ctrl+[ ]`
    列进“不能改”，与 1.30.0 的 33 条命令目录相反；
  - `README.md` 的快捷键表被一段 `>` 提示从中间截断，最后 4 行落在提示之后，
    实际渲染成两张表；
  - `docs/介绍.md` 还写着 50,000 条「按名称排序约 4 秒」，1.18.0 实测已是 **1,566 ms**；
    安装体积标签也停在 1.29.0。
  这些是“文档说的不是现状”，不是历史章节，应该在本轮一并收口并加门禁。

## 3. 行为规格

- `listViewPlaylist.MultiSelect = true`；Ctrl / Shift / Shift+方向键沿用 WinForms 原生行为。
- `Ctrl+A` 只选当前可见行：无筛选 = 全部；有搜索 / 类型筛选 = 只选看得见的；
  列表空时什么都不做。批量操作统一按 `GetSelectedPlaylistIndices()` 升序，不按点击顺序。
- 批量动作：
  - `Delete` / 右键 / 工具栏移除：`RemoveMany` 一次删完；正在播的项在其中就先停止；
    **删前清选中**，删完不残留；状态栏写「移除 N 项」。
  - 下一首播放：按模型顺序入队，重复 / 队列满沿用原说明。
  - 复制完整路径：每行一条，按模型顺序；状态栏写「复制 N 条」。
  - 在资源管理器中显示：只定位第一项，多选时状态栏说明「一次只能定位一项」。
  - 上移 / 下移：仍只允许一项；多选时右键项置灰，工具栏点击给「请先选中一项再移动」。
  - 拖动换位：仍只允许一项；多选时给「多选时不能拖动排序，请只选一项」。
- 右键菜单按选中数刷新：移除 / 复制 / 下一首写数量，显示项写「第一项」。
- 双击按焦点行播放；Enter / 菜单「播放」按选中第一项播放。

## 6. 边界与如实说明

- 不做整批上移 / 下移与多行拖动：插入位置对多项没有确定语义，保持单行。
- 资源管理器 `/select,` 一次只能定位一个文件，多选时只定位第一项并说明。
- `Ctrl+A` 在 50,000 行时没有量过耗时；本轮只验 6 项功能。
- 没有人工鼠标 / 200% DPI 验收；Ctrl / Shift 是 WinForms 原生行为，测试用程序化选中 + 键处理覆盖。
- 文档真值只收口本轮发现的矛盾，不是全量校对。
- 仍不做：网络位置缩略图、20k 平铺虚拟化、缩略图尺寸档、关窗挂起根因、代码签名。

# 1.33.0 计划：批量添加真值 + 清空可撤销 + 歌单库整批拖动

> 状态：**已实现（未发，验收通过）**。基线 `HEAD = 3ab4f54`（1.32.0 发行记录）；`<Version>` 1.32.0 → **1.33.0**。
> 范围 = 修批量添加不标「未保存」的根因 + 把 1.32.0 的一级撤销扩到清空 + 歌单库多选整批拖动。
> 本轮**不发版**：没有 tag / 打包 / GitHub Release，`dist\` 不动。

## 1. 为什么是这三件事

- **批量添加没有把当前歌单标成「未保存」**：`Playlist.AddRange` 只发 `Changed`、
  不发 `ContentChanged`，而「未保存」只订阅后者。拖入多个文件 / 文件夹 / m3u 追加之后，
  载入另一份歌单会被当成「干净」，不给「先保存」的机会。1.32.0 的撤销失效逻辑也只能加
  一道「`Changed` 后比条数」的兜底；现有第 17 项只覆盖单条 `Add`。
- **清空仍只有确认框**：1.32.0 已有现成的一级快照与 `InsertRestored`，清空是同一类破坏性动作。
- **歌单库多选后拖动仍只认一行**：歌单窗口已开 `MultiSelect`（供批量删除 / 批量重命名），
  但 `OnRowDrag` / `OnRowsDragDrop` 要求恰好一行；与 1.31.0 → 1.32.0 主列表的缺口同一模式。

## 3. 行为规格

### 3.1 事件契约

- `AddRange` 非空：先 `ContentChanged`、再 `Changed`，各一次；空输入 / 全部重复不发。
- `AddRangeDistinct` 有新增时同样各一次；无新增不发。
- 保持干净的路径继续 `SuppressModified`：启动恢复、载入歌单替换、新建空歌单清空。
- 用户动作路径标脏：拖入、文件夹、m3u 追加 / 替换、文件页、光盘、历史、命令行。

### 3.2 清空撤销

- 确认框保留；清空前保存全部条目 + `0..n-1` 索引，类型 `Clear`，与移除共用一级槽位。
- `Ctrl+Z` / 右键「撤销清空（恢复 N 项）」：原顺序还原、不选中、`CurrentIndex` -1、
  不恢复播放、不恢复筛选；快照立即消费。
- 移除撤销行为不变（恢复后选中原条目，菜单「撤销移除 N 项」）。

### 3.3 歌单库整批拖动

- 新增 `PlaylistLibrary.MoveMany(names, insertBefore, out moved, out error)`：
  原坐标块移动、块内顺序不变、非连续跨过未选中项、块内 / 全选 no-op、名字失效整批失败、
  成功只写一次 `歌单顺序.txt`、不碰 m3u8 内容。
- 窗口多选允许拖动；`MoveSelectedBlockTo` 落点换 `insertBefore`，成功后重载并重选块；
  单选仍走 `TargetIndex` + `MoveSelectedTo`。
- 提示文字改为「拖动选中的一行或几行；多选按块移动」。

## 5. 测试

### 5.1 第 10 项（纯模型）

- `AddRange` 2 条：`ContentChanged` / `Changed` 各 1。
- 空数组、全部重复的 `AddRangeDistinct`：都保持 1。
- 既有 `RemoveMany` 单次通知 / 当前项断言保持。

### 5.2 第 17 项（主窗体歌单联动）

- 单条 `Add` 标未保存 → 覆盖保存回干净（既有）。
- 批量加入 2 个文件：`Modified` + 标题「未保存」；覆盖保存回干净。
- 重开窗体：当前歌单恢复、`Modified == false`、标题不含「未保存」。
- 既有载入 / m3u / 新建断言保持。

### 5.3 第 35 项（清空撤销）

- 6 项清空 → 0 项；菜单「撤销清空（恢复 6 项）」可点。
- `Ctrl+Z` → 6 项原顺序、选中为空、`CurrentIndex == -1`、状态「已撤销清空」。
- 撤销后快照消费；再 `Ctrl+Z` 说明「没有可撤销的移除」。
- 再清空 → 加文件 → 快照失效，`Ctrl+Z` 不改列表。

### 5.4 第 17 项（歌单库整批拖动）

- 4 份歌单；非连续块拖到末尾 / 最前；`List()` / 顺序文件 / 窗口显示一致；内容不变；重选块。
- 全选拖到末尾 no-op；拖到块内 no-op；名字失效整批失败且不写文件。
- 既有单选 `TargetIndex` / `MoveSelectedTo` 保持。

### 5.5 变异

实际做了 **13 条可自动化变异**，全部验红：M1 `AddRange` 只发 `Changed`；M2 连发两次
`ContentChanged`；M3 清空不存快照；M4 类型写错；M5 撤销清空后选中；M6 恢复当前项；
M7 不清快照；M9 `ContentChanged` 不清快照；M10 菜单文案；M12 歌单库 `MoveMany` 只移第一项；
M13 不写顺序文件；M14 块内倒序；M15 不重选块。逐条临时改、确认红、复原；不提交变异改动。

两条计划中的变异没有计入：**M8「清空不抑制失效」**没有可观察差异——清空事件之后代码会把
快照重新赋成刚存的那份，抑制与否最终状态相同；**M11「OLE 拖动入口仍拒绝多选」**无法在冒烟里
合成真实鼠标，窗口那侧的 `ItemDrag` / `DragOver` 只能人眼看（与 1.32.0 的边界一致）。

## 7. 边界与如实说明

- 清空撤销只有一级，不恢复播放 / 当前项 / 选中 / 筛选，不落盘。
- 确认框保留；撤销是确认误点后的第二道安全网。
- 歌单库整批拖动不提供撤销：拖错只能再拖回去，或删掉 `歌单顺序.txt` 回到按名字排。
- 歌单库只改顺序文件，不碰 m3u8 内容；名字失效时整批失败，不移动一半。
- 真实 `DoDragDrop` 多选路径无法在冒烟里合成鼠标；覆盖 `MoveSelectedBlockTo` /
  `PlaylistLibrary.MoveMany`，没有人工鼠标 / 200% DPI 验收。
- 50,000 条播放列表清空 / 撤销仍整建一次界面（约 1.5 秒），本轮不专门量。
- 批量添加现在会标脏，这是有意的行为变化；载入歌单 / 启动恢复仍干净。
- 本轮不发版；安装体积标签仍是 1.32.0 的实测值。

## 8. 明确不做

- 多级撤销 / 重做 / 撤销落盘；
- 恢复被删项 / 清空前的播放状态、选中或筛选；
- 歌单库删除撤销 / 回收站；
- 50,000 条整建优化或 `VirtualMode`；
- 筛选状态下整批移动 / 拖动；
- 降低缩略图性能检查阈值。

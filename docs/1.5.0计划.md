# 1.5.0 更新计划

**这份文档管"1.4.0 之后做什么、按什么顺序、每一条怎么验"。**
规矩仍然来自 [维护手册](维护手册.md)：触发条件不成立就不动、每条改动都要有断言与变异、
`tools\release-check.ps1` 全绿、文档同批同步。

**现状（写这份文档时）**：1.4.0 已发布（2026-10-10，Latest，两个产物都核过服务端 digest 与匿名 Range）。
本地与远端一致，工作树干净。**1.5.0 还没有开始做**——这一份是计划，不是进度。

**一句话结论**：先发一个 **1.4.1 补丁**把用户碰得到的原生崩溃（M8）修掉，
再谈加功能；**1.5.0 装什么必须所有者点名**（次版本号 = 加用户看得见的能力，
按维护手册第 1 节第 1 条的"解冻"处理）。
**1.5.0 已经点名：`F1` 睡眠定时器 + `F2` 随机播放一轮不重复**（合计 1.5 天，两条都不改既有语义）；
其余候选留在第 1 节，等以后再点。

## 0. 先修再增：1.4.1（补丁，不需要点名）

补丁只装修复 / 测试 / 文档（维护手册第 4 节的版本号规则）。这一版的目标只有一个：

### 0.0 已做：构建基线改回 SDK 8（写这份计划时顺手修的）

这台机器上现在只有 **.NET SDK 8.0.202**（10.x 的 SDK 已经不在，10.0.10 运行时还在）。
第一次跑 `release-check -SkipSmoke` 三项全红、4 秒退出，两条原因都实测过：

1. `NETSDK1112：未下载 Microsoft.Windows.SDK.NET.Ref 的运行时包` ——
   `obj\project.assets.json` 还是 1.4.0 那轮 **SDK 10** 留下的，而脚本用 `--no-restore`。
   **先 `dotnet restore`**（这次 4 秒）即可；
2. 之后真正的拦路虎是**一处 C# 14 语法**：`MainForm.DesktopLyrics.cs` 的
   `_desktopLyrics?.FontFamilyName = …`（null 条件赋值），SDK 8 的编译器只认到 C# 12，
   报 `CS0131 赋值号左边必须是变量、属性或索引器`。

**都已修**：那一行改成等价的 `if (_desktopLyrics != null) …`；
csproj 的 `LangVersion` 从 `latest` **钉成 `12.0`**（不钉的话，装了 SDK 10 的机器能编、
基线机器编不过——这种差异最难查）。修完实测主工程 Debug / Release 与冒烟工程**都是 0 警告 0 错误**。
依据与"以前写过的 '必须用 SDK 10' 被这次推翻"记在 [ARCHITECTURE.md](ARCHITECTURE.md) 第 16.1 节。

> **对后面几条的影响**：M8 的探针与二分可以照原计划做，不需要先装任何 SDK；
> 但每台机器上**第一次构建前先 `dotnet restore`**，并且**不要把 `LangVersion` 改回 `latest`**。

### 0.1 M8：换画面旋转内核时进程偶发硬崩（`0xC0000005`）——**这一版的头号任务**

A 类必修（崩溃，而且**用户碰得到**：把六种旋转挨个点一遍、紧接着按「下一个」，
和冒烟第 13 步做的是同一件事）。原文与已有的定位见 [维护手册](维护手册.md) 第 3 节「M8」。

**已经拿到的三条事实**（1.4.0 验收时量的，别再重新猜）：

1. 全量冒烟**同一份代码过了 3 次、崩了 2 次**；单独跑第 13 步连续 3 次全绿 →
   不是判据问题，是原生崩（`finally` 都没跑到，现场留下 `rotate-quadrants*.mp4`）。
2. 产品日志最后一行是 `打开媒体：rotate-quadrants-2.mp4`，**后面没有** `换了 libvlc 内核以应用画面旋转。`
   → 崩在 `Open` → `EnsureCore`（换内核那一段）里。
3. 崩的那一次是**第七次切换**：前六次每个目标内核都是新建的，**只有这一次是第一次复用缓存里的内核**
   （从"某个旋转"切回"不旋转"）。这条不对称是目前最有价值的线索。
4. **2026-10-15 又崩了一次**（改构建基线那一轮的全量**第一遍**，签名与上面一模一样），
   复跑即绿。数一下样本：**全量 8 次里崩了 4 次**——复现率不低，探针那一轮应该不难写。

**做法（顺序不许颠倒）：**

1. **先复现，再改。** 在 `tools\SmokeTest\Program.Video.cs` 里加一段**只在设了环境变量时**才跑的压测
   （`播放器_TEST_STRESS_ROTATION=1`）：一个进程内把"六种旋转各设一次 + 切到另一首"循环 **20 轮**，
   每轮打印轮次 / 目标旋转值 / 用的是新建还是复用内核。
   - 放在第 13 步**末尾**、由环境变量把关 → **冒烟步数仍是 20**，正常全量不设这个变量，行为一字不变；
     跑压测时崩了就崩在那一次进程里，正是我们要看的现场。
   - 素材要**两份**（崩溃那次是"切到另一首"）：照第 13 步现成的做法用 ffmpeg 造两个四象限短片。
   - 判据只能这么写：**探针 20 轮不崩 + 全量冒烟连跑 3 次不崩**。原生崩不是"失败返回"，
     写不成断言——这一条要如实写在文档里，别假装有断言。
2. **复现之后二分两种切换顺序**（现在只有第一种）：
   - ① 现状：先建新播放器 → 抛 `CoreRebuilt`（窗体把 `VideoView` 挂过去）→ 再放旧播放器；
   - ② 先从窗体摘下来（`videoView.MediaPlayer = null`）→ 停 + 放旧播放器 → 建新的 → 挂上去。
     代价：要动 `CoreRebuilt` 的约定，窗体在中间那一刻没有播放器；
   - ③ 还有一条便宜的假设值得先试：**"复用缓存内核"这一步到底做了什么多余动作**——
     崩溃只出现在复用那一次，所以先看"复用"与"新建"在代码上差在哪（例如把已经挂过的内核
     又挂给同一个 `VideoView`、或者旧的 `MediaPlayer` 与新的 `MediaPlayer` 短暂共存）。
3. **修完要把三处"如实说明"同步改掉**（它们现在都写着"没有修"）：
   README「已知限制」里 M8 那一段、维护手册的 M8 与节奏表、CHANGELOG 的 1.4.1 一节。
4. **放弃判据（写清楚，免得变成"照着猜改一遍"）**：探针 20 轮如果复现不出来，
   **不改产品代码**，只把探针、复现步骤与当时的机器状态记进文档，留到下次崩溃现场再查。
   维护手册 M8 原文就是"改之前必须能复现"，这一条不放松。

### F1 睡眠定时器（半天）

- **现状**：没有。`SleepTimer` 在整个工程里不存在（定时停止、定时退出都没有）。
- **行为**：`播放 → 睡眠定时器` 子菜单：`听完这一首就停` / `15 分钟后停` / `30 分钟后停` /
  `60 分钟后停` / `自定义分钟数…` / `取消`。菜单第一行写着**还剩多久**（每 10 秒刷一次），
  到点做的是**暂停**（不是退出——退出会让人以为程序崩了），状态栏写清"睡眠定时器到点，已暂停"。
- **改动点**：新增 `Core\SleepTimer.cs`（纯逻辑：`Remaining(now)` / `IsDue(now)` / `Describe`）；
  判定挂在 `MainForm.UiTimer.cs` 那**已有的** 200 ms 计时器里（**不另起计时器**——
  1.3.0 那轮刚被"僵尸计时器每 20 秒把旧历史写回磁盘"坑过）；菜单加进 `MainForm.Playback.cs`。
- **断言**：① 纯函数：到点判定、剩余时间取整、取消之后不再到点、"听完这一首"在换歌那一刻失效；
  ② 第 6 步真播放那一段——**必须挑一个"不播完也能验"的场景**：30 秒素材 + 自定义"2 秒后停"，
  泵 3 秒后断言引擎**处于暂停**、且**没有被切到下一首**。
  ⚠ 这里有个容易自欺的坑（1.3.0 的 A-3 踩过同型）：**"播完自动停"和"定时器让它停"结果一样**，
  所以判据不能只用"播完那一首"，否则"定时器那一支压根没动作"的变异照样绿。
- **变异**：① 到点那一支不动作 → 必须红；② "听完这一首"实现成"立刻停" → 必须红
  （断言要能抓到"当前这首还在播"）。
- **如实说明**：不动系统的睡眠 / 休眠（那是另一个产品）；到点只暂停；定时器不落盘（关程序即失效）。
- **成本**：半天（含断言、变异、文档）。

### F2 随机播放改"一轮不重复"（洗牌袋）（1 天）

- **现状（读过代码）**：`MainForm.Playback.cs` 的 `NextRandomIndex()` 是
  "在 `0..n-1` 里均匀取一个、只要不等于当前这个"——所以**同一首可能在一轮里播两次**
  （别的还没轮到之前），列表越长越明显。这就是大家抱怨的"随机播放老是重复"。
- **行为**：开随机时改成**洗牌袋**：把下标洗一遍、一个一个取；袋子空了**重新洗**，
  重洗时**避开上一轮最后播的那一首**（否则同一个文件会连着播两次）。
  推荐**直接改掉**（不用加开关）——绝大多数播放器说的"随机播放"就是这个意思；README 里写清。
- **改动点**：新增 `Core\ShuffleBag.cs`（纯逻辑：`Next(currentIndex)` / `Reset(count)`，
  构造函数接受 `Random` 或种子 → 断言可以完全确定）；`MainForm.Playback.cs` 改用它；
  列表长度变化（添加 / 删除 / 清空 / 载入歌单）时袋子必须跟着重置。
- **断言**：① 纯函数（固定种子）：走 n 次，**每个下标恰好出现一次**；再走一轮，第一个不等于上一轮最后一个；
  `n == 1` 时不卡死（现在的实现靠 `do/while` 保证不取当前项，n=1 时走的是提前返回）；
  列表长度变化后袋子重置（不会取到越界、也不会漏播）；
  ② 第 6 步真播放：4 首短 WAV、开随机、连按 4 次「下一个」→ 断言这 4 次打开的是**4 个互不相同**的文件
  （按引擎路径集合比）。
- **变异**：① 袋子取完不重洗 → 红；② 重洗时不避开上一轮最后一个 → 红
  （判据要能抓到"连着两次同一首"）。
- **如实说明**：随机顺序**不再跨会话一致**（本来也没承诺过）；"上一个"在随机模式下
  仍回列表里的上一项（**现状如此，这一版不改**，写进 README 的已知边界）。
- **成本**：1 天（含断言、变异、文档）。

### F3 按文件记住音轨 / 字幕轨的选择（1 天）

- **现状（读过代码）**：`MainForm.Subtitle.cs` 的轨道菜单点一下只是当次生效（`SetAudioTrack` / `SetSpu`），
  换歌再回来、或者下次打开，**选过的音轨 / 字幕轨不会自己回来**；`TrackAdjustments` 里
  只有音画延迟 / 字幕延迟 / 歌词偏移 / 旋转四个字段，没有任何轨道信息。
  双语 MKV、带导演评论音轨的片子每次都要重选——这是真实的长尾别扭。
- **动手前先做 10 分钟前置验证**（照 B-2 的先例，别把没验过的当前提）：
  **同一个文件重开两次，libvlc 给的轨道 id 是不是一样？**
  - 一样 → 直接记 id；
  - 不一样 → 记"轨道名 + 同类中的序号"（或"语言 + 序号"），并把结论写进文档与注释。
  （`GetSubtitleTracks()` 给的是 libvlc 的轨道 id，媒体级；同一份文件通常稳定，但没验之前不许当成前提。）
- **行为**：选音轨 / 字幕轨（含"关闭字幕"）就按文件记住，**和音画 / 字幕延迟同一处**
  （`history.json`，同一套"改一次就落盘"的路径）；下次打开自动选回去，状态栏说明"已记住这条音轨"。
- **改动点**：`Core\PerFileAdjustments.cs` 的 `TrackAdjustments` 加两个**可空**字段
  （`int?`：null = 没记过，`-1` = 记过"关闭字幕"——**这两种必须分得开**，
  否则"上次特意关了字幕"会被当成"没记过"而自动选上一条）；
  `PlaybackHistory` 的记录结构**只增字段**（老文件读出来就是 null）；`MainForm.Subtitle.cs` 选完之后 `Record*`，
  恢复挂在**轨道清单已经可用**的那一刻（`RebuildTrackMenus` 那一带），恢复时先置一个"正在恢复"标志，
  免得"选中动作 → 事件 → 再写一次记录"绕圈。
- **断言**：① 纯逻辑：记录 / 读回 / "没记过"与"记过 -1"分得开 / 网络流不记；
  ② 第 13 步（真视频）那一段：ffmpeg 现造一个"两音轨 + 两字幕轨"的小 mkv
  （这台机器有 ffmpeg，做法照第 13 步现成的素材套路；没 ffmpeg 就跳过并打印原因），
  起播 → 切到第 2 音轨与第 2 字幕轨 → 换歌再切回来 → 断言 `CurrentAudioTrack` / `CurrentSubtitleTrack`
  回到了刚才那两个（**不是"菜单里有勾"**）。
- **变异**：① 不恢复 → 红；② 把"记过 = 关闭字幕"当成"没记过" → 红。
- **风险与如实说明**：素材要现造；轨道 id 如果不稳，就按"名字 + 序号"记，并在 README 写清
  "同一部片子的不同压制版本可能对不上"。
- **成本**：1 天（含素材、断言、变异、文档）。

### F4 播放列表"找出重复项"（半天）

- **现状**：列表**允许**同一文件出现两次（刻意的：`MainForm.Files.cs` 里写着"同一段听两遍是合法用法"，
  所以"追加"不去重；只有"打开文件夹"与歌单窗口的"追加"会跳过已存在的路径）。
  但"不小心加了两遍"眼下没法收拾——几百项时肉眼找不到。
- **行为**：播放列表右键 / 工具栏加一项 `找出重复项…`：按完整路径比对
  （`Path.GetFullPath` 归一、大小写不敏感），**只把重复的那几项选中**（保留第一次出现的那一项），
  状态栏写"找到 N 项重复，已选中；要删请按 Delete"——**不自动删**；
  再给一个 `移除这些重复项`（确认一次）。没有重复时如实说"没有重复项"。
- **改动点**：新增 `Core\PlaylistDuplicates.cs`（纯函数：返回"该被选中的下标"）；
  `MainForm.Playlist.cs` 加菜单与动作（选中已有现成的按下标选中那套）。
- **断言**：① 纯函数：大小写不同、相对 / 绝对路径、带 `..` 的路径、同一个文件出现三次只留一项、
  没有重复时返回空；② 第 6 步真列表：塞 5 项、其中 2 项是重复的 → 断言选中的正好是重复的那 2 个、
  其它项一个没动、列表项数没变（**没自动删**）。
- **变异**：保留最后一个而不是第一个 → 红。
- **成本**：半天。

### F5（M2 / B4）筛选状态下拖动换位（半天）

- **现状**：`MainForm.Search.cs` 的 `OnPlaylistItemDrag` 在筛选时直接拒绝并提示（有意为之）。
- **要动就先定死语义**：把选中项插到目标**可见行**在模型里的位置（跨过被筛掉的行）。
- **断言**：第 6 步加一段——6 项筛出 3 项、把第 3 个可见项拖到第 1 个可见项之前，
  清空筛选后断言模型顺序、且只动了 1 项；**变异**：按可见下标而非模型下标插入 → 红。
- **说明**：这条是维护手册 B 表的 **B4**（"可修"），**不必当成"解冻"**——
  但它改变了用户可见的交互语义，所以**搭 1.5.0 发**比搭补丁干净；不做判据仍是"没人被绊住就不动"。

### F6 进度条悬停出画面缩略图（2~3 天，**这一轮不做**）

### F7 字幕外观（字号 / 位置 / 背景）（**先探针**）

- **现状（读过的）**：`MainForm.Subtitle.cs` 只能选轨 / 关字幕；libvlc 3 里与字幕外观有关的东西

## 3. 假设

> ⚠ **写这份文档时先修掉的一处构建问题（实测，不是猜的）**：
> 这台机器现在只有 **.NET SDK 8.0.202**（`dotnet --list-sdks` 只有这一条；10.x 的 SDK 已经不在，
> 10.0.10 的**运行时**还在）。第一次跑 `release-check -SkipSmoke` 三项全红、4 秒退出：
> `NETSDK1112：未下载 Microsoft.Windows.SDK.NET.Ref 的运行时包`——
> 那是 `obj/project.assets.json` 还是 1.4.0 那轮 **SDK 10** 留下的，而脚本用的是 `--no-restore`。
> `dotnet restore`（4 秒）之后仍然编不过，真正的原因是**一处 C# 14 语法**：
> `MainForm.DesktopLyrics.cs` 里的 `_desktopLyrics?.FontFamilyName = …`（null 条件赋值），
> SDK 8 的编译器只认到 C# 12，报 `CS0131 赋值号左边必须是变量、属性或索引器`。
> **两条都已修**：那一行改成等价的 `if (_desktopLyrics != null) …`；
> csproj 的 `LangVersion` 从 `latest` **钉成 `12.0`**（不钉的话"本机装了哪个 SDK"就会决定能不能编过）。
> 修完实测：主工程 Debug / Release 与冒烟工程都是 **0 警告 0 错误**。
> → 所以 **1.4.1 的第 0 步不再是"装 SDK 10"，而是"`dotnet restore` 一次 +
> 别把 `LangVersion` 改回 `latest`"**。细节见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 16.1 节。

- 本机：Win10 19045（22H2）、**构建基线是 dotnet SDK 8.0.202（语言版本钉在 C# 12）**、
  Inno Setup 6、7-Zip、`gh` 已登录；
  ffmpeg 8.0 在 `D:\ffmpeg-8.0-full_build\bin\ffmpeg.exe`（多轨素材、隔行素材、四象限素材都从它造）。
  真视频素材仍由 `播放器_TEST_VIDEO` 指定；没设就跳过第 13 步（既有约定不变）。
- **数据只增不改**：F3 会给 `history.json` 的按文件记录加两个字段（老文件读出来是"没记过"）；
  F1 若做"自定义分钟数"要进 `AppSettings` + `SettingsProfile` 的分组
  （**否则第 20 步的"不重不漏"会红**）；F2 不加设置项的话只动内存逻辑。
- **冒烟仍是 20 步**：新检查继续挂在第 6 步 / 第 13 步那几段里；
  M8 的压测是**环境变量把关**的一段，正常全量不跑它。
- 桌面歌词 / 歌单 / m3u 的既有约束不变：**不自动写回"当前列表"**；歌单窗口里的管理动作直接动文件。

## 4. 每条都要交的东西（house rules）

1. **断言**：判据要能区分"环境不成立"与"功能坏了"，跳过必须打印原因；
   别拿"早先拍下的状态"当基准；等待型判据要问"**是不是它**"，而不是"到没到时候"。
2. **变异**：把被测行为改坏，必须**以一句具体的话**变红。
3. `tools\release-check.ps1` 全绿（Debug / Release 0 警告 0 错误 + 全量 20 步）。
4. 文档同批：README（功能面）、[docs/介绍.md](介绍.md)（入门）、[CHANGELOG.md](../CHANGELOG.md)、
   本手册的分诊表 / 更新节奏。
5. **这一轮新增一条**：**原生崩溃写不成断言**——判据只能是"探针 N 轮不崩 + 全量连跑 M 次不崩"，
   跑几次、跑哪一段、当时机器在干什么都要写进文档；**没复现就不许改**（M8 的放弃判据）。

## 5. 明确不做（这次翻不了案）

- **画面调整（亮度 / 对比度 / 饱和度 / 色相 / 伽马）**：C1 实试过五种办法都不影响输出画面——
  "1.5 要加功能"不是翻案的理由。
- **逐字染色（卡拉 OK）**：LRC / SYLT 里没有逐字时间轴（C8）。
- **歌词编辑与内建在线歌词搜索**：在线获取走 LrcAPI 已够用（C4）。
- **DLNA / NAS 媒体库、皮肤、跨平台**：复杂度过收益（C3）。
- **只列自己导入的字体**：刻意如此（C6）。
- **Ogg / Opus 的 Vorbis comment 与 WMA / APE 标签**：外挂 `.lrc` 对所有格式都有效（C5）。
- **虚拟列表、封面 / 歌词重绘优化、`IsOpenable` 剩余角落**：D 档，各自的触发条件见维护手册。
- **缩略图预览（F6）**：这一轮不排，除非所有者点名。
- **系统媒体控件那半边的"人眼验收"**：1.4.0 已经"验过一遍"，但**不当成"以后免验"**——
  界面部分只有人眼看得到，这条边界照旧写在 README 里。

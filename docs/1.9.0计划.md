## 1. A4 最近播放没有记录（A 类，必修）—— **已修（2026-11-03，见 CHANGELOG 的 `[1.9.0]`）**

### 1.1 现场证据（这台机器，2026-11-03 量）

`%AppData%\播放器\settings.json`：

```json
"ResumePlayback": false,
```

`%AppData%\播放器\history.json`：**23 条记录，每一条 `LastPlayedUtc` 都是 `0001-01-01T00:00:00`、
`PositionSeconds` 都是 0**。也就是说这 23 条**没有一条是"播过"留下的**——它们是 1.7 / 1.8
的"按文件记住音轨 / 字幕轨 / 延迟 / 歌词偏移"顺手建的空壳记录。

而 `PlaybackHistory.Recent` 只挑 `LastPlayedUtc != default` 的，于是结果是 0 条：

- 菜单里永远是「（暂无记录）」；
- `menuFileRecent.Enabled = false`，整项还是灰的——**看起来像功能坏了，其实一条记录都没写进来**。

### 1.2 根因（一行早退）

```csharp
// MainForm.History.cs
private void RecordCurrentPosition()
{
    if (!_settings.ResumePlayback) return;   // ← 就是这一行
    ...
}
```

同一个开关还挡着 `CommitHistory()`（切歌 / 暂停）与 `FlushHistory()`（退出）——**三个入口一起早退**。
于是「记住播放进度」这个开关实际控制的是"**整份播放历史写不写**"：关掉之后续播位置和最近播放
一起消失。这不是用户关开关时能预期到的语义（他要的是"别记我播到哪儿"，不是"别记我听过什么"）。

### 1.3 改法：把"记不记位置"和"记不记听过"拆开

| 开关 | 现在 | 改完 |
| --- | --- | --- |
| 续播位置 `PositionSeconds` | 关掉就不记 | **关掉就不记**（语义不变） |
| 最近播放 `LastPlayedUtc` | 关掉就不记（bug） | **照记** |
| 切歌 / 暂停 / 退出时落盘 | 关掉就不写 | 照写（只写"听过"） |
| 菜单里的「· 12:34」后缀 | 有位置就显示 | **只在开关打开时显示**（否则会出现"显示了位置、打开却不续播"） |

改动点：

| 文件 | 改什么 |
| --- | --- |
| `Core/PlaybackHistory.cs` | 新增 `MarkPlayed(string filePath)`：只写 `LastPlayedUtc`（单调递增那段照抄 `Record`），**不碰 `PositionSeconds`**；`Record` 与 `TryGetResumePosition` 一个字不动 |
| `MainForm.History.cs` | `RecordCurrentPosition` 拆两路：开关开 → `Record(...)`；关 → `MarkPlayed(...)`；`CommitHistory` / `FlushHistory` 去掉早退；`RebuildRecentMenu` 的后缀加 `_settings.ResumePlayback &&`；新增 `internal RefreshRecentMenu()`（测试触发重排，和 `RefreshVideoMenu` 同一类入口） |
| `Core/PlaybackHistory.Save.cs` | 只改注释：那句"关掉开关之后按文件的调整只剩这一条落盘路径"的前提已经变了，说清现在历史照写、合并写的语义不变（**代码不动**） |
| `tools/SmokeTest/Program.History.Recent.cs`（新，≈230 行） | 1.4 的两段断言；`Program.MainForm.cs` 里在 `CheckSessionMirror()` 之后调一次（日志编号 8） |

`ScheduleResume` / `ApplyPendingResume` **仍然**以开关为前提——那两个才是真的"续播"，归开关管。

### 1.4 断言（冒烟第 8 项，`tools/SmokeTest/Program.History.Recent.cs`）

纯内存（`CheckMarkPlayedRules`）：

1. `MarkPlayed(a)` 之后 `Recent` 有 `a`，但 `TryGetResumePosition(a)` 为 `false`（位置没写）。
2. 已经 `Record(a, 3 分钟)` 的记录再 `MarkPlayed(a)`：**位置还是 3 分钟**（不许被"只记听过"抹掉），
   而 `LastPlayed` 往前推了。
3. `MarkPlayed` 不记网络流、不记空路径。

主窗体（`CheckRecentPlayedWithoutResume`，60 秒 wav 播起来后跳到 30 秒——3 秒的样本验不出
"有没有偷记位置"，因为它本来就不到 15 秒的续播门槛）：

4. 关掉「记住播放进度」→ 播过的文件**在** `History.Recent` 里，且**没有**续播位置。
5. 菜单：开关关着时条目上没有「· 位置」（先注入一条"上次开关开着时记下的 30 秒"，
   否则显示 / 不显示两种实现看起来一样，验不出菜单到底看没看开关）；
   打开开关之后同一条记录上又出现「· 00:30」。

### 1.5 变异（各自以一句具体的话变红，原话是实测抓下来的）

| 改坏什么 | 实测变红的句子 |
| --- | --- |
| 把 `RecordCurrentPosition` 的早退加回去 | `最近播放：关掉「记住播放进度」之后播过的文件没有进最近播放（5 条）` |
| 不管开关、位置一律 `Record` | `最近播放：关掉开关时还是记了进度（现在 31s，期望一条都不记）` |
| 菜单后缀不看开关 | `最近播放：开关关着，菜单里还是显示了续播位置（&1 recent-off.wav　·　00:30 / …）` |

### 1.6 风险与如实说明

- **老数据不回溯**：那 23 条空壳记录不会凭空变成"最近播放"；播一次就会出现（顺序按时间，符合预期）。
- **关掉开关之后会多写盘**：以前关掉就完全不写，现在每次暂停 / 退出会落一次 `history.json`
  （几 KB，`SaveInBackground` 还是合并写）。实现时量一次"关着开关连播 10 首的写入次数"，写进 CHANGELOG。
- 这条修的是"关掉进度记忆的人"。开关默认是开的，所以属于**少数人撞上、撞上就完全没法用**的那类；
  README 里「最近播放」那段要补一句"和「记住播放进度」无关"，免得下次又被当成同一个概念。

## 2. F11 音频 / 视频两种窗口（新能力）—— **已做（2026-11-03，见 CHANGELOG 的 `[1.9.0]`）**

### 2.1 目标（都能判真假）

1. 放音频文件 → 自动进**音频窗口**：420×650 的简化窗口（封面 + 曲名 + 艺术家·专辑 + 一行歌词 + 原传输条），
   **没有**工具栏、播放列表、侧栏。
2. 放视频文件 → 自动回**视频窗口**（1.8.0 的布局与大小，画面 / 侧栏 / 播放列表照旧）。
3. 手动可覆盖：`视图 → 窗口模式` 三项（自动 / 音频 / 视频），`Ctrl+Alt+M` 在当前形态上直接翻一下——
   **它和菜单等价，会把偏好定成翻到的那个形态**（状态栏说明"已固定为音频窗口；要按文件自动切回
   「视图 → 窗口模式 → 自动」"）。不做"临时切一下、下首歌又自动跳回去"的第三态，那种状态用户记不住。
4. 两种窗口**各记各的位置与大小**（`WindowX…` 与 `AudioWindowX…`），来回切不互相污染。
5. 音频窗口里 `F11` / 双击画面不进全屏（说一句原因）；全屏里不切进音频窗口。
6. 偏好是 `audio` 时**启动就是音频窗口**（没有媒体也一样，卡片显示空状态）；偏好 `auto` 且没有媒体 → 视频窗口
   （没东西可判，不猜）。

### 2.2 判定规则（纯函数，先能单测）

| 偏好（设置） | 路径 | 结果 |
| --- | --- | --- |
| `auto`（默认） | `MediaFormats.IsAudioFile` | 音频窗口 |
| `auto` | 视频扩展名 / 串流 / 空路径 | 视频窗口 |
| `audio` | 任意 | 音频窗口（放视频＝只听声音） |
| `video` | 任意 | 视频窗口 |

```csharp
// Core/WindowModes.cs（新，≈90 行）
public enum WindowShape { Video, Audio }

public static class WindowModes
{
    public const string Auto = "auto", Audio = "audio", Video = "video";

    // 自动（按文件）/ 总是音频 / 总是视频
    public static IReadOnlyList<(string Label, string Value)> All { get; }

    public static string Normalize(string? value);                       // 认不出来 → auto
    public static WindowShape Resolve(string? preference, string? path); // 纯函数，不碰引擎
    public static string Describe(string? value);
}
```

**为什么存字符串**：`JsonStringEnumConverter` 碰到不认得的值会让**那一项**读不出来，整份设置于是走
"抢救"流程（状态栏弹一句「设置文件有一处读不出来…」，那一项用默认值）；字符串 + `Normalize` 没有这个副作用，
跟 A3 的 `DeinterlaceModes` 是同一套做法：老设置、手改的 json、降级之后的新值，都安全落在 `auto` 上。

### 2.3 简化窗口长什么样

```
┌──────────────────────────────┐
│ 文件  播放  字幕  视图  帮助   │  ← 保留（否则切不回来）
├──────────────────────────────┤
│                              │
│        ┌────────────┐        │
│        │   封面      │        │  ← CoverView，按短边等比缩
│        └────────────┘        │
│         曲名（粗体一行）        │
│      艺术家 · 专辑（一行）      │
│       当前歌词行（一行）        │
│                              │
├──────────────────────────────┤
│ 00:00:30 ──────────── 03:45  │  ← pnlTransport 原样复用（Dock=Bottom）
│   🔊 ───────────────── 70%   │
├──────────────────────────────┤
│ 正在播放：xxx                 │  ← 状态栏保留（错误与提示都在这里）
└──────────────────────────────┘
            420 × 650（逻辑像素）
```

- **不复制传输条**：`pnlTransport` 原地不动（视频区底部 Dock=Bottom），音频窗口只是**在画面位置上
  盖一块** `NowPlayingView`（Dock=Fill，插在 `videoView` 之上、`lblPlaceholder` 之下）。
  这样进度条 / 音量 / 拖动 / 主题 / 冒烟的 `Find("trackSeek")` 全部不用改。
- 新控件 `Ui/NowPlayingView.cs`（≈260 行）：`ShowTrack(path, tags)`、`SetLyricLine(text)`、
  `ApplyPalette(palette)`，内部用 `CoverView`（已有 `ApplyPalette`，直接转发）。
- 歌词行由 `MainForm.Metadata.cs` 的 `UpdateLyricsPosition()` 顺手推（`LineIndexAt` / `CompanionOf`
  已有，桌面歌词走的就是这条链；没歌词就不占位）。
- 窗口：进入时 `MinimumSize` 换成 360×520（× DPI），**先改最小尺寸再赋 `Bounds`**（否则 420 宽会被 860 夹回去）；
  隐藏 `toolStripMain`；`splitMain.Panel2Collapsed = splitVideo.Panel2Collapsed = true`。

### 2.4 与既有功能的交界

| 既有 | 音频窗口里怎么办 |
| --- | --- |
| `F11` / 双击画面 | **不进全屏**，状态栏说一句「音频窗口没有全屏，先切回视频窗口」；`视图 → 全屏` 禁用 |
| 画面右键菜单（1.8.0 F10） | **不弹**：光标落在 `NowPlayingView` 上，`IsScreenPointOnVideo` 的窗口链本来就断在 `SplitContainer`，不用改代码——加一条断言钉住，防以后把命中判定改宽 |
| 字幕（`V` / 字幕菜单） | 照旧可点；音频文件没有字幕轨时引擎自己会说「没有字幕轨」，不额外禁用 |
| 播放列表 / 侧栏 | 进入时收起；这两个菜单项在音频窗口里**置灰**（要它们就切回视频窗口）；`F9` 在音频窗口里只给一句提示、不改布局 |

| 全屏 → 音频窗口 | 全屏里按 `Ctrl+Alt+M` 先说明「先退出全屏」，不改形态 |

### 2.6 断言（冒烟第 11 项，不新增检查编号）

1. **纯规则**：`Resolve` 四种组合全对；`Normalize` 把 `""` / `"weird"` / `null` 都归成 `auto`。
2. **布局**：`SetWindowMode("audio")` 之后——`IsAudioWindow` 为真、`NowPlayingView` 可见且完全盖住画面
   （`Bounds == splitVideo.Panel1.ClientRectangle`）、传输条仍可见、播放列表与侧栏收起、工具栏隐藏、
   窗口宽 < 700。
3. **几何来回**：记下进窗口前的 `Bounds` → 进音频窗口 → 断言尺寸等于 `AudioWindowWidth/Height`
   且 `Settings.AudioWindowWidth` 已落盘 → 退出 → 断言 `Bounds` 与进之前**逐像素相同**。
4. **自动判定**：`auto` + 音频夹具 → 自动进；`auto` + 视频夹具（第 13 项那套 ffmpeg 短片；没有 ffmpeg
   就跳过并打印原因）→ 自动出；`"video"` + 音频夹具 → **不**进。
5. **全屏被挡**：音频窗口里 `ProcessShortcut(F11)` → `IsFullscreen == false`，状态栏那句话在。
6. **右键菜单不弹**：音频窗口里 `ShowVideoMenu(...)` 弹不出来，`IsScreenPointOnVideo(画面中心)` 为假。
7. **偏好记忆**：把偏好设成 `audio` → 关窗 → 新开一个主窗体（不带媒体）→ 它是音频窗口，且几何用的是
   `AudioWindow*`（不是 `Window*`）。

**实现时踩到的两件事**（写下来免得下次重踩）：

1. **整套冒烟要钉在"总是视频窗口"**：其余 19 项都是按三栏布局写的，放音乐时自动切卡片会让
   侧栏 / 播放列表 / 全屏那些断言一起失准（第一次跑就是在第 7 项"分离检查"红的）。
   现在 `Program.Main` 里跟"默认关掉在线歌词"一样先写一次偏好，音频窗口那一段自己切过去再切回来。
2. **检查里别拿"还原快照"去改设置**：`defaults` 是"验完要还原"的那一份，`defaults.WindowMode = Auto`
   等于把还原值也改了——后面第 7 项就继承了 auto。改成另读一份 `setup` 去写。

### 2.8 风险与如实说明

- **按扩展名判，不看真实轨道**：`.mkv` 里只有音频也当视频；`.mp3` 里塞了封面也不会当视频。
  按真实轨道判要等 libvlc 解析（打开后 0.3～2 秒），窗口会先出来再"变形"，比按扩展名更糟。
  这条写进 README 的"已知限制"。
- **首次进音频窗口会从 1152×700 缩到 420×650**：这是这一版最抢眼的行为变化。菜单里有「视频」可一键关掉；
  默认值待你点头（见 §8）。
- **音频窗口里放视频＝只听声音**：画面不显示，但 libvlc 仍在解码（CPU 照花）。这一版**不关视频轨**——
  关了再切回视频窗口要重开媒体，代价大于收益；如实验证里写清楚。
- **DPI / 多显示器只能靠合成输入**：冒烟验的是"进 / 出 / 几何 / 菜单状态"，125% 缩放下的封面排版、
  拖到副屏再切形态，需要人手看一眼（清单见 §4.3）。
- 音频窗口里"封面大图每次绘制重排"可能是新的热点（和 D2 同类），先不优化，量到掉帧再进 D 表。

## 7. 明确不做（这次翻不了案）

- **按真实轨道判音频 / 视频**：要等 libvlc 解析，窗口会"先出来再变形"，比按扩展名更糟（见 2.8）。
- **音频窗口里关掉视频解码**：省 CPU，但切回视频窗口要重开媒体，代价大于收益。
- **音频窗口的可视化 / 频谱 / 全屏封面**：另一个产品，这一版只做"简化窗口"。
- **音频窗口里保留播放列表 / 侧栏**：会把它变成"小一号的视频窗口"，与"简化"背道而驰；
  要列表就切回视频窗口（或把列表分离成独立窗口）。
- **`F5`～`F9`**（筛选拖动 / 缩略图 / 字幕外观 / 串流最近地址 / 真正的自动去隔行）：仍然没点名，一行不动。
- **代码签名、D1～D3**：各自的触发条件没变。

## 8. 三个决策点（2026-11-03 已确认，三项都按推荐值）

**结论：计划不用改，照这份开工**——默认 `auto`（按扩展名自动切）、音频窗口里播放列表与侧栏都收起
（菜单置灰）、窗口 420×650（最小 360×520）。下面留着备选，以后想改知道改哪儿。

1. **音频窗口的默认判定**：按扩展名自动切（`auto` 默认），而不是默认永远是视频窗口？
   ——这是最省事的用法，但也是这一版最抢眼的变化。要更保守就默认 `video`，只在菜单里手动切。
2. **音频窗口里收起播放列表与侧栏**（菜单置灰），而不是缩成很窄的一栏？
   ——"简化"的代价是放着音乐时看不见列表；要保留就把它们做成独立悬浮窗。
3. **音频窗口尺寸 420×650、最小 360×520**（逻辑像素）——合适还是再窄/再宽一点？

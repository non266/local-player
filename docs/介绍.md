# 全能本地播放器 · 介绍

一个 Windows 上的本地音视频播放器，界面是经典的窗体布局，播放内核用 **VLC**。

它想做的事很具体：**把"每天都要用到的那些细节"做扎实**——歌词、歌单、桌面歌词、
窗口布局、按文件记住的调整。格式支持不用操心，那是 VLC 内核的事。

- 想快速了解它长什么样、能干什么 → 读这一篇就够
- 想查某个功能的完整说明、快捷键、踩过的坑 → [docs/参考手册.md](参考手册.md)
- 想知道内部怎么分层、怎么保证改动不破坏行为 → [docs/ARCHITECTURE.md](ARCHITECTURE.md)

## 一句话概括

| | |
| --- | --- |
| 平台 | Windows 10 / 11（x64） |
| 技术栈 | .NET 10 + Windows Forms + LibVLCSharp（libvlc 3.0.24） |
| 播放能力 | 与 VLC 基本一致：MP4 / MKV / AVI / MOV / FLV / WebM / TS / RMVB…，MP3 / FLAC / APE / WAV / AAC / M4A / OGG / Opus / WMA…，外挂字幕、多音轨、网络串流 |
| 要不要装 VLC | **不用**。播放内核以 NuGet 包形式带在输出目录里 |
| 程序体积 | 自包含发行包（1.33.0 实测）：装机 **245.5 MB / 649 个文件**（覆盖安装 245.8 MB），便携版解压 **241.1 MB / 647 个文件**。只构建（不发布）的输出小一些（1.6.2 实测 431 个文件 / 131.9 MB），其中 libvlc 原生库约占 106 MB |
| 数据放哪 | `%AppData%\播放器\`（设置、播放历史、歌单、设置方案、导入的字体、日志）。设环境变量 `播放器_DATA_DIR`、或在程序旁边放一个 `portable.ini`，都能把数据改到别处（绿色 / 便携版；后者落在 `<程序目录>\data`） |

## 它在意的几件事

这几条决定了它"手感"和你用过的播放器不太一样：

1. **不自动改你的文件。** 歌单和设置方案都是"点了保存才写"：改了列表只在标题上标
   `【歌单名·未保存】`，只有你点「覆盖保存」才落盘；替换当前列表之前一定会问一句。
   删歌单只删那个 m3u8，媒体文件一个都不动。
2. **出错要说出来。** 坏掉的设置文件会被备份成 `settings.json.corrupt` 并在状态栏说明；
   读不出来的歌单会**如实报数**（`另外 2 项文件已经不在了，已跳过`）而不是静默少几首；
   被忽略的异常也带着理由写进日志。乱码、找不到、解析失败，宁可说一句，不装作没事。
3. **记住你调过的东西。** 每个文件播到哪儿、音画 / 字幕延迟调过多少、歌词偏移调过多少、
   窗口摆在哪儿、侧栏多宽——都按文件或按程序记着，下次打开自己回来。
4. **不联网也要能用。** 在线歌词与封面（走 LrcAPI）是可选项，**服务地址默认留空**：
   程序不会自己挑一个第三方地址把请求发出去；不填就完全不联网。
5. **顺手比功能多重要。** 比如歌词字体只允许手动导入（系统里那几百个字体列出来又长又难找），
   桌面歌词的外观是一个"边拖边改真的歌词窗口"的对话框，而不是"点一下、看一眼、再点一下"。

## 五分钟上手

**1. 添加内容**：`文件 → 打开文件…`（`Ctrl+O`）、`打开文件夹…`（`Ctrl+Shift+O`，会递归扫子目录）、
`打开网络串流…`（`Ctrl+U`）。也可以直接把文件 / 文件夹**拖进窗口**（拖 m3u / m3u8 进来 =
把里面的条目追加进列表），或者用命令行参数传给 exe。

**2. 播放列表**：添加、移除、清空、上移下移、多选、拖动换位；搜索框支持
**空格分隔多个关键字**（与关系）；排序可按名称 / 路径 / 时长，**点表头也能排**
（一下升序、再点反向、第三下回原始顺序），随时恢复原始顺序。
**打开程序默认是一张空列表**——要接着上次的列表开，勾上 `播放 → 启动时恢复上次播放列表`
（默认不勾；不勾时连"上次在哪个歌单"也不挂，免得空列表挂着一个歌单名，加两首就把它覆盖掉）。

**3. 歌词与封面**：右侧侧栏分「歌词 / 封面 / 媒体信息 / 视频 / 文件」五页。歌词按优先级自动找——
同目录同名 `.lrc` → **文件内嵌歌词**（FLAC / MP3 / MP4 / Ogg / APE 都认）→ 同目录同名 `.txt`；
带时间轴的歌词会高亮当前行、**点任意一行跳到那一句**、鼠标停上去显示这句的时间点。
自动识别 UTF-8 / UTF-16 / **GBK**，`[offset:]` 按通行惯例生效。

**4. 桌面歌词**：`视图 → 桌面歌词` 或 `Ctrl+D`。无边框、置顶、**背景完全透明**（只有字本身有像素，
带一圈描边所以白底上也看得清），鼠标停上去才铺出一块可抓的半透明背景。
抓字就能拖，`Ctrl+Alt+D` 是**全局**解锁热键（锁定时鼠标穿透，点得到下面的程序）。

**5. 播放列表与歌单**（`文件 → 播放列表`，一个菜单管到底）：

- `Ctrl+S` **保存为歌单**——存进歌单库（`数据目录\播放列表\`，一个歌单一个标准 m3u8 文件，
  菜单里一行一个，点一下切过去，可覆盖 / 重命名 / 删除）；
- `Ctrl+L` **从 m3u 文件追加**、另有「从 m3u 文件替换当前列表…」——追加和替换是**两个菜单项**，
  语义写在名字里；
- `Ctrl+Shift+S` **另存为 m3u 文件**（任意位置，给别人、拷进别的播放器）；
- 歌单窗口里能一次看全（名字、曲目数、最后修改时间），外部的 m3u / m3u8 拖进去就收进库；
  **拖动一行或几行调整歌单顺序**（多选按块移动；顺序记在 `播放列表\歌单顺序.txt` 里，菜单也按它列），
  多选之后**批量重命名**成 `基名 1` / `基名 2` …（名字不合法或撞车就一个文件都不动）。

**6. 设置方案**（`文件 → 设置方案`）：把当前这一套设置命名存下来，随时切过去。
载入时可以**只挑几组**（播放 / 界面与主题 / 窗口与悬浮 / 歌词与桌面歌词 / 音视频输出 / 行为 /
会话），每行还写着这一组和当前有几项不一样——"把这套外观搬过来、音量别动"。
设定之后它就是**当前方案**，之后的改动会自动写回它；也可以导出成一个 json 文件带走。

**7. 文件浏览器**（1.24 ～ 1.28）：侧栏第 5 页「文件」，也可以单独弹出成独立窗口。地址栏 +
返回 / 前进 / 上级 / 刷新 + 磁盘列表；进入目录只读当前一层，默认只列能播的音视频、字幕与 m3u，
打开「显示所有文件」才连隐藏项一起看。搜索框按文件名筛选当前文件夹（空格分隔多关键字）；
勾选「含子文件夹」后按 `Enter` 递归搜索，结果里的「位置」列写明在哪一层找到；
「位置 → 只看类型」可以只看视频 / 音频 / 字幕 / 播放列表（文件夹始终留着）；
「位置 → 缩略图（平铺）」用封面（没有封面就截视频首帧）平铺显示音视频文件；
开关也在主菜单「视图」里，两处同一份状态。缩略图后台解码、每目录最多 300 个（可调 600 / 1000）、
落盘缓存 128 MB、网络位置不做；「位置 → 缩略图数量 / 清空缩略图缓存」都在那里。
左侧可以打开**文件夹树**（懒展开、跟列表同步、不跟目录联接），
「位置 → 自动刷新」默认开：盯着当前**本地**目录，文件增删改会静默跟上（不闪、选中项不丢）。
选中项可以直接拖到播放列表，文件夹递归仍有界（32 层 / 200,000 文件）。
双击播放，右键加入播放列表 / 下一首播放 / 把整个文件夹递归加进来；
收藏目录与最近浏览都记得住，也能从「位置」菜单定位当前正在播的文件。
关闭独立窗口就归位，侧栏里会留一块「已分离」提示。
它只管找和放：不删文件、不改名；递归搜索有界且不建索引。

**8. 快捷键**：`F1` 里有全部清单（播放控制、声音、文件与字幕、画面与同步、界面）；
`帮助 → 快捷键设置…` 可以改其中命令目录里的那 33 条（改完立刻生效，只存与默认不同的项），
包括逐帧、音画与字幕延迟、歌词偏移。

## 功能总览

**播放**
打开文件 / 文件夹（递归）/ 网络串流 · **最近地址**（`文件 → 最近地址`：最近 10 条串流，
最新在前；地址里常带账号口令，所以落盘 DPAPI 加密、菜单只显示脱敏短标签，清除当场写盘）·
**打开光盘**（DVD-Video 先出菜单、方向键选片 / 音频 CD / 数据盘；蓝光只识别）·
播放暂停停止 · 上一个下一个 · 快进快退 5 秒 · 拖动进度条 ·
音量与静音 · 倍速 0.5×~2.0× · 循环（不循环 / 单曲 / 列表）· **A-B 循环**（`播放 → A-B 循环`，
A ≥ B 会如实拒绝并说明原因）· **音量均衡 normalize**（`播放 → 音量均衡（normalize）`，
媒体级滤镜，切换会重载当前这一首并从头开始）· **睡眠定时器**（`播放 → 睡眠定时器`：
听完这一首就停 / 15·30·60 分钟后停 / 自定义分钟数，到点**暂停**而不是退出）·
**随机播放（一轮不重复：洗牌袋，每首播一次再重洗）** · 画面比例切换 · 全屏（双击或 F11）·
**全屏进度条**（鼠标一动底部浮出，2.5 秒收起，松手定位）·
截图保存 PNG · **任务栏缩略图四个按钮**（上一个 / 播放暂停 / 下一个 / 停止，按状态置灰）

**播放列表**
增删改与多选（`Ctrl` / `Shift` / `Ctrl+A`；批量移除 / 下一首 / 复制路径 / 整批上移下移与拖动，
`Ctrl+Z` 撤销最近一次移除或清空）·
拖动换位（多选按块移动，带插入位置提示）· **「下一首播放」队列**（右键或 `播放` 菜单入队，
排进队的行标 `▶`，最多 20 条；自然播完先播队首，列表的当前项不动）·
搜索过滤（空格分隔多关键字）· 排序与恢复原始顺序 ·
在资源管理器中定位 / 复制完整路径 · 汇总总时长（**只数真的能读到的条目**，坏的会说明）·
无法播放的条目标红并写明原因 · 保存 / 载入 / 追加 / 替换 m3u、m3u8 ·
**网络位置（SMB / NAS）的整个目录也能拖进来**（判目录 / 递归枚举 / 读网络 m3u 都在后台，离线不冻窗口） ·
**找出重复项**（右键菜单：保留第一次出现的那一项，其余选中；多选下按 Delete 一次删完）·
**默认空白启动**，可选"启动时恢复上次播放列表"（连当前歌单关联一起，默认关）

**文件浏览器**
侧栏第 5 页 / 可分离独立窗口 · 地址栏 + 返回 / 前进 / 上级 / 刷新 · 磁盘列表 · 只读当前层 ·
默认只看音视频 / 字幕 / m3u，可显示所有文件 · 名称 / 大小 / 修改时间 / 类型排序 ·
**搜索当前文件夹**（空格分隔多关键字，`Ctrl+F` / `Esc`）· **含子文件夹**（按 `Enter` 有界递归，
结果带「位置」列）· **只看类型**（视频 / 音频 / 字幕 / 播放列表）·
**缩略图（平铺）**（封面平铺显示，内嵌图 → 同目录外挂图；后台解码、每目录 300 个、
网络位置不做、落盘缓存 128 MB、只按可见范围排队）·
**拖到播放列表**（文件夹递归有界）· **定位当前播放文件** ·
收藏目录与最近浏览 · 双击播放 · 右键加入播放列表 / 下一首播放 / 整个文件夹递归加入 /
在资源管理器中显示 / 复制路径 · 独立窗口位置、大小、吸附都记住

**歌单库**
一个歌单一个 m3u8，放在 `数据目录\播放列表\` · 新建空歌单（同名不覆盖）· 名字规则严格
（非法字符指名道姓、Windows 保留名挡住）· 歌单窗口（列出全部、载入 / 追加 / 新建 / 重命名 / 删除）·
**拖动调整歌单顺序**（多选按块移动；记在 `歌单顺序.txt` 里，删掉就回到按名字排）· **多选批量重命名**（`基名 1` / `基名 2`…，
名字不合法或撞车时一个文件都不动）·
文件已经不在的条目如实计数 · 右键菜单与工具栏按钮上也能直接切

**歌词与封面**
侧栏五页（歌词 / 封面 / 媒体信息 / 视频 / 文件）· 歌词按优先级自动找（同目录 lrc → 内嵌 → txt，在线另算）·
媒体信息写明分辨率 / 显示比例 / 帧率 / 语言中文名 / 总码率（1.22.0；读不到的不编造）·
点行跳转 · 悬停看时间 · 时间轴偏移（`视图 → 歌词偏移`、`Ctrl+]` / `Ctrl+[`，一档 0.5 秒，
**按文件记住**）·
桌面歌词（透明、可锁、可调字号与浓度、自定义字体与颜色）· 字体导入与管理（每行用该字体画它的族名）·
在线歌词与封面（LrcAPI，可选、可填服务地址与鉴权密钥）

**声音**
均衡器（预置 + 自定义频段）· 音频输出设备切换（多声卡 / 耳机 / HDMI）·
音量均衡（normalize，把忽大忽小的音量拉平）

**视频**
音画同步（音频 ±50ms、字幕 ±250ms，**按文件记住**）· **画面旋转 / 翻转**
（六种，**按文件记住**，切换停在原来的位置）· 去隔行（混合 / Bob / 线性 / Yadif /
Yadif 2x / IVTC / 荧光）· 逐帧步进（`E` / `Shift+E`）·
按时间码精确定位 · 章节跳转 · 字幕加载与轨道切换（`V` 关 / 开字幕，
**画面右键**里也能换字幕 / 音轨，全屏时同样可用）·
**音轨 / 字幕轨按文件记住**（选过的自动选回，「关闭字幕」也记得住；网络流不记）·
**字幕外观**（`字幕 → 字幕外观…`：字号 / 颜色 / 描边 / 背景四组预设；
只管纯文本字幕，ASS / SSA 与 DVD 图形字幕由文件自己决定；参数是内核级的，**下次启动生效**）

**界面**
5 套主题（跟随系统 / 浅色 / 深色 / OLED 纯黑 / VLC 橙，含深色标题栏与菜单）·
三栏布局（视频 | 侧栏 | 播放列表），**侧栏与播放列表互不牵连**，都能**脱离主窗口**成悬浮窗 ·
**音频窗口里也能把侧栏分离成悬浮窗**（停靠的侧栏照旧收起，归位后仍收起；迷你模式只能归位、不能再新分离）·
侧栏第 5 页「文件」还能**单独弹出**成独立窗口（有自己的位置 / 大小 / 吸附）·
悬浮窗能**吸附在主窗口边上**跟着一起移动（像 Winamp 挂在旁边）

**系统集成**
系统托盘（关闭缩到托盘、托盘菜单）· 全局媒体键 · **系统媒体控件**（Win10/11 音量弹窗与锁屏上显示
曲名 / 歌手 / 封面 / 状态 / 进度，**带播放 / 暂停 / 停止 / 上一个 / 下一个按钮**；封面优先内嵌图、
其次同目录的 `cover.jpg` 这类外挂图，见参考手册）·
单实例（第二个实例把文件转给已开的窗口）·
窗口置顶 · 记住窗口位置与大小 · 快捷键可改（`帮助 → 快捷键设置…`，命令目录里那 33 条）·
便携模式（程序旁放 `portable.ini`，或设 `播放器_DATA_DIR`）

**诊断**
诊断日志（内存最近 500 条 + `数据目录\播放器.log`，1 MB 自动轮转，可关）·
`帮助 → 查看日志…` 直接看 / 复制 / 打开文件 · 未处理异常先写日志再提示 ·
**没有"空吞异常"**：每处"决定不管"都写了理由并记进日志 · 时长扫描逐条记录耗时

## 关于质量：它是被测试钉住的

这个项目有一件和多数小工具不一样的地方：**每一项行为都有一条测试钉着，改动不允许"看起来对"**。

- **35 个运行步骤 / 40 项检查的冒烟测试**（`tools/SmokeTest`）：编号到 40——有几项共用同一个编号
  （比如第 15 项里既有桌面歌词，也有歌词字体与几个对话框的排版）。检查项是：播放内核、
  主窗体与主题、时长扫描、设置持久化、标签与歌词、均衡器与引擎、侧栏与播放列表、单实例、
  视频功能与逐帧、回归点、桌面歌词、在线歌词与封面、歌单库、歌词偏移、日志与错误处理、设置方案、光盘、光盘菜单、
  命令层、迷你模式、播放业务与所有权、网络位置、网络目录、扫描上限与取消、网络等待与探测去重、
  大列表排序、切歌时的等待、在线歌词缓存、文件浏览器、文件页导航与自动刷新、
  关窗收尾、快捷键设置、数据目录与便携模式、文件页缩略图性能。
  它不需要任何外部媒体文件——样本（WAV、各种标签的音频、LRC、字体、假的 LRCAPI 服务器）
  都在测试里现场合成；真的需要真实视频或外网的那几步会**明说自己跳过了**，不伪装成通过。
- **每个新检查都要通过"变异验证"**：把被测行为临时改坏，确认测试以一句**具体**的话失败，再改回来。
  例如：
  - 去掉"新建歌单不覆盖同名" → `同名新建没有报错，把已有歌单覆盖了`
  - 让 `SetCurrent` 也发"内容变了" → `只切换了一下当前项，就被当成「歌单有改动」了`
  - 让设置合并忽略勾选 → `设置合并：只勾了「播放」，界面与视频输出却被一起改了`
- **两套配置零警告**：Debug 与 Release 都是 0 警告 0 错误。
- **规模**（量出来的，2026-11-28）：主程序 **55,057 行 / 215 个文件**（含约 1,200 行的设计器生成文件），
  测试 **35,250 行 / 100 个文件**。

内部结构上，这个项目做过一轮"架构收敛"（起因是一次外部评审给了 8/10，建议"别再无限加功能"）：
把主窗口这个 2,233 行的 god class 拆开（现在是 43 个按职责分的 partial）、
把测试从 9,000 行单文件拆成 23 份（1.6.2 的 R3 / R7 与 1.7.0 的 F3 / F4 之后是 58 份，1.8.0 拆出多轨样本那份是 59，
1.11.0 之后是 66 份、1.13.0 之后是 67 份、1.14.0 之后是 68 份、1.15.0 之后是 69 份、1.20.0 之后是 77 份、1.21.0 之后是 78 份、1.22.0 之后是 82 份、1.23.0 之后是 87 份、1.24.0 之后是 91 份、1.25.0 仍是 91 份、1.26.0 之后是 92 份、1.27.0 之后是 93 份、1.28.0 之后是 95 份、1.29.0 之后是 97 份、1.30.0 之后是 98 份、1.31.0 之后是 99 份、**1.32.0 之后是 100 份、1.33.0 仍是 100 份**）、把测试里 171 处反射访问降到 1 处（只剩框架必须反射的那一处）、
并给所有改动立了"全量回归 + 变异验证"的规矩。过程、债务清单和每一步的证据都在
[docs/ARCHITECTURE.md](ARCHITECTURE.md)。

## 已知限制（挑和日常使用最相关的）

- **只有 Windows**（x64）：界面用的 WinForms，另外还有几处 Windows 原生调用（深浅色标题栏、
  任务栏缩略图按钮、全局媒体键），没有跨平台计划。
- **没有画面调整**（亮度 / 对比度 / 饱和度 / 色相 / 伽马）：libvlc 3.0.23 时代五种办法在这台机器上
  逐一实试都不影响输出画面；**3.0.24 上复测过**（`--video-filter=adjust` 一开，整幅画面变纯绿
  `(0,135,0)`，硬解软解、`--vout=direct3d11` 都一样）——所以是"调了会把画面弄坏"，继续不做。
- **标签解析**覆盖 ID3v2 / FLAC / MP4 / ID3v1 / Ogg（Vorbis / Opus / Speex / FLAC / Theora）/
  APEv1 / APEv2 / ASF（WMA / ASF / WMV）；ASF 的 DRM / WMA Pro 与 Ogg 里 ≳ 2 MB 的封面读不到，
  这些格式想显示歌词仍可以放同目录同名 `.lrc`。
- **字幕外观只影响纯文本字幕**：ASS / SSA 走 libass、按字幕文件自己的样式画，DVD 图形字幕是位图；
  参数只能在建内核时设置，所以保存后**下次启动程序生效**，桌面歌词另有自己的字号 / 浓度。
- **最近地址只记"打开过"**（死链也会在列表里）：落盘是 DPAPI 密文，换 Windows 用户 / 换机器后
  解不开的那条会被丢掉（设置方案与导出文件里也是密文，不往别的机器带）；菜单只显示脱敏短标签。
- **文件浏览器只做"找与放"**（1.24 ～ 1.28）：不删 / 不改名 / 不移动文件；搜索默认只筛
  **当前文件夹**，勾选「含子文件夹」后按 `Enter` 才有界递归（本地 32 层 / 20,000 条结果 /
  200,000 个已看条目；网络 16 层 / 10,000 条 / 100,000 条），不建索引；
  **文件夹树默认关**（视图宽 ≥ 360 逻辑像素才可用，每层最多 2,000 个，不展开目录联接）；
  **自动刷新默认开**，但只盯当前**本地**一层（网络位置与"此电脑"不盯，搜索结果页不刷新）；
  单目录超过 20,000 项只列前 20,000；隐藏 / 系统项默认不显示；
  网络共享只能从地址栏进，不自动发现；从它发起的「整个文件夹」与拖放文件夹递归有界
  （32 层 / 200,000 文件，不跟目录联接），触到上限会说明「只扫了一部分」。
  **「缩略图（平铺）」默认关**：封面优先，没有封面才截**视频首帧**（片头全黑 / 解不开就退回类型图标）、
  **网络路径不做**（离线共享上的读盘不可取消）、**落盘缓存**在 `%AppData%\播放器\thumbnails`（上限 128 MB）；
  只按当前**可见范围**排队（前后各一屏，滚动时补），内存缓存 512 条、满了只重建可见范围；
  每目录最多 300 个文件（可调 600 / 1000），其中最多 60 个视频截帧；
  平铺里没有大小 / 位置两列（递归搜索结果会自动回详情视图）。
- **快捷键可以改**（1.29.0 起，`帮助 → 快捷键设置…`；1.30.0 把逐帧 / 延迟 / 歌词偏移也收进来，
  共 33 条）：每条命令最多主 / 次两个键、改完立刻生效；只把与默认不同的项写进设置。
  `F1` / `Delete` / `Esc` / `Enter` / `Tab` / `Backspace` / `F5` / `Ctrl+F` / `Ctrl+Z` /
  `Alt+←→`、文件页与 DVD 菜单那些键是固定的——绑上去会被那一处先吃掉，所以对话框直接挡住；
  全局热键（`Ctrl+Alt+D`）与多媒体键不参与。
- **播放列表多选（1.31.0 / 1.32.0 / 1.33.0）** 用于批量移除 / 下一首 / 复制路径 / 整批移动；
  多选按一个块移动，块内相对顺序不变；筛选状态下不能整批移动 / 拖动（单选移动仍可用）。
  `Ctrl+Z` 撤销最近一次移除或清空；清空仍先确认，确认后也能撤销；
  不恢复播放、不恢复选中、不跨重启；列表内容再变一次就失效。
  `Ctrl+A` 只选当前可见行（筛选状态下不会带上被筛掉的条目），5 万行全选的耗时没有量过。
- **歌单窗口多选整批拖动（1.33.0）**：选中几份歌单后按一个块拖动排序，块内相对顺序不变；
  只改 `歌单顺序.txt`，不碰歌单内容；拖错了只能再拖回去，或删掉那个文件回到按名字排。
- **关窗最多等 2 秒**（1.29.0）：音频窗口关闭那一处从 1.18.0 起偶发 Application Hang
  （`0xCFFFFFFF`）；现在引擎释放挪到后台、界面最多等 2 秒，超时就记一行并继续关
  （后台线程随进程退出回收）。**根因未定**——修的是"不让它把界面挂住"，不是"libvlc 不再卡"。
- **便携模式**（1.29.0）：程序旁边放一个 `portable.ini`（内容随意）→ 数据放 `<程序目录>\data`
  （设置 / 历史 / 歌单 / 字体 / 缩略图缓存 / 在线缓存都跟着走）。便携 zip **不预置**这个文件
  （老用户解压覆盖时数据不会凭空搬家）；程序目录写不进去会退回 `%AppData%\播放器` 并说明。
- **媒体信息的轨道码率 / Profile / Level 多半读不到**：libvlc 3 实测对 mp4 报 -1 / 0，
  界面就不写这几项（不编造）；文件级「总码率」是文件大小 ÷ 时长算出的容器平均。
- **歌词只做显示与跳转**，没有编辑、没有内建的歌词搜索（在线获取走 LrcAPI，可选）。
- **DLNA / NAS 媒体库、皮肤、跨平台都没有**：属于"复杂度超过收益"，明确不做。
  **系统媒体控件（SMTC）有**——Win10/11 音量弹窗与锁屏上能显示曲名 / 歌手 / 封面 / 状态 / 进度，
  还带播放 / 暂停 / 停止 / 上一个 / 下一个按钮（1.3.0 做显示、1.4.0 补齐按钮与封面，
  需要 Win10 2004 以上）；更老的系统安静降级，媒体键与任务栏缩略图按钮不受影响。
- **大列表（1.15.0 实测）**：切歌只挪加粗那一行、末尾追加只补新行
  （50,000 条切歌 1.8 秒 → 1 毫秒、追加 1.9 秒 → 5 毫秒）；整建 / 筛选 / 排序仍是 O(n)
  （50,000 条整建约 1.4 秒、筛选约 0.5 秒、按名称排序约 1.6 秒），没上虚拟模式——
  整建低于维护手册 D1 的 2 秒阈值。
- **去隔行**接进了 libvlc 的去隔行接口（8 个模式）。2026-10-20 用 ffmpeg 自造的隔行素材实测过：
  混合 / 线性 / Yadif / IVTC / 荧光 / Bob / Yadif 2x 都把"梳状"压低约 76%～79%
  （数字与量法见参考手册）。**1.7.0 删掉了「自动」**：它实测和关闭一模一样，
  libvlc 3 的播放器级接口根本不认 `auto` 这个名字——留个按了没反应的选项比没有更糟。
  边界：合成素材，真实片源（编码 / 位深 / 硬解）没有逐种验，也量不出"哪个模式最好"。
- **逐帧**是按帧长精确定位实现的（libvlc 的 `NextFrame()` 实试无效），可变帧率片源偶尔可能差一帧。
- 播放记忆（进度、歌词偏移、音画 / 字幕延迟）**按文件路径记录**，文件改名或移动后会重新开始记。
- 其余限制与"知道但暂时没动"的几条，参考手册的「已知限制与可继续做的方向」里都列着。

## 环境要求与构建运行

| | |
| --- | --- |
| 操作系统 | Windows 10 / 11（x64） |
| SDK | .NET 10 SDK（仓库根目录的 `global.json` 钉在 10.0.402；装了更高版本也能构建） |
| 运行时 | .NET 10 Desktop Runtime——只有"自己构建后直接运行"才需要；发行包是自包含的 |

```powershell
# 还原依赖（首次需要联网）
dotnet restore 播放器.csproj

# 生成
dotnet build 播放器.csproj -c Release

# 运行
.\bin\Release\net10.0-windows10.0.19041.0\播放器.exe
```

也可以直接用 Visual Studio 打开 `播放器.csproj` 按 F5。

> **输出 431 个文件 / 131.9 MB**（1.6.2 / libvlc 3.0.24 实测），其中绝大部分是 libvlc 的原生库。
> `VideoLAN.LibVLC.Windows` 默认会把 win-x64 / win-x86 / win-arm64 三套全复制过来（合计约 302 MB），
> 而本项目固定 x64、另两套永远用不上，工程文件里已经把另外两套关掉了，不用手动删任何东西。

> **离线构建**：如果这台机器上不了网而包已经还原过一次，`dotnet build` 可以离线跑；
> 在完全干净的机器上要离线还原，可以从 NuGet 的 HTTP 缓存
> （`%LocalAppData%\NuGet\v3-cache`）里捞出 nupkg 当本地源。具体命令与这次踩到的
> SDK / 目标包问题记在 [docs/ARCHITECTURE.md](ARCHITECTURE.md) 的「环境记录」一节。

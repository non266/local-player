# 全能本地播放器 · 介绍

一个 Windows 上的本地音视频播放器，界面是经典的窗体布局，播放内核用 **VLC**。

它想做的事很具体：**把"每天都要用到的那些细节"做扎实**——歌词、歌单、桌面歌词、
窗口布局、按文件记住的调整。格式支持不用操心，那是 VLC 内核的事。

- 想快速了解它长什么样、能干什么 → 读这一篇就够
- 想查某个功能的完整说明、快捷键、踩过的坑 → [README.md](../README.md)
- 想知道内部怎么分层、怎么保证改动不破坏行为 → [docs/ARCHITECTURE.md](ARCHITECTURE.md)

## 一句话概括

| | |
| --- | --- |
| 平台 | Windows 10 / 11（x64） |
| 技术栈 | .NET 8 + Windows Forms + LibVLCSharp（libvlc 3.0.23） |
| 播放能力 | 与 VLC 基本一致：MP4 / MKV / AVI / MOV / FLV / WebM / TS / RMVB…，MP3 / FLAC / APE / WAV / AAC / M4A / OGG / Opus / WMA…，外挂字幕、多音轨、网络串流 |
| 要不要装 VLC | **不用**。播放内核以 NuGet 包形式带在输出目录里 |
| 程序体积 | 约 100 MB（其中绝大部分是 libvlc 的原生库） |
| 数据放哪 | `%AppData%\播放器\`（设置、播放历史、歌单、设置方案、导入的字体、日志）。设环境变量 `播放器_DATA_DIR` 可以改到别处，做绿色版 |

## 它在意的几件事

这几条决定了它"手感"和你用过的播放器不太一样：

1. **不自动改你的文件。** 歌单和设置方案都是"点了保存才写"：改了列表只在标题上标
   `【歌单名·未保存】`，只有你点「覆盖保存」才落盘；替换当前列表之前一定会问一句。
   删歌单只删那个 m3u8，媒体文件一个都不动。
2. **出错要说出来。** 坏掉的设置文件会被备份成 `settings.json.corrupt` 并在状态栏说明；
   读不出来的歌单会**如实报数**（`另外 2 项文件已经不在了，已跳过`）而不是静默少几首；
   被忽略的异常也带着理由写进日志。乱码、找不到、解析失败，宁可说一句，不装作没事。
3. **记住你调过的东西。** 每个文件播到哪儿、音画 / 字幕延迟调过多少、歌词偏移调过多少、
   窗口摆在哪儿、侧栏多宽——都按文件或按程序记着，下次打开自己回来。
4. **不联网也要能用。** 在线歌词与封面（走 LrcAPI）是可选项，**服务地址默认留空**：
   程序不会自己挑一个第三方地址把请求发出去；不填就完全不联网。
5. **顺手比功能多重要。** 比如歌词字体只允许手动导入（系统里那几百个字体列出来又长又难找），
   桌面歌词的外观是一个"边拖边改真的歌词窗口"的对话框，而不是"点一下、看一眼、再点一下"。

## 五分钟上手

**1. 添加内容**：`文件 → 打开文件…`（`Ctrl+O`）、`打开文件夹…`（`Ctrl+Shift+O`，会递归扫子目录）、
`打开网络串流…`（`Ctrl+U`）。也可以直接把文件 / 文件夹**拖进窗口**（拖 m3u / m3u8 进来 =
把里面的条目追加进列表），或者用命令行参数传给 exe。

**2. 播放列表**：添加、移除、清空、上移下移、多选、拖动换位；搜索框支持
**空格分隔多个关键字**（与关系）；排序可按名称 / 路径 / 时长，**点表头也能排**
（一下升序、再点反向、第三下回原始顺序），随时恢复原始顺序。
**打开程序默认是一张空列表**——要接着上次的列表开，勾上 `播放 → 启动时恢复上次播放列表`
（默认不勾；不勾时连"上次在哪个歌单"也不挂，免得空列表挂着一个歌单名，加两首就把它覆盖掉）。

**3. 歌词与封面**：右侧侧栏分「歌词 / 封面 / 媒体信息」三页。歌词按优先级自动找——
同目录同名 `.lrc` → **文件内嵌歌词**（FLAC / MP3 / MP4 都认）→ 同目录同名 `.txt`；
带时间轴的歌词会高亮当前行、**点任意一行跳到那一句**、鼠标停上去显示这句的时间点。
自动识别 UTF-8 / UTF-16 / **GBK**，`[offset:]` 按通行惯例生效。

**4. 桌面歌词**：`视图 → 桌面歌词` 或 `Ctrl+D`。无边框、置顶、**背景完全透明**（只有字本身有像素，
带一圈描边所以白底上也看得清），鼠标停上去才铺出一块可抓的半透明背景。
抓字就能拖，`Ctrl+Alt+D` 是**全局**解锁热键（锁定时鼠标穿透，点得到下面的程序）。

**5. 播放列表与歌单**（`文件 → 播放列表`，一个菜单管到底）：

- `Ctrl+S` **保存为歌单**——存进歌单库（`数据目录\播放列表\`，一个歌单一个标准 m3u8 文件，
  菜单里一行一个，点一下切过去，可覆盖 / 重命名 / 删除）；
- `Ctrl+L` **从 m3u 文件追加**、另有「从 m3u 文件替换当前列表…」——追加和替换是**两个菜单项**，
  语义写在名字里；
- `Ctrl+Shift+S` **另存为 m3u 文件**（任意位置，给别人、拷进别的播放器）；
- 歌单窗口里能一次看全（名字、曲目数、最后修改时间），外部的 m3u / m3u8 拖进去就收进库；
  **拖动一行调整歌单顺序**（顺序记在 `播放列表\歌单顺序.txt` 里，菜单也按它列），
  多选之后**批量重命名**成 `基名 1` / `基名 2` …（名字不合法或撞车就一个文件都不动）。

**6. 设置方案**（`文件 → 设置方案`）：把当前这一套设置命名存下来，随时切过去。
载入时可以**只挑几组**（播放 / 界面与主题 / 窗口与悬浮 / 歌词与桌面歌词 / 音视频输出 / 行为 /
会话），每行还写着这一组和当前有几项不一样——"把这套外观搬过来、音量别动"。
设定之后它就是**当前方案**，之后的改动会自动写回它；也可以导出成一个 json 文件带走。

**7. 快捷键**：`F1` 里有全部清单（播放控制、文件与字幕、界面、歌词偏移、视频逐帧等）。

## 功能总览

**播放**
打开文件 / 文件夹（递归）/ 网络串流 · 播放暂停停止 · 上一个下一个 · 快进快退 5 秒 · 拖动进度条 ·
音量与静音 · 倍速 0.5×~2.0× · 循环（不循环 / 单曲 / 列表）· **A-B 循环**（`播放 → A-B 循环`，
A ≥ B 会如实拒绝并说明原因）· **音量均衡 normalize**（`播放 → 音量均衡（normalize）`，
媒体级滤镜，切换会重载当前这一首并从头开始）· 随机 · 画面比例切换 · 全屏（双击或 F11）·
截图保存 PNG · 任务栏缩略图控制按钮

**播放列表**
增删改与多选 · 拖动换位（带插入位置提示）· **「下一首播放」队列**（右键或 `播放` 菜单入队，
排进队的行标 `▶`，最多 20 条；自然播完先播队首，列表的当前项不动）·
搜索过滤（空格分隔多关键字）· 排序与恢复原始顺序 ·
在资源管理器中定位 / 复制完整路径 · 汇总总时长（**只数真的能读到的条目**，坏的会说明）·
无法播放的条目标红并写明原因 · 保存 / 载入 / 追加 / 替换 m3u、m3u8 ·
**默认空白启动**，可选"启动时恢复上次播放列表"（连当前歌单关联一起，默认关）

**歌单库**
一个歌单一个 m3u8，放在 `数据目录\播放列表\` · 新建空歌单（同名不覆盖）· 名字规则严格
（非法字符指名道姓、Windows 保留名挡住）· 歌单窗口（列出全部、载入 / 追加 / 新建 / 重命名 / 删除）·
**拖动调整歌单顺序**（记在 `歌单顺序.txt` 里，删掉就回到按名字排）· **多选批量重命名**（`基名 1` / `基名 2`…，
名字不合法或撞车时一个文件都不动）·
文件已经不在的条目如实计数 · 右键菜单与工具栏按钮上也能直接切

**歌词与封面**
侧栏三页（歌词 / 封面 / 媒体信息）· 歌词按优先级自动找（同目录 lrc → 内嵌 → txt，在线另算）·
点行跳转 · 悬停看时间 · 时间轴偏移（`视图 → 歌词偏移`、`Ctrl+]` / `Ctrl+[`，一档 0.5 秒，
**按文件记住**）·
桌面歌词（透明、可锁、可调字号与浓度、自定义字体与颜色）· 字体导入与管理（每行用该字体画它的族名）·
在线歌词与封面（LrcAPI，可选、可填服务地址与鉴权密钥）

**声音**
均衡器（预置 + 自定义频段）· 音频输出设备切换（多声卡 / 耳机 / HDMI）·
音量均衡（normalize，把忽大忽小的音量拉平）

**视频**
音画同步（音频 ±50ms、字幕 ±250ms，**按文件记住**）· **画面旋转 / 翻转**
（六种，**按文件记住**，切换停在原来的位置）· 去隔行（自动 / 混合 / Bob / 线性 / Yadif /
Yadif 2x / IVTC / 荧光）· 逐帧步进（`E` / `Shift+E`）·
按时间码精确定位 · 章节跳转 · 字幕加载与轨道切换

**界面**
5 套主题（跟随系统 / 浅色 / 深色 / OLED 纯黑 / VLC 橙，含深色标题栏与菜单）·
三栏布局（视频 | 侧栏 | 播放列表），**侧栏与播放列表互不牵连**，都能**脱离主窗口**成悬浮窗 ·
悬浮窗能**吸附在主窗口边上**跟着一起移动（像 Winamp 挂在旁边）

**系统集成**
系统托盘（关闭缩到托盘、托盘菜单）· 全局媒体键 · **系统媒体控件**（Win10/11 音量弹窗与锁屏上显示
曲名 / 歌手 / 状态 / 进度；那几个按钮与封面这一版没做，原因见 README）·
单实例（第二个实例把文件转给已开的窗口）·
窗口置顶 · 记住窗口位置与大小 · 便携模式（`播放器_DATA_DIR`）

**诊断**
诊断日志（内存最近 500 条 + `数据目录\播放器.log`，1 MB 自动轮转，可关）·
`帮助 → 查看日志…` 直接看 / 复制 / 打开文件 · 未处理异常先写日志再提示 ·
**没有"空吞异常"**：每处"决定不管"都写了理由并记进日志 · 时长扫描逐条记录耗时

## 关于质量：它是被测试钉住的

这个项目有一件和多数小工具不一样的地方：**每一项行为都有一条测试钉着，改动不允许"看起来对"**。

- **20 步冒烟测试**（`tools/SmokeTest`）：一共 16 项检查，编号到 20——有几项共用同一个编号
  （比如第 15 步里既有桌面歌词，也有歌词字体与几个对话框的排版）。检查项是：播放内核、
  主窗体与主题、时长扫描、设置持久化、标签与歌词、均衡器与引擎、侧栏与播放列表、单实例、
  视频功能与逐帧、回归点、桌面歌词、在线歌词与封面、歌单库、歌词偏移、日志与错误处理、设置方案。
  它不需要任何外部媒体文件——样本（WAV、各种标签的音频、LRC、字体、假的 LRCAPI 服务器）
  都在测试里现场合成；真的需要真实视频或外网的那几步会**明说自己跳过了**，不伪装成通过。
- **每个新检查都要通过"变异验证"**：把被测行为临时改坏，确认测试以一句**具体**的话失败，再改回来。
  例如：
  - 去掉"新建歌单不覆盖同名" → `同名新建没有报错，把已有歌单覆盖了`
  - 让 `SetCurrent` 也发"内容变了" → `只切换了一下当前项，就被当成「歌单有改动」了`
  - 让设置合并忽略勾选 → `设置合并：只勾了「播放」，界面与视频输出却被一起改了`
- **两套配置零警告**：Debug 与 Release 都是 0 警告 0 错误。
- **规模**（量出来的）：主程序约 **26,000 行 / 90 个文件**，测试约 **10,300 行 / 23 个文件**。

内部结构上，这个项目做过一轮"架构收敛"（起因是一次外部评审给了 8/10，建议"别再无限加功能"）：
把主窗口这个 2,233 行的 god class 拆开（现在是 29 个按职责分的 partial）、
把测试从 9,000 行单文件拆成 23 份、把测试里 171 处反射访问降到 1 处（只剩框架必须反射的那一处）、
并给所有改动立了"全量回归 + 变异验证"的规矩。过程、债务清单和每一步的证据都在
[docs/ARCHITECTURE.md](ARCHITECTURE.md)。

## 已知限制（挑和日常使用最相关的）

- **只有 Windows**（x64）：界面用的 WinForms，另外还有几处 Windows 原生调用（深浅色标题栏、
  任务栏缩略图按钮、全局媒体键），没有跨平台计划。
- **没有画面调整**（亮度 / 对比度 / 饱和度 / 色相 / 伽马）：libvlc 3.0.23 在这台机器上怎么调都不影响
  输出画面（五种办法逐一实试过），与其给几个不起作用的滑块，不如不做。
- **标签解析**覆盖 ID3v2 / FLAC / MP4 / ID3v1；**Ogg / Opus 的 Vorbis comment 与 WMA / APE 的标签没解析**，
  这些格式想显示歌词请放同目录同名 `.lrc`（外挂歌词对所有格式都有效）。
- **歌词只做显示与跳转**，没有编辑、没有内建的歌词搜索（在线获取走 LrcAPI，可选）。
- **没有 SMTC**（Win10/11 音量弹窗里的媒体控件）、**没有 DLNA / NAS 媒体库、没有皮肤**。
  这几样属于"复杂度超过收益"，明确不做；媒体键 + 任务栏缩略图按钮已能覆盖日常操作。
- **播放列表几万条会偏慢**（复用同一个 `ListView` 整体刷新，没上虚拟模式）。
- **去隔行**接进了 libvlc 的去隔行接口（各个模式都能设进去），但手上没有隔行素材，
  **实际画面效果没有验证过**。
- **逐帧**是按帧长精确定位实现的（libvlc 的 `NextFrame()` 实试无效），可变帧率片源偶尔可能差一帧。
- 播放记忆（进度、歌词偏移、音画 / 字幕延迟）**按文件路径记录**，文件改名或移动后会重新开始记。
- 其余限制与"知道但暂时没动"的几条，README 的「已知限制与可继续做的方向」里都列着。

## 环境要求与构建运行

| | |
| --- | --- |
| 操作系统 | Windows 10 / 11（x64） |
| SDK | .NET 8 SDK 或更高（更高版本 SDK 也能构建这个工程） |
| 运行时 | .NET 8 Desktop Runtime |

```powershell
# 还原依赖（首次需要联网）
dotnet restore 播放器.csproj

# 生成
dotnet build 播放器.csproj -c Release

# 运行
.\bin\Release\net8.0-windows\播放器.exe
```

也可以直接用 Visual Studio 打开 `播放器.csproj` 按 F5。

> **输出约 100 MB**：其中绝大部分是 libvlc 的原生库。`VideoLAN.LibVLC.Windows` 默认会把
> win-x64 / win-x86 / win-arm64 三套全复制过来（约 280 MB），而本项目固定 x64、另两套永远用不上，
> 工程文件里已经把另外两套关掉了，不用手动删任何东西。

> **离线构建**：如果这台机器上不了网而包已经还原过一次，`dotnet build` 可以离线跑；
> 在完全干净的机器上要离线还原，可以从 NuGet 的 HTTP 缓存
> （`%LocalAppData%\NuGet\v3-cache`）里捞出 nupkg 当本地源。具体命令与这次踩到的
> SDK / 目标包问题记在 [docs/ARCHITECTURE.md](ARCHITECTURE.md) 的「环境记录」一节。

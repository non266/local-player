# 维护手册（稳定维护期）

这份文档管**怎么维护**这件事：维护期的判据、每次改动的固定动作、已知问题的分诊、发布纪律。

- 怎么用、有哪些功能、快捷键 → [README.md](../README.md)
- 内部怎么分层、债务与收敛过程、验收方式的来龙去脉 → [docs/ARCHITECTURE.md](ARCHITECTURE.md)
- 给第一次接触这个程序的人看的入口 → [docs/介绍.md](介绍.md)

## 1. 什么叫"稳定维护期"

架构收敛那一轮（`docs/ARCHITECTURE.md` 第 2 节的 D1~D9）已经清完，
项目从这里开始进入维护期。三条判据**同时成立**才算：

1. **功能面冻结**：不再新增能力。想加的东西先写进本手册第 3 节或 CHANGELOG 的「计划」，
   不直接动代码。
2. **每次改动都有断言与变异验证**，全量 20 步冒烟必须绿，Debug / Release 零警告。
3. **已知问题有明确归属**：修 / 不修 / 等触发，每条都写清判据（第 3 节），不靠"以后再说"。

**明确不做**：重写、换 UI 框架、无红测试的重构、为"看起来更现代"改交互、
为了功能数量而加功能。

## 2. 每次改动的四件套

1. **先看现状**：读代码、量数据（"我记得是这样"不算），把现状写进注释或文档。
2. **改**：一次只做一件事；搬家就只搬家（行为零变化），修行为就顺手加断言。
3. **验证**：跑 [tools/release-check.ps1](../tools/release-check.ps1)（Debug + Release 构建 + 全量 20 步），
   **外加一个"改坏了就会红"的变异**——把被测行为临时改错，确认测试以一句具体的话失败，再改回来。
   （变异没红，先确认变异真的写进去了：曾经因为缩进猜错、`Replace` 没命中，导致"测试通过"。）
4. **同步文档**：README（功能面）/ 本手册（分诊表、纪律）/ [CHANGELOG.md](../CHANGELOG.md)（发版）。

```powershell
# 本机默认策略禁止直接跑 .ps1，所以走 -ExecutionPolicy Bypass
powershell -NoProfile -ExecutionPolicy Bypass -File tools\release-check.ps1

# 只看某一块（会把它依赖的前置检查一起带上）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\release-check.ps1 -Filter 歌单

# 只构建不跑测试（改文档时用）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\release-check.ps1 -SkipSmoke
```

## 3. 已知问题分诊表

分诊判据（自上而下先归入第一类）：

| 类别 | 判据 | 什么时候动 |
| --- | --- | --- |
| **A 必修** | 丢数据 / 崩溃 / **静默失败**（按了没反应、界面不说）/ 启动被卡住 | 优先级最高，随时可以插队修 |
| **B 可修** | 明确的长期操作别扭；**改完必须带断言 + 变异** | 有余力时做，一次一件 |
| **C 不改** | 设计取舍（附理由）；系统或内核限制 | 不改，只在文档里说清为什么 |
| **D 等触发** | 性能类：只有真的咬到你（几条、多大规模）才值得动 | 出现真实触发条件再排 |

> README 的「已知限制与可继续做的方向」是这些条目的**完整叙述**（含实测数据与来龙去脉）；
> 这里只做分诊，不重复细节。

### A 必修（2 条已修，0 条待修）

修完的条目**留在这里不删**——"为什么它算必修"这个判据比"修没修"更值得留下。
状态记的是当时那一版；发版后见 [CHANGELOG.md](../CHANGELOG.md)。

| # | 问题 | 为什么算必修（实测） | 修法 | 状态 |
| --- | --- | --- | --- | --- |
| A1 | 启动时逐个 `File.Exists` 上次的播放列表（`RestoreSession`，在窗体构造函数里） | **启动被卡住**：这台机器上实测，访问一个离线的网络路径一次查询 **>25 秒**（本地不存在的文件只有 4 ms）——上次从 NAS 播过的话，几十条就是"双击之后半天不出窗口"；而且那些条目还会被静默丢掉 | 启动恢复**一次磁盘都不查**（列表原样恢复、窗口立刻出来），打不开的交给后台线程核对：标记 + 状态栏说明，**不删条目**（网络盘暂时离线时下次挂上还能播）；`PlayIndex` 对已标记的条目直接跳过，不再等 SMB 超时 | **已修** |
| A2 | 全局媒体键只报告"注册上了几个"，不区分是哪几个 | **静默失败**：4 个里只成功 1 个时界面不提示，另外 3 个按了没反应（媒体键是抢占资源，别的播放器占了就注册不上） | `MediaKeys.Register` 返回**真正成功的那些 id**，`DescribeMissing` 把缺的名字写成一句话（"全局媒体键有 1 个没注册上：下一首…"），启动时并进 `ReportLoadWarnings` 一起显示 | **已修** |

> 两条的共同点值得记住：**改的是"把发生了什么说清楚"，不是加功能**——
> 维护期里最该优先做的往往就是这一类。
>
> 验证（四条变异都按预期变红）：恢复时同步查磁盘 → `构造函数返回时列表里有 2 项，期望 3`；
> 后台核对不标记 → `后台核对没有把打不开的那条标出来（HasError=False、原因「（空）」）`；
> 提示永远为空 → `缺了「下一首」但提示里没写出名字`；
> 把注册失败当成功 → `明明被测试占着，「下一首」却被算成注册成功了`。
> "媒体键被占"那条是<b>真抢占</b>验的：测试自己先用 `RegisterHotKey` 占住那个键再开主窗体。

### B 可修（4 条）

| # | 问题 | 现状与判据 | 修法 |
| --- | --- | --- | --- |
| B1 | 歌单窗口一次只能操作一个歌单（不支持多选批量删除），也没有拖拽排序 | 真别扭但可控：删十个要点十次 + 确认十次 | 列表改多选 + 批量删除（一次确认，说明删几个）；排序保持自然顺序即可 |
| B2 | 设置文件损坏时不尝试"丢弃坏字段、保留能读出来的部分" | 现在会备份成 `.corrupt` 并在状态栏说明，然后整份退回默认值——不丢数据，但**丢掉的是用户全部设置** | 坏 JSON 时逐字段容错解析（`JsonDocument` 逐属性试），失败的字段单独列出来告诉用户 |
| B3 | 双语歌词（同一时间戳的原文 + 翻译）只会显示其中一行，另一行永远轮不到"当前句" | 解析后按时间稳定排序、取最后一条命中的行，于是"后面那一行赢" | 把同一时间戳的多行合成一组，并给第二行一个"下一句 / 翻译"的选项（桌面歌词那一行现在只能显示下一句） |
| B4 | 列表筛选状态下不能拖动换位 | 有意禁用（界面行与模型索引不连续，拖动会有歧义），会提示先清空搜索框 | 要么允许"在筛选视图内移动"并定义清楚插到哪里，要么保持现状；**倾向保持**，除非真的有人被绊住 |

### C 不改（12 条，附理由）

| # | 问题 | 为什么不改 |
| --- | --- | --- |
| C1 | 没有画面调整（亮度 / 对比度 / 饱和度 / 色相 / 伽马） | libvlc 3.0.23 在本机怎么调都不影响输出画面（五种办法逐一实试）；给几个不起作用的滑块比不做更糟 |
| C2 | 没有 SMTC（Win10/11 音量弹窗里的媒体控件） | 要引 WinRT（目标框架得改成 `net8.0-windows10.0.19041.0`），改动面大于收益；媒体键 + 任务栏缩略图按钮已覆盖日常 |
| C3 | 没有 DLNA / NAS 媒体库、没有皮肤、没有跨平台 | 复杂度过收益；WinForms + 多处 Windows 原生调用，跨平台等于重写 |
| C4 | 歌词只做显示与跳转，没有编辑、没有内建歌词搜索 | 在线获取走 LrcAPI（可选）已够用；编辑是另一个产品 |
| C5 | Ogg / Opus 的 Vorbis comment 与 WMA / APE 的标签不解析 | 外挂 `.lrc` 对所有格式都有效，成本收益不划算 |
| C6 | 字体列表里只有自己导入的字体，看不到系统已安装字体 | 刻意如此：系统字体动辄几百个，列出来又长又难找 |
| C7 | 桌面歌词不给"只显示字、连描边都不要"的选项 | 白底程序上会完全看不见，宁可没这个开关 |
| C8 | 桌面歌词不逐字染色（卡拉OK 效果） | LRC / SYLT 里没有逐字时间轴，做不到就别假装能做到 |
| C9 | 置顶窗口盖不住"独占全屏"的程序 | 系统限制：独占全屏接管了显示模式，普通窗口置顶不生效 |
| C10 | 逐帧走"按帧长定位"而不是 libvlc 的 `NextFrame()`；可变帧率片源偶尔差一帧 | `NextFrame()` 实试无效；现在的落点是精确可复现的（同刻来回 seek 像素差 0.00），代价写清楚了 |
| C11 | 去隔行 9 个模式都能设进去，但**实际画面效果没有验证过** | 手上没有隔行素材；属于"未验证"而不是"已知坏"——拿到素材可以补验（补验后把这条挪走） |
| C12 | 暂停时画面上那一帧比 `MediaPlayer.Time` 滞后约 100~200ms | vout 与时钟的固有时差；用户按逐帧不受影响（按绝对时刻定位），只是"拿暂停那张图当基准"不成立 |

### D 等触发（3 条）

| # | 问题 | 触发条件 | 修法与代价 |
| --- | --- | --- | --- |
| D1 | 播放列表复用同一个 `ListView` 整体刷新，几万条时偏慢 | 真的往列表里塞几万条 | 改 `VirtualMode`：要动自绘渲染、选择、拖动换位与列宽自适应，代价大——所以等触发 |
| D2 | `CoverView` 每次绘制重排文字（同一帧还 `MeasureText` 两遍）；`LyricsView` 平滑滚动每 15ms 重建高亮路径与画刷 | 大窗口 + 高分屏下掉帧 | 照 `LyricsView` 已有的 `_boxes` / `_layoutDirty` 缓存思路推广；都不泄漏，只是热点 |
| D3 | `MediaFormats.IsOpenable` 是同步 `File.Exists` | 刚拖进来（还没核对过）的网络路径上出现可感知停顿 | **A1 已经把大头处理掉了**：启动恢复不再碰它，已被后台核对标成"打不开"的条目在 `PlayIndex` 里直接跳过。剩下的是"用户新加的网络路径"这一种，代价要多线程化 `PlayIndex` 的顺延逻辑——等真的被绊住再说 |

> **新增条目往这里记**：分诊的结论比"修没修"更重要——写清判据，下次就不用重新想一遍。

## 4. 发布纪律

- **版本号**只有一个地方：`播放器.csproj` 里的 `<Version>`（现在是 `1.0.0`，与 tag `v1.0.0` 对应）。
- **每次发版三步**：改版本号 → 在 [CHANGELOG.md](../CHANGELOG.md) 写一节 → 打标签（`v1.0.1` 这种格式）；
  发版前跑一次 `tools\release-check.ps1`，把结果记进 CHANGELOG 那一节。
- **数据兼容规矩**：`settings.json` / `history.json` / 歌单（m3u8）/ 设置方案（json）
  **只增字段、不改语义**；读到未知字段忽略、缺字段用默认值（现有实现已经是这样）。
  确实要改语义（比如单位从秒改成毫秒、目录布局变化）时，必须：
  单列一节「破坏性变更」+ 写清用户需要做什么 + 留一版过渡。
- **依赖不追新**：`libvlc` / `LibVLCSharp` 定版是稳定性的来源。
  联网时跑一次 `dotnet list package --vulnerable`，把结果贴进 CHANGELOG；
  只有出现真实漏洞或必须的修复才升，升级后照样跑全量 + 变异。
